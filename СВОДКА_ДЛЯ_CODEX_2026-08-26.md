Задача: адаптивность полевых PWA под разные размеры экранов (подготовка к полевому тесту на 50 водителей, 16 экскаваторщиков, 2 горных мастера).

### 1. Поддержка выреза экрана (вырез камеры / полоса жестов)

В `templates/base.html` строка viewport переведена на блок:

```
<meta name="viewport" content="width=device-width, initial-scale=1{% block viewport_extra %}{% endblock %}">
```

`viewport-fit=cover` включён **только** для трёх полевых приложений через переопределение блока:

- `templates/users/driver_shift.html` — безусловно;
- `templates/trips/excavator_work.html` — безусловно;
- `templates/trips/dispatcher_control.html` — **только** при `mining_master_mobile_enabled`.

Причина: в вёрстке водителя уже были прописаны `env(safe-area-inset-*)`, но без `viewport-fit=cover` браузер возвращал нули, и контент уходил под системные элементы.

**Важно:** экран диспетчера намеренно оставлен БЕЗ `viewport-fit=cover`. Проверено на боевом: у диспетчера viewport прежний. Не «чините» это.

### 2. Водитель — шапка больше не обрезается

- `templates/users/driver_shift.html`: добавлена функция `fitDriverHeaderId()`, вызывается внутри `fitDriverViewport()` (в существующем `requestAnimationFrame`). Подбирает размер шрифта `.driver-header-id` под ширину контейнера, нижний предел 11px.
- Там же `.driver-header-id`: `text-overflow: clip` → `ellipsis` (крайний случай для аномально длинных ФИО).

### 3. Экскаваторщик — картинка не вылезает из карточки

`static/css/app.css`, правило `.eo-dashboard-empty`:

- переведено с grid на flex (`overflow: hidden`), картинка получила `flex: 0 1 auto; min-height: 0`;
- добавлено `@media (max-height: 620px) { .eo-dashboard-empty img { display: none } }` — ниже этой высоты картинка сжималась в нечитаемую полоску и наезжала на ФИО.

Было воспроизводимо на 320×568.

## Проверка перед следующим деплоем

Правило после вчерашних потерь: **«коммит X — предок Y» не доказывает, что содержимое сохранится.** Сверять фактическое содержимое сервера пофайлово.

Ловушка: на сервере смешанные окончания строк (CRLF и LF в разных файлах). Прямое сравнение md5 даёт **ложные** расхождения. Нормализуйте:

```
tr -d '\r' < файл | md5sum
```

Именно так 4 «несовпадающих» файла оказались идентичными по содержимому, а полная сверка показала 0 расхождений на 593 файлах.
