# Автономная работа полевых приложений Экскаваторщика и Водителя

Дата начала: 13.09.2026.

## Цель

Подготовить проверенный пакет выпуска, в котором Экскаваторщик и Водитель могут
продолжать согласованные рабочие действия при временной недоступности сервера,
надёжно сохранять их на устройстве и автоматически синхронизировать после
восстановления связи без дублей и потери исходного времени.

Production, рабочая база, nginx, systemd и установленные приложения сотрудников
в рамках этой задачи не изменяются.

## Рабочий контракт реализации

Клиентское действие сначала проверяется по доступному локальному контексту, затем
записывается в durable-хранилище, после успешной записи применяется к UI и только
после этого отправляется. Общий batch endpoint возвращает отдельный результат для
каждого события: `accepted`, `deduplicated`, `conflict`, `retry`, `auth_required`
или `invalid`. Конфликтные и ошибочные события не удаляются до явного разрешения.

Окончательная матрица действий, правила конфликтов, результаты тестов, версии и
границы выпуска дополняются после интеграции и независимой приёмки.

## Зафиксированный контракт синхронизации

Пакет отправляется через `POST /offline-events/sync/`. Конверт содержит версию
формата, роль, устойчивый идентификатор устройства и массив событий. Каждое
событие содержит неизменяемый `event_id`, тип, время действия с часовым поясом,
порядковый номер устройства, зависимости, смену, технику, серверный либо
локальный идентификатор рейса/простоя, снимок контекста и параметры действия.

Поддерживаемые события первой версии:

- Экскаваторщик: погрузка, отмена погрузки, начало/окончание простоя, закрытие
  смены;
- Водитель: разгрузка, изменение фактической точки разгрузки,
  начало/окончание простоя, закрытие смены.

Открытие смены и принятие нового назначения без сервера намеренно не разрешены:
отсутствие связи не создаёт новых полномочий. Сервер возвращает отдельный
результат по каждому событию: `accepted`, `deduplicated`, `conflict`, `retry`,
`auth_required` или `invalid`, вместе с серверными идентификаторами и временем
получения. Повтор того же события с тем же содержимым безопасен; повтор ключа с
другим сотрудником, устройством или содержимым фиксируется как конфликт.

Два одновременно отключённых телефона не получают новые события друг друга.
Автоматическое связывание только по близости времени запрещено. Поэтому
разгрузка Водителя может быть связана с уже известным серверным рейсом, а новый
локальный рейс другого отключённого устройства до синхронизации считается
неизвестным и не открывает Водителю дополнительное действие.

## Реализовано

- добавлен серверный журнал автономных событий и `POST /offline-events/sync/`;
- каждое событие обрабатывается в отдельной транзакции, а точный повтор
  подтверждается без повторного доменного действия;
- несовпадение сотрудника, допуска, роли, устройства, контекста либо полезной
  нагрузки при том же идентификаторе фиксируется как конфликт;
- сохранены отдельно исходное время действия и время получения сервером;
- Экскаваторщик сохраняет в IndexedDB погрузку, отмену ещё не отправленной
  погрузки, начало/окончание простоя и закрытие смены;
- Водитель сохраняет в IndexedDB разгрузку, изменение фактической точки,
  начало/окончание простоя; закрытие смены продолжает использовать существующую
  web/native очередь, но теперь сохраняет исходное время, различает временные,
  авторизационные и терминальные ошибки и проверяет неизменяемую подпись запроса;
- очереди переживают замену HTML-фрагмента, перезапуск приложения и обновление
  service worker; старый авторизованный shell переносится только полным
  проверенным комплектом и не заменяется страницей входа;
- нативные WebView Водителя и Экскаваторщика регистрируют тот же проверенный
  ролевой service worker, но не включают браузерную блокировку интерфейса,
  баннер обновления или принудительную перезагрузку; неуспешная установка
  повторяется одним потоком с ограниченным числом попыток;
- подтверждённый выход удаляет из Cache Storage только авторизованный HTML-shell,
  сохраняя статические зависимости и IndexedDB-очередь для последующей сверки;
- временные ошибки `408`, `429` и `5xx` повторяются с ограниченной задержкой;
  `401`/`403` ждут новой авторизованной сессии; конфликт и ошибка данных остаются
  видимыми для сверки;
- применение к интерфейсу выполняется только после надёжной локальной записи;
  устаревшее серверное обновление не стирает неподтверждённую локальную проекцию.

## Матрица автономности

| Действие | Экскаваторщик | Водитель | Ограничение |
|---|---:|---:|---|
| Погрузка / отправка | да | не относится | только из последнего подтверждённого локального контекста |
| Разгрузка | не относится | да | только для уже известного рейса |
| Изменение фактической точки | не относится | да | с проверкой ожидаемого предыдущего значения |
| Начало/окончание простоя | да | да | окончание связано с точным локальным или серверным началом |
| Закрытие смены | да | да | исходное время сохраняется, повтор идемпотентен |
| Открытие смены | нет | нет | новые полномочия выдаёт только сервер |
| Принятие нового назначения | нет | нет | новые полномочия выдаёт только сервер |

Если оба телефона одновременно без связи, новый локальный рейс Экскаваторщика
не появляется у Водителя до первой синхронизации Экскаваторщика и последующего
обновления Водителя. Это намеренная защита от ошибочного связывания рейсов.
