## 1. Цель и ветки

S106-C1 принят и не переоткрывается. Рецензия координатора разобрана в [решении Астры](ПАСПОРТ_МЕХАНИК_РАЗБОР_S106_C1_РЕЦЕНЗИИ_2026_09_29.md). Теперь подготовь **работающий отдельный кандидат**, который сохраняет релизные исправления и устраняет ошибки допуска/выбора времени при повторе. Это не новый общий аудит и не разрешение на выпуск всей волны 2.

На постановке: PR №106 `17cbb3e913dfdc98aaa9585ba4090d0f4cf17ee0`; свежий release `35d11e1fe479ec80fddd3d8120e535cb0014e60e`, уже с №125/v367 и №133. Сначала fetch и зафиксируй реальные SHA. Не работай поверх старого 8c215ae2 как будто он текущий.

Отдельный worktree/ветка кандидата от проверенного head №106. Внутри **только кандидата** интегрируй свежий release, отдельно зафиксируй разрешение конфликтов и отдельно предметный патч C2. Перечень конфликтов пересчитай: старые три не считать гарантированным текущим числом. Сохрани весь свежий release; целиком старые файлы поверх него не переносить. Если №106 сменился — опиши дельту и не теряй чужие коммиты. Общие `fix/driver-truth-wave2` и release не двигать.

## 2. Сервер: один допуск, две независимые политики

1. Идентичность original event проверяется до допуска: event ID, actor/access/role/device, fingerprint и payload. Исходный конверт и первый приём не переписываются.
2. ACCEPTED, включая no_effect, возвращает сохранённый результат без handler-эффекта. RETRY остаётся отдельным рабочим путём. Только допустимые CONFLICT role/type/code идут на переобработку; плохие часы сами по себе не открывают произвольный код.
3. Объединить поддержанные случаи release/№106 в одном predicate/decision helper. Покрыть корень `driver.trip.loaded/free_bucket_not_available`, обе роли `device_clock_ahead`, зависимые события по согласованным собственным ссылкам, существующие восстанавливаемые предметные случаи №106. Не добавлять blanket allow для всех ошибок/ролей.
4. Для любого допущенного повтора time-policy определяется сохранёнными собственными доказательствами события, не последним error_code и не плохими часами предка. Доказанная собственная поправка сохраняется при смене кода; первое received_at стабильно. Исправный по действующему критерию timestamp ребёнка сохраняется. Не объявлять отсутствие известного сдвига доказательством абсолютной точности часов.
5. Dependency-policy выбирается независимо. Clock-ветка не должна досрочным return отменять допустимую самостоятельную обработку по own refs. `depends_on` не снабжает объектными ID/полномочиями. Отсутствующий нужный объект — сохранённый retry по своей ссылке, не выдуманный успех.
6. Восстановление допуска не отменяет предметные проверки handler. Например, устранение чередования часов/ошибки смены не даёт права завершить рейс чужой смены.

## 3. Сохранить релизные исправления целиком

- №126: после доказанной собственной ссылки и проверки truck/автора/смены завершать по `trip.excavator`; расхождение подписи payload — `manual_complete_excavator_mismatch`, не потеря события. Не выключать проверки владения и не выбирать чужой Trip.
- №128: перенести locked revive/self-accept отменённого TTL права при фактической погрузке, ограничение другого живого права, предметную идемпотентность и закрытие принятия своим завершением. Одного кода допуска недостаточно.
- №131: корневая ручная погрузка восстанавливается в клиенте, потом её зависимые действия. Принятый/удалённый родитель и самостоятельный ребёнок не должны навечно застревать из-за отсутствия записи родителя в outbox.
- №125: правило одного рейса, закрытие режима после своего завершения, подписи завершения/отмены экскаватором рейса и новые тесты сохраняются. Чужое завершение не должно гасить не связанный с ним ковш.

## 4. Клиент и сервер: исполняемый контракт

Одна проверяемая таблица role/event type/code и условий replay. Допустим общий fixture с тестами реальных predicates обеих сторон; одинаковые массивы строк сами по себе недостаточны. Если функции внутренние — исполнять фактический runtime через его входы, не копию helper в тест.

Докажи одновременно soundness и обязательное покрытие: клиент не поднимает неподдержанные случаи, но поднимает все нужные случаи восстановления; пустое подмножество не PASS. На повторе неизменны ID и полный payload/context/время/ссылки. Startup, потеря ответа, accepted/no_effect родителя без Trip, parent удалён из outbox, own-clock + dependency в одном событии проверяются явно. HTTP 2xx без валидного результата события не считать предметным успехом.

Версия v367 уже занята №125, v368 зарезервирована координатором для №106. В изолированном кандидате при изменении Driver runtime используй v368 с согласованными metadata/tests, если резерв ещё актуален; при параллельном занятии номера не перезаписывай чужой резерв. Версию Excavator определять по фактически изменяемому контуру и release-протоколу; новая версия не означает разрешение выкладки.

## 5. Адресная приёмка кандидата

| Группа | Обязательный исход |
|---|---|
| Status/identity | ACCEPTED с плохим raw-time и no_effect не применяются второй раз; неподходящий код с плохими часами не допускается; RETRY работает; несовместимые actor/device/fingerprint/payload не меняют оригинал |
| Собственные часы | Четыре повтора при смене domain-кода не чередуют старые/исправленные часы; raw и first_received неизменны. Ребёнок со своим исправным временем не получает +30 секунд из-за предка |
| Корень ковша | Два named Django-теста №128 и JS `restart resends a manual load refused as free_bucket_not_available and its chain` работают на интегрированном кандидате; не ImportError и не MOCK предметного handler |
| №126 | Свой рейс под ковшом + payload основного экскаватора → accepted, один Trip, фактический excavator сохранён; другой truck/автор/смена не получают обход |
| Ссылки | Корень с Trip / accepted без Trip / отсутствующий / чужой local actor/device; явный trip_id со штатными handler guards. Отдельно предок X и собственный ребёнок Y: X неизменён. Подмена object ID через dependency невозможна |
| Чужое живое право | Revive не присваивает чужое право, не создаёт второй рейс/эффект; исходный факт/receipt не теряется; сохранены код и технический лог действующего release. Это known boundary, не объявленная целевая блокировка работника |
| №125 | Полный цикл одного ковша; завершение собственного рейса гасит режим; другой рейс его не гасит; подписи берутся у рейса. Сохранены актуальные регрессии №125 |
| Конкуренция PostgreSQL | Два соединения одновременно повторяют один event; повтор корня рядом с ребёнком; competing live right. Не больше одного доменного эффекта/Trip, без обхода владения и потери receipt. Исключение при эффекте не оставляет частичную запись |

К известному сценарию чередования приложен [probe Астры](ДОКАЗАТЕЛЬСТВА_РЕЦЕНЗИИ_S106_C1_2026_09_29/README.md). Его ожидания намеренно описывают дефект текущего PR: использовать как before-доказательство, а новый regression должен требовать отсутствие чередования. Не называть старый PASS доказательством исправления.

Запусти затронутые существующие Django/Node группы и обязательные mobile gates из AGENTS для реально изменённого контура. PostgreSQL — изолированная test DB с проверкой vendor; при отсутствии локальной среды подготовить и выполнить disposable CI-проверку кандидата через подходящий тестовый workflow, без production/receiver/VERIFY. Для итогового PostgreSQL PASS нужны фактические raw и точный SHA; отсутствие среды обозначить NOT_RUN, не подменять SQLite. Полный nightly без конкретной причины не нужен.

## 6. Явно открытый остаток S106-T1 — не реализовывать в C2

Четыре terminal-handler при честном времени ребёнка раньше условной погрузки; source provenance; почасовой отчёт; driver timeline/credited_trips; закрытие простоев и ковша. Причины описаны в §5 разбора.

Не вводи общий max и не переставляй completed_at/cancelled_at/loaded_at для зелёного теста. Не меняй отчёты, нормы оплаты/отмены R-12, модели или новые миграции. Сохрани прежние предметные правила в этой части, их текущие отказы и clamp перечисли как KNOWN_GAP; при влиянии новой time-policy зафиксируй конкретный новый исход. Подготовь только короткую таблицу четырёх путей на кандидате, не ещё один общий аудит. Принятие C2 не означает, что этот остаток решён, и не разрешает выпуск №106.

Неоднозначные local-ссылки и расходящиеся trip_id/local_trip_id не объявлять защищёнными автоматически по `.first()`; replay не должен расширять их полномочия. Если адресный probe обнаружит действующий обход/новую неоднозначность, сохрани минимальную трассу и отдели блокер соответствующего случая. Не переделывай весь resolver молча.
