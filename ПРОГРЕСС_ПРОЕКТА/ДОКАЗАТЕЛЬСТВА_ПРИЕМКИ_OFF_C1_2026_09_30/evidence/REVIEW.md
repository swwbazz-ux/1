- `source-metadata.json → changed_file_sha256` считает локальные working-tree bytes: только **3/22** совпали с SHA-256 Git bytes. Для нескольких изменённых старых файлов несовпадение воспроизводится смесью прежних CRLF и новых LF; нельзя выдавать эту таблицу за проверку 22 Git-хешей. - Сравнения сохранены в `hash-verification.json` и `source-hash-verification.json`.

## Существенные границы воспроизведения

1. `fresh authenticated rendered shell precaches every exact dependency` требует `EXCAVATOR_RENDERED_SHELL_PATH`. Переданный HTML не опубликован, а воспроизводимого генератора синтетического авторизованного shell в пакете нет. Без этого внешнего файла тест пропускается. Сам тест проверяет список URL и модель CacheStorage, а содержимое JS/CSS подменяет `asset:<url>`; он не исполняет страницу целиком.
2. Runner проверяет HEAD и происхождение от base, но не проверяет чистоту tracked/untracked/staged дерева. Локальная модификация на правильном HEAD может пройти gates. Для приёмочного пакета нужен fail-closed cleanliness gate.
3. Runner наследует окружение БД. В режиме без `--postgres` не доказывает SQLite, хотя в JSON пишет `sqlite`; PostgreSQL vendor проверяется лишь после основного Django-набора. Настройки читают `POSTGRES_DB`, тогда как README предлагает `DJANGO_DB_NAME`, который ими не используется. Перед следующим прогоном нужны явные изолированные test DB и проверка фактического vendor до любых тестов. Это недостаток воспроизводимости, не доказательство обращения выполненного прогона к production: raw сообщает создание и уничтожение test DB.
4. 235 событий измерены в memory adapter. Это не реальная смена на IndexedDB/WebView и не проверка квоты или аварийной остановки процесса. Restart в unit-тесте — новый экземпляр ядра с тем же адаптером/снимком.
5. PostgreSQL, Gradle/установленный APK, настоящий DOM, Xiaomi/WebView, native audio и отключение радиосети остаются `NOT_RUN`. Добавленная PG concurrency проверка использует два потока, но не задаёт barrier, поэтому даже её будущий PASS не гарантирует столкновение в критической точке.

Рекомендация: учитывать эти границы в OFF-C1-R1 вместе с функциональными замечаниями других рецензентов; не организовывать отдельную бесконечную доработку только ради оформления логов.
