# Диспетчерская сверка рейсов с пробегом и выявление систематических расхождений

Статус: **требования согласованы, реализация не начата, production не изменён.**
Дата: 18.09.2026. Этот документ — постановка задачи и результат проверки текущей
модели данных. Перечень зависимостей для чата ручного режима Водителя вынесен в
`198_ЗАВИСИМОСТИ_СВЕРКИ_ПРОБЕГА_ДЛЯ_ЧАТА_РУЧНОГО_РЕЖИМА_ВОДИТЕЛЯ_2026_09_18.md`.

## 1. Зачем

Число отмеченных рейсов за смену и фактический пробег самосвала должны сходиться.
Если рейсов отмечено больше, чем позволяет пробег, — есть повод проверить лишние
отметки. Если пробег заметно больше расчётного — повод проверить пропущенные рейсы
или дополнительные переезды. Проверку выполняет диспетчер; водитель дополнительных
предупреждений и вводов не получает.

## 2. Принятые требования

1. **Адресат — диспетчер.** Результаты сверки показываются только в диспетчерском
   интерфейсе. Водителя не отвлекать предупреждениями и дополнительными полями.
2. **Плечо** — расстояние в километрах в одну сторону от экскаватора до точки
   разгрузки.
3. **Что сопоставляется.** Фактический пробег за смену (конечный одометр минус
   начальный) против расчётного пробега по маршрутам отмеченных рейсов.
4. **Базовая оценка** для одинаковых круговых маршрутов: `сумма плеч рейсов × 2`.
   Оценка приблизительная. Её ограничения обязательны к показу и учёту: выезд из
   гаража и возврат, заправка, перестановки между экскаваторами, свободный ковш,
   изменение маршрута внутри смены, незавершённый круг на конец смены. Оценку
   нельзя выдавать за точное измерение.
5. **Допуск настраиваемый:** фиксированный запас в километрах плюс процент от
   расчётного пробега. Численные пороги определяются по реальным сменам, а не
   назначаются заранее; до калибровки статус «подозрение» не выставляется
   автоматически.
6. **Диспетчерский интерфейс** показывает по каждой смене: водитель, самосвал,
   смена, число рейсов, фактический пробег, расчётный пробег, отклонение
   (км и %), полнота исходных данных, статус сверки. Предусмотрена расшифровка:
   по маршрутам (экскаватор → точка, число рейсов, плечо, вклад в расчёт) и по
   событиям смены (перестановки, свободный ковш, смена точки, конфликты).
7. **История повторяемости по водителю:** число проверенных смен, число
   отклонений, направление отклонения (недостаток / избыток пробега), результаты
   проверки диспетчером. Три различимых исхода: **подозрение** (автоматически),
   **объяснённое расхождение** и **подтверждённое нарушение** (оба — только
   решением диспетчера). Система никого не обвиняет автоматически и не удаляет
   рейсы.
8. **Направление отклонения — подсказка, что проверять.** Недостаток пробега →
   лишние отметки. Избыток → пропущенные рейсы или дополнительные переезды.
   Отдельно: если у нескольких водителей одного маршрута расхождение одного
   знака и близкой величины — проверять плечо маршрута, а не водителей.
9. **Неполные данные обозначаются явно:** нет одометра (начального или
   конечного), нет плеча хотя бы у одного рейса, есть неразобранные конфликты
   или неотправленные события. Неполная сверка не может стать подтверждённым
   нарушением. После поступления задержанных событий результат пересчитывается.

| --- | --- | --- |

| Подтверждённые водителем показания на закрытие | `shifts.DriverShiftReadingConfirmation` (`start_mileage`, `end_mileage`, `warnings`, `client_action_id`) | Один на смену; уже несёт подтверждённые предупреждения |
| Исправление переданных показаний между сменами | `shifts.ShiftReadingCorrection` (`metric = mileage`, `transferred_value`, `actual_value`) | Источник «сдвиг одометра между сменами» |
| Плечо рейса | `trips.Trip.transport_distance_km` | Заполняется при создании (формы, offline-синхронизация) и корректировкой диспетчера в отчётах |
| Точки рейса | `Trip.dump_point`, `assigned_dump_point`, `actual_dump_point`; `reports.dispatcher_shift_forms.effective_dump_point()` | Фактическая точка уже разрешается единым правилом |
| Экскаватор и смены рейса | `Trip.excavator`, `loading_shift`, `unloading_shift`, `driver_control_shift` | Привязка рейса к смене водителя уже есть |
| Действующее плечо экскаватора | `assignments.ExcavatorPlacement.transport_distance_km`, `assignments.ExcavatorDumpPointSetting.transport_distance_km` | **Только текущее значение, истории изменений нет** |
| Свободный ковш | `trips.FreeBucketAcceptance` (`used_trip`, `primary_assignment`, статусы) | Связь временного приёма с рейсом есть |
| Дубли и замены рейсов | `Trip.superseded_by`, статус `UNCONTROLLED`, `TripClientAction.client_action_id` | Идемпотентность клиентских действий уже ведётся |
| Неотправленные события и конфликты | `core.OfflineFieldEvent` (`status`, `retryable`, `error_code`), `core.OfflineFieldEventConflict` | Готовый источник признака «данные неполные» |
| Журнал действий диспетчера | `trips.DispatcherActionLog` (`action_type`, `reason`, `trip`, `shift`) | Расширять типы действий, а не заводить второй журнал |
| Снимки смены водителя | `reports.DriverShiftPassportSnapshot` (`payload`, `source_fingerprint`, ревизии) | Готовый механизм «пересчитать после задержанных событий» |

Чего нет и что потребуется (решение о форме — на этапе реализации):

- **история плеч**: запись «плечо экскаватор→точка, действовавшее с … по …» и
  плечо, зафиксированное в рейсе на момент отправки, — иначе изменение настроек
  меняет исторические расчёты;
- **результат сверки смены**: расчётный пробег, отклонение, полнота данных,
  статус, версия расчёта, отпечаток источников — по аналогии с
  `DriverShiftPassportSnapshot`, а не новая независимая таблица «с нуля»;
- **решение диспетчера по сверке**: исход (подозрение / объяснено /
  подтверждено), причина, кто и когда — как новый тип в `DispatcherActionLog`
  плюс ссылка на результат сверки;
- **настройки допуска**: запас в км и процент — единая настройка с историей
  изменения (кто, когда, прежнее значение).

## 4. Правила расчёта (согласованный минимум)

- Фактический пробег = `end_mileage − start_mileage` смены самосвала; если
  одометр отсутствует или конечный меньше начального — полнота «нет одометра».
- Расчётный пробег = Σ по рейсам смены `плечо_рейса × 2`, где плечо_рейса —
  значение, сохранённое в рейсе на момент отправки; при его отсутствии — плечо
  из истории настроек на момент рейса; если и его нет — рейс помечается «без
  плеча», полнота «нет плеч».
- В расчёт входят рейсы со статусами «на разгрузку», «выполнен» и «разгрузка
  непроконтролированная»; отменённые и заменённые (`superseded_by`) — нет.
- Отклонение = факт − расчёт; допуск = `запас_км + процент × расчёт`.
  Статус: «в допуске», «подозрение: недостаток пробега», «подозрение: избыток
  пробега», «неполные данные». До калибровки порогов — только «в допуске» /
  «неполные данные» / «нужна калибровка».
- Общая ошибка плеча: если по маршруту (экскаватор → точка) за период у ≥ N
  водителей отклонение одного знака и величина коррелирует с числом рейсов —
  выводить отдельно как «проверить плечо маршрута».
