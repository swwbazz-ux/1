## 4. Подробная карточка каждого исправления

### `QA-P1-001` Переходящий рейс

**Статус:** `ГОТОВО К ПЕРЕПРОВЕРКЕ`. Воспроизведение подтвердило, что оперативная выборка ошибочно ограничивалась временем открытия новой смены. В `trips/views.py` переходящий открытый рейс оставлен в оперативном состоянии, а сменный KPI ограничен новой сменой. Тесты `test_carryover_trip_is_visible_but_not_counted_in_new_shift_kpi` и `test_carryover_trip_created_before_master_shift_remains_visible` — `PASS`. Повторить: создать рейс до пересменки, открыть новую смену, сверить один ID и состояние у Диспетчера/Горного мастера/Машиниста; KPI новой смены не должен включить старый объем.

### `QA-P1-002` Удвоение транспортного отчета

**Статус:** `ГОТОВО К ПЕРЕПРОВЕРКЕ`. Причина — группировка по самосвалу без идентификатора смены и фильтрация по вычисляемому типу рейса. В `reports/views.py` строки сгруппированы по `unloading_shift_id`, фильтр смены использует `unloading_shift__shift_type`, для legacy-записей добавлена строка «Смена не определена». `test_dispatcher_transport_separates_same_truck_by_unloading_shift` проверяет экран и Excel: всего `4 / 198`, день `2 / 94`, ночь `2 / 104` — `PASS`. Исторические записи без смены не теряются.

### `QA-P1-003` Нулевая ширина полей Машиниста

**Статус:** `ГОТОВО К ПЕРЕПРОВЕРКЕ`. До исправления computed style обоих input был `0 px`: соседний `<small>` занимал `flex-basis:100%` в строке без переноса. В `excavator-work-v55-shift.css` включен перенос и заданы ненулевые flex/min-width; PWA поднята `v113 → v114`. Browser QA: `390 px` — `119,975/110,525 px`, `462 px` — `119,475/109,238 px`, `768 px` — `119,475/109,238 px`, горизонтальный overflow `0`. Через UI выполнены начало и закрытие локальной QA-смены. Старый кеш показал диалог `v113 → v114`, после явного обновления загрузилась v114.

### `QA-P1-004` Тупик смены Диспетчера

**Статус:** `ГОТОВО К ПЕРЕПРОВЕРКЕ`. Причина — служебное закрытие было доступно только при собственной активной смене, которую блокирующая чужая смена не позволяла открыть. Добавлен видимый блок владельца старой смены, обязательная причина и действие «Закрыть предыдущую смену служебно»; обработчик блокирует строку транзакционно и пишет аудит. Три теста положительного и негативного пути — `PASS`; свою смену этим путем закрыть нельзя.
