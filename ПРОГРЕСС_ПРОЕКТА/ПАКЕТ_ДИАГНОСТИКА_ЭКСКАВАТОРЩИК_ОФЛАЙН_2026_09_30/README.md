## Методика

- **Браузер**: отдельный headless Chrome на каждый стенд (кука `sessionid` для `localhost` общая для всех портов, поэтому один браузер на оба стенда нельзя):
  `chrome.exe --headless=new --remote-debugging-port=9241 --user-data-dir=<свой каталог> --window-size=392,732 --force-device-scale-factor=1 --no-first-run about:blank`
  (для :8042 — порт 9242 и другой каталог). Фактическая ширина окна в headless вышла 500 CSS px — на результат не влияет.
- **Вход без PIN**: серверная сессия (`scripts/offline_session.py` печатает ключ) → `node scripts/cdpx.js 9241 any cookie <ключ>` → `nav http://localhost:8041/excavator/work/`. PIN и пароли не вводились.
- **Касания**: `Input.dispatchTouchEvent` с `Emulation.setTouchEmulationEnabled` (команды `tap`, `hold`, `drag` в `cdpx.js`), координаты — в CSS px из `getBoundingClientRect()`.
- **«Без сети»** = сервер стенда остановлен (`preview_stop`) **и** проверено `netstat -ano | grep ":8041 "` пусто + `curl -m 3 http://localhost:8041/` → `000`. Внимание: после перезапуска сессии `preview_stop` оставил живые runserver — один прогон из-за этого выброшен (logs/stand_environment_notes.log).
- **«Слабый сигнал»** = на порту стенда `node scripts/blackhole.js 8041 8042` (принимает TCP и молчит) — так ведёт себя сеть в карьере; остановленный сервер отвечает отказом мгновенно и маскирует ожидание.
- **Время событий** — по базе (`scripts/offline_facts.py`, `scripts/offline_timeline.py`), не по экрану.

## Подготовка базы (одинаково на обоих стендах)

1. `cp <любая рабочая копия>/db.sqlite3 .` → `mkdir media` → `manage.py migrate`.
2. `manage.py shell < scripts/offline_reset.py` — закрыть открытые смены сотрудника 3 и экскаватора 54, закрыть старые рейсы, простои и приёмы ковша, дать самосвалу 1 назначение на экскаватор 54 (самосвал 10 остаётся назначен на ЭКС-2 → он «чужой» для проверки ковша).
3. `manage.py shell < scripts/offline_assign.py` — рабочее назначение сотрудника 3 на экскаватор 54 (иначе «Начать смену» заблокирована).
4. `manage.py shell < scripts/offline_backdate.py` — сдвинуть завершение старых рейсов на 3 ч назад, иначе самосвал в «возвращается к экскаватору» и карточка выключена.
5. `manage.py shell < scripts/offline_session.py` → ключ сессии → кука в свой headless Chrome.
6. С работающим сервером открыть `/excavator/work/`, дождаться `navigator.serviceWorker ... activated` и кэша с оболочкой (`caches.keys()`), затем остановить сервер.

## Как повторить каждый пункт

Везде: `node scripts/cdpx.js <9241|9242> excavator <команда>`; после каждого шага — `eval` состояния (примеры в CDP_ВЫДЕРЖКИ.md) и `shot`.

1. **Холодный старт.** Сервер выключен (проверить порт). Открыть новую вкладку `/json/new?http://localhost:804x/excavator/work/`, потом закрыть старую. `eval performance.getEntriesByType('navigation')[0]` (DCL, transferSize), `document.body.dataset.appContractLocked`, число `[data-eo-truck-card]` и `[data-eo-dump-target]`. Повторить с `blackhole.js` на порту вместо выключенного сервера и замерять, когда у вкладки появится заголовок.
2. **Начать смену.** Вкладка «Смена»: заполнить `[data-eo-shift-fuel]`=60 и `[data-eo-shift-engine-hours]`=12000 (через native setter + input/change), `hold <центр [data-eo-shift-button]> 1400`. Проверить `data-eo-shift-state`, `eoLocalShiftId`, `data-eo-work-available`, `await eoExcavatorFieldOutbox.pending()`.
   Для релиза, чтобы проверить п.3–4, смену открыть **онлайн**, затем остановить сервер.
3. **Работа.** Погрузка: `drag <центр карточки> <центр ККД> 14`. Ковш: `tap` по `[data-eo-free-bucket-open]`, клавиши `1`,`0`, выбрать строку, «Принять на погрузку», затем `drag` карточки tmp-10 на вторую точку. Простой: вкладка «Простой», `tap` «БВР», `tap` «Обед», `tap [data-eo-close-event]`. Отмена: вкладка «Работа», `drag 88 420 88 300 12` (свайп вверх по плитке ККД с чипом самосвала). Настройки: вкладка «Забой», горизонт 76, «Применить настройки».
4. **Закрыть смену.** Вкладка «Смена»: топливо 55, моточасы 12006, `hold` 1,4 с. Проверить надпись и `disabled` кнопки сразу, через 5 с и после перезапуска вкладки без сети.
5. **Вернуть сервер** (`preview_start`). Через 15 с — `pending()` (conflict?), затем `scripts/offline_facts.py` / `offline_timeline.py` по базе стенда.
6. **Перезапуск с сетью.** Открыть новую вкладку (не `Page.reload` — та же вкладка отдаёт статику из памяти и искажает замер) и смотреть **лог сервера** в эти секунды: запросы `/static/...` с 200 = статика пришла из сети. `transferSize` в Resource Timing не годится — через SW он всегда 0.

**event_id_reused.** Одна база, два кода:
1. Сервер релиза на :8041 (сессия есть в базе). `node scripts/replay_event.js 8041 <ключ сессии> scripts/replay_event.json` дважды → `accepted`, затем `deduplicated`.
2. Остановить :8041, скопировать `db.sqlite3` релиза в каталог c05a5925 (сохранив его базу в резерв), поднять :8042, отправить **тот же** `replay_event.json` → `conflict event_id_reused`. Сравнить `OfflineFieldEvent.fingerprint` и `OfflineFieldEventConflict.fingerprint` для этого event_id. Вернуть базу из резерва.
В `replay_event.js` CSRF-значение — выдуманная тестовая константа (кука и заголовок совпадают), не реальный токен.
