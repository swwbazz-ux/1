## Итог

**Главная цепочка простоя исправлена.** Досылка open→load→start→switch→stop→close сходится: интервалы и суммы — как нажато, авто-«Ожидание самосвалов» — временем события, три свои смены подряд созданы/закрыты временем нажатия. Под слабым сигналом — 14/14 событий `accepted` одной отправкой.

**Не принято (FAIL):**
1. **Обновление с release: номера порядка начинаются заново** — после v262→v263 то же устройство выдаёт `sequence` 1, 2… → сервер отвечает `sequence_reused`, **все новые действия работника отклоняются**. Причина: `excavator_work.html:1780–1785` берёт номер из нового ledger (`nextSequence`, старт с 1) и не учитывает счётчик прежнего клиента (`legacyExcavatorFieldSequence` / `__sequence__` outbox). Блокер выпуска.
2. **Отказы, уже записанные текущим release, не восстанавливаются**: повтор с тем же ID → `conflict` «Не удалось доказать границу производного автопростоя»; на сервере остаются БВР 0 с, «Обед» без конца (до служебного закрытия), смена не закрыта. Клиент R1 после обновления эти события переотправил — упирается в сервер.
3. **Предупреждение показаний при закрытии без сети (C6)**: после связи — окно «Проверьте показания», «ВСЁ ВЕРНО — ЗАКРЫТЬ СМЕНУ» принимает закрытие с тем же `event_id` ✅, но **следующая своя смена остаётся `dependency_rejected` и не переотправляется**, её простой — `retry` бесконечно.
4. **Погрузка под свободный ковш невозможна** ни без сети, ни с сетью: карточка принятого самосвала выключена (`excavator_work.html:1540` включает только при `data-eo-prepared-can-load="1"`, карточку ковша строит `excavator-free-bucket-v1.js` без атрибута). Приём/«Убрать»/повторный приём — работают.
5. **Настройки забоя в местной смене**: после первого изменения поля «Применить» выключается (`:1534–1537` не ставит `data-eo-settings-available`, а `:3069` его требует). В смене, уже известной серверу, без сети — работает.
