## Правило использования

Каждая реализационная задача Codex должна ссылаться на один или несколько ID этой матрицы. Задача считается принятой только после выполнения указанных проверок. Статус меняется по доказательствам нового HEAD, а не по отчёту «сделано».

## Критерий закрытия разрыва

Для смены статуса на READY обязательны одновременно:

1. реализация в утверждённом HEAD;
2. миграция или доказательство, что она не нужна;
3. позитивный, негативный и граничный тест;
4. для interval/concurrency — PostgreSQL-проверка;
5. обновление `07_ТЕКУЩЕЕ_СОСТОЯНИЕ_HEAD.md` и этой матрицы;
6. независимая проверка агентом, не реализовывавшим изменение.
