## 3. Реализованный контракт повтора

### 3.1. Сервер

В `core/offline_sync.py` введено одно решение `OfflineReplayDecision` с раздельными политиками допуска, времени и зависимостей.

- До допуска сравнивается неизменяемая идентичность события: event ID, actor/access/role/device, fingerprint и payload. Повтор не переписывает первый конверт, исходное `occurred_at` и первое `received_at`.
- Сохранённый `ACCEPTED`, включая `no_effect`, возвращает сохранённый результат без второго запуска handler. `RETRY` остаётся самостоятельным рабочим путём.
- Из `CONFLICT` повторно запускаются только перечисленные сочетания роль/event type/code. Неподходящий код не становится допустимым только из-за плохих часов.
- Собственная поправка часов хранится как внутреннее доказательство события и переживает смену последующего domain-кода. Dependency-policy выбирается независимо; собственная clock-ветка не отменяет проверку собственных ссылок события.
- `depends_on` не предоставляет ребёнку объектные ID или полномочия. Если собственный обязательный объект отсутствует, handler сохраняет свой `retry`, а не выдуманный успех.
- Внутреннее доказательство повтора сохраняется в result payload receipt; при выдаче полевому клиенту оно удаляется.

Исполняемая таблица `core/fixtures/offline_replay_contract.json` содержит 11 положительных и отрицательных сценариев. Её проверяют реальные server/Driver/Excavator predicates, а не копии тестового helper.

### 3.2. Клиенты

`driver-offline-outbox-v2.js` и `excavator-field-outbox-v1.js` используют явные predicates с теми же границами: dependency-коды, доказанная собственная clock-поправка и разрешённые предметные коды. Regex больше не является единственным основанием для расширения допуска.

Проверены startup, потеря ответа, удалённый из outbox parent, accepted/no_effect parent без Trip, own-clock вместе с dependency, чужой actor/device/object и четыре последовательных повтора без чередования старого и исправленного времени.

## 6. S106-T1 — незакрытая граница

Ниже зафиксировано только текущее поведение кандидата, не целевое правило:

| Путь | Текущее поведение |
|---|---|
| Отмена погрузки машинистом | Раннее время только журналируется; затем сохраняется raw `cancelled_at`. |
| Отмена ручной погрузки водителем | Раннее время даёт `cancel_before_load`. |
| Ручное завершение водителем | Раннее время даёт `manual_complete_before_load`. |
| Обычная разгрузка водителем | Раннее время прижимается к `loaded_at`. |

Следовательно, единое правило времени и учёта зависимого события машиниста этим кандидатом не доказано и не реализовано. Тесты C2 доказывают только устойчивость допуска/повтора и сохранение собственного evidence; они не закрывают S106-T1.
