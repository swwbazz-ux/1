# Проверочный пакет P28-I2-R2

Пакет проверяет отдельный неподключённый Django-адаптер свидетельств маршрута.
Он не подключает адаптер к обработчикам или экранам и не изменяет БД
приложения.

## Зафиксированная основа

- свежая release-base: `5721c045d665f5811fc8d343d7374575f386af66`;
- candidate: `bdecc7eb9c528e40a4891201e1bae4682dc309e1`;
- неизменённое ядро R1, Git blob:
  `64b2519fb8bb0874012577fd2d779d7b9a619b74`;
- три acceptance-probe извлекаются из Git commit
  `834539b201b68eb3ac165fefd26c6118eb53e899`, а не читаются из рабочей
  копии.

## Запуск

Из корня `docs/mechanics-passport`:

```powershell
$python = 'C:\Users\swwba\Desktop\Проект учетная система\ПОЕКТ\СИСТЕМА_MVP\.venv\Scripts\python.exe'
& $python '.\ПРОГРЕСС_ПРОЕКТА\ПАКЕТ_P28_I2_R2_2026_09_29\run_isolated_r2.py' `
  --candidate-root 'C:\codex-tmp\p28-i2-r2-route-evidence-adapter-20260929'
```

Runner отказывается работать, если не совпадают HEAD/base, изменён blob ядра,
появились другие файлы кандидата, checkout грязный, присутствует `.env` или
соединение не является временной SQLite `:memory:`.

Опубликованные probes проверяются по Git blob OID и SHA-256. Затем их точные
Git-байты материализуются во временную папку. Поэтому скрытое преобразование
LF→CRLF больше не требуется и `core.autocrlf` не влияет на gate.

## Состав исполнения

1. 21 тест адаптера: прежние 19 и два отрицательных R2 scope-guard.
2. Три исходных probe Астры без изменения ожиданий.
3. Неизменный совмещённый C1/C2 probe Астры.
4. Четыре прежних теста действующих обработчиков точки.
5. `manage.py check` и `makemigrations --check --dry-run`.
6. 30 тестов неизменённого ядра P28-I1-R1, также извлечённых из Git.

PostgreSQL, конкурентный writer, DOM, телефон, native-контур, production,
merge и deploy этим пакетом не проверяются.

`verify_published_manifest.py` отдельно сверяет manifest с байтами конкретного
опубликованного документационного commit через `git cat-file`; проверка рабочей
копии или ручная нормализация строк не используется.

`build_git_manifest.py` строит такой manifest из Git blobs и при необходимости
сверяет опубликованный head удалённой ветки.
