# Аудит CSS Диспетчерского пульта — 25.09.2026

## Цель и границы

Проверен текущий production-derived каскад Диспетчерского пульта в ветке
`codex/dispatcher-stabilization-20260925`. Аудит не пытается автоматически
«упростить» исторические overrides: он разделяет безопасные точные повторы и
правила, которые действительно меняют поведение.

Фактический порядок анализа совпадает с порядком загрузки:

1. `dispatcher-control-v1.css`;
2. `dispatcher-workspace-v1.css`;
3. `dispatcher-detail-v1.css`;
4. `dispatcher-adaptive-v1.css`;
5. `dispatcher-detail-overrides-v1.css`;
6. `dispatcher-canvas-v1.css`.

Воспроизводимая команда из `СИСТЕМА_MVP/backend`:

```text
node tools/audit_dispatcher_css.cjs
```

Отсутствие полностью совпадающих блоков означает, что безопасно удалять целые

точками каскада: среди них базовая сетка, поздняя workspace-компоновка,
адаптивные правила и визуальная настройка диалога смены.

## Риск-зоны изменяющих overrides

Наибольшее число изменённых значений сосредоточено в `.dispatcher-board`,
`.dispatcher-complex-card`, `.dispatcher-complexes`, `.complex-equipment`,
`.complex-trucks`, `.complex-plan`, `.dispatcher-theme-button`, полях общего
диалога смены и адаптивных правилах до `1180px`. Эти `69` свойств не входят в
автоматическую очистку; для каждого нужен отдельный разбор применимости и
визуальных состояний.

## Найденная runtime-регрессия

Во время Browser QA выяснилось, что realtime reconciliation заменяет HTML
общего диалога смены, а прежний inline-обработчик не привязывается повторно.
Идемпотентная инициализация опубликована в `window.initSharedShiftLogin`, а
`dispatcher-realtime-v1.js` вызывает её после обновления DOM. Исправление
оформлено отдельным локальным commit `ecaf672a` и регрессионным runtime-тестом.
