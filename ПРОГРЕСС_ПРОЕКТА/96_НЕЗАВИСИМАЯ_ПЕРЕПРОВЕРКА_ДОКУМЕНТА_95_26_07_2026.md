## 5. Новый дефект QA-CHAOS-P2-001-R3

### Название

Безопасный выход блокируется на старом read-only-экране.

### Приоритет

`P2`.

### Воспроизведение

1. Войти Горным мастером.
2. Оставить его PWA открытой.
3. Переключить активную роль того же сотрудника.
4. Дождаться сообщения `Роль неактивна — доступен только просмотр`.
5. Нажать обычную ссылку `Выйти`.

### Фактический результат

```text
до клика:
http://mining-master.localhost:8000/mining-master/assignments/

после клика:
http://mining-master.localhost:8000/mining-master/assignments/

confirm hidden=true
выход не выполнен
```

### Ожидаемый результат

Безопасный выход должен оставаться доступным на старом read-only-экране и завершать локальную сессию.

### Причина

В `templates/base.html`:

- общий обработчик ссылки `/logout/` сначала выполняет `event.preventDefault()`;
- затем вызывает `openConfirmDialog()`;
- `openConfirmDialog()` при read-only сразу возвращается;
- переход уже отменён, поэтому не выполняется ни confirm, ни logout.

### Требуемое исправление

- отдельно обозначить logout как безопасное действие;
- при read-only либо разрешить для него безопасный confirm, либо выполнить прямой переход;
- не ослаблять запрет изменяющих подтверждений;
- добавить исполняемую регрессию:

```text
роль неактивна
→ клик по обычной ссылке /logout/
→ выход выполняется
```

## 6. Новый дефект QA-REG-P2-001

### Название

В форме закрытия смены Водителя остался вызов отсутствующей функции `resetHold()`.

### Приоритет

`P2`.

### Подтверждение

`templates/users/driver_shift.html` содержит:

```javascript
resetHold();
```

Определения `resetHold` в текущем production-шаблоне больше нет. После рефакторинга управление этим состоянием выполняет `shiftCloseHoldGuard`.

Обычный путь через кнопку `Изменить показания` сначала переводит action обратно в `review`, поэтому в выполненном Browser QA ошибка не возникла и консоль осталась чистой. Но оставшийся production-вызов является реальным интеграционным дефектом: при событии `input` в состоянии `close` он завершится `ReferenceError`.

### Требуемое исправление

- заменить устаревший вызов на корректный reset/cancel текущего `shiftCloseHoldGuard`;
- не оставлять несуществующий идентификатор;
- добавить исполняемый интеграционный тест реального обработчика формы, а не только изолированного общего guard;
- после изменения шаблона поднять Driver PWA shell выше `v104`.
