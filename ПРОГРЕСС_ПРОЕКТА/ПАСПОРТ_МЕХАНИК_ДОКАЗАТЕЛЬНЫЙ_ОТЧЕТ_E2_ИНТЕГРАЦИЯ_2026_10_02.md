## 6. План включения и отката

1. До merge выполнить недостающую установленную E2-приёмку на exact SHA и зафиксировать backend SHA, APK hash, event IDs и receipts.
2. Непосредственно перед решением о merge повторно проверить release head и занятость shell-версии. При новом release влить его в draft-кандидат и повторить обязательный gate.
3. После отдельного разрешения владельца слить draft PR №149.
4. Через защищённый GitHub Actions-канал выполнить `verify` на точном merge SHA. E2 не содержит миграций, поэтому сама по себе не требует `verify_migrations`/`deploy_migrations`; эти режимы нужны только если итоговый совмещённый release содержит отдельно утверждённую миграцию.
5. Deploy выполнять только по отдельному разрешению, на том же полном SHA, затем smoke и физическая проверка приложения.
6. Сохранить выданный workflow `rollback_id`. При отрицательном smoke или проверке устройства использовать защищённый `rollback` к этому идентификатору; прямой SSH не применять.
