### QA-CHAOS-P1-P02-016

Воспроизведение на уничтожаемой test DB:

```text
до POST:
Employee = archived / is_active=false
Access = blocked / is_active=false

POST /system-admin/accesses/<id>/unblock/

после POST:
Employee = active / is_active=true
Access = activated / is_active=true
HTTP = 302
```

Причина: обработчик запрещает `unblock` только для `DISMISSED` и `DELETED`, но затем явно включает `ARCHIVED` в список статусов, переводимых в `ACTIVE`.

Исправление не требует нового бизнес-решения: архив должен восстанавливаться только отдельной процедурой `Восстановить сотрудника`.

### QA-CHAOS-P1-P04-EARLY

Подтвержденное производственное правило реализовано не полностью:

- ранних комплексов обычно три, иногда четыре;
- они начинают и заканчивают работу примерно на час раньше;
- ориентир около `06:00–18:00`;
- отчетных смен остается две: день и ночь;
- график должен настраиваться по конкретному комплексу, а не создавать третью смену.

Сейчас у `EmployeeShift` и комплекса нет такого графика, а отчеты используют глобальные границы `07:00/19:00`.

### QA-CHAOS-P1-P04-NOSHOW

Подтвержденное производственное правило:

- автоматической неявки по таймеру нет;
- неявка фиксируется вручную;
- это могут сделать Заместитель начальника участка, Диспетчер или Горный мастер;
- создается одно событие неявки;
- выбирается один допустимый сменщик;
- параллельное второе решение получает актуальный конфликт;
- авторы и результаты сохраняются в аудите.

Сейчас имеется только пассивное состояние `смена не начата`; доменного действия неявки нет.

### QA-CHAOS-P1-P05-010

Решение владельца получено 26.07.2026:

> Постоянное закрепление техники за сотрудником сохраняется. Открытая на момент отключения техники смена после повторного включения не возобновляется и остается заблокированной для любых производственных действий. После уполномоченного служебного закрытия старой смены сотрудник открывает новую смену по сохраненному постоянному закреплению.

Требования к исправлению:

1. Отключение техники во время открытой смены должно зафиксировать долговременную блокировку этой смены без удаления постоянного `EquipmentAssignment`.
2. Повторное включение техники не должно само снимать блокировку старой `EmployeeShift`.
3. Все изменяющие серверные пути старой смены должны оставаться запрещенными и после повторного включения техники; одного UI-скрытия недостаточно.
4. Уполномоченное служебное закрытие должно сохранить показания и остальные параметры техники, после чего сотрудник может открыть новую смену по прежнему постоянному закреплению.
5. Нельзя автоматически восстанавливать старые временные haul-назначения или старый расформированный комплекс.
6. Нужны постоянные положительные и отрицательные регрессии отдельно для Самосвала и Экскаватора: `отключение → включение → старый POST запрещен → служебное закрытие → новая смена разрешена`.
