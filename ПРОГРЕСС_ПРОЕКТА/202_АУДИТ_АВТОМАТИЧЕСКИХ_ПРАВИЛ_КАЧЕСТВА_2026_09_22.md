### 4.4. Принятый ratchet-дизайн

Первый Python-пакет должен добавить закреплённые quality dependencies,
`pyproject.toml`, repository-owned wrapper и его тесты. Wrapper обязан:

- получать точный base SHA и добавленные строки из Git diff;
- в существующем файле блокировать только нарушение на добавленной строке;
- новый Python-файл проверять целиком;
- `ruff format --check` сначала применять только к новым файлам;
- исключить migrations, generated/vendor и исторические QA artifacts;
- размер нового production-файла более `500` строк и новой функции более `100`
  строк сначала показывать предупреждением, затем включить блокировку после
  проверки ложных срабатываний.

Включение выполняется двумя PR:

- `2A`: non-blocking режим и реальные отчёты;
- `2B`: после подтверждения стабильности добавить job в Required quality gate.

Реализация `2A` закрепляет Ruff `0.16.8` версией и SHA-256. Отдельный job
публикует summary, warning-аннотации и JSON artifact, но намеренно не входит в
агрегатор `Required quality gate`. Находки возвращают успешный код report-only;
невозможность построить достоверный отчёт возвращает код `2` и не маскируется.
Wrapper проверяется существующим обязательным discovery тестов `tools`.

Типы вводятся через `.github/ci/typecheck-targets.txt`: сначала новые и уже
хорошо типизированные доменные сервисы. Большие legacy `views.py` не включаются
целиком до их отдельного безопасного разделения.

pypdf и sqlparse напрямую кодом не вызываются, но остаются закреплёнными
зависимостями. Удаление pypdf и lock транзитивных пакетов не смешиваются с этим
security upgrade.

Локальный `manage.py check --deploy` с безопасными CI-переменными дал только
`security.W004` об отсутствующем HSTS. HSTS нельзя включать механически в рамках
этого этапа: это долговременная production-настройка и требует отдельной
проверки HTTPS/proxy/rollback.

### 6.3. Безопасный security ratchet

1. Отдельным разрешённым settings-шагом включить Dependabot alerts и CodeQL
   default setup; сначала только получить и классифицировать baseline.
2. В CI добавить report-only `pip-audit` и полный npm audit.
3. После классификации блокировать новые `high/critical`; существующее исключение
   допускается только по advisory ID, с причиной, владельцем и сроком.
4. `npm audit --omit=dev --audit-level=high` можно сделать блокирующим раньше:
   текущий production baseline равен нулю.
5. Django deploy-check и Gradle warnings пока публиковать как diagnostics, не
   ослабляя рабочие production-настройки ради зелёного CI.

### 10.2. Подтверждённые риски

#### P1 — CI cache poisoning (`#1-9`, high)

`.github/workflows/nightly-quality.yml` разрешает пользователю с write-доступом
передать произвольный `workflow_dispatch.target_ref`. Доверенный workflow затем
выполняет этот код с включёнными pip/npm/Gradle caches. Обычный внешний PR и
штатный schedule этот путь не открывают, но скомпрометированный write-аккаунт
может отравить кэш последующих доверенных сборок, включая Android supply chain.

Минимальный контур: убрать свободный `target_ref`; для PR/push использовать
точный SHA события, для schedule/manual — фиксированную canonical-ветку; всем
исполняющим checkout добавить `persist-credentials: false`; сохранить
`permissions: contents: read`. Нужны YAML contract tests, проверка resolved SHA,
Required gate и автоматический CodeQL Actions. Rollback — revert workflow-only
commit; откат возвращает риск, поэтому безопаснее forward-fix.

#### P1 — stored/DOM XSS Экскаваторщика (`#18`, high)

В `templates/trips/excavator_work.html` экранированный сервером гаражный номер
читается из DOM, затем повторно вставляется через `innerHTML`. Специально
сформированное значение может создать новый HTML-элемент/обработчик в очереди
разгрузки полевого приложения Машиниста экскаватора.

Минимальный контур: создавать `img` и `strong` через `createElement`, записывать
номер только через `textContent`; добавить runtime-тест с вредоносной строкой.
Поскольку код входит в кэшируемый HTML shell, атомарно поднять Excavator shell
`v250 -> v251` во всех восьми контрактных местах. Gate: профильные Node/Django
тесты, полный JS suite, Required, PostgreSQL nightly, CodeQL и Browser QA
online/offline очереди разгрузки. Миграций и данных нет; безопасный rollback —
только forward-fix `v252`, потому что возврат `v250` возвращает уязвимость.

#### P2 — внешний redirect Диспетчера (`#30-40`, medium)

`trips/views.py` берёт `POST next` или `HTTP_REFERER` и после штатного изменения
смены передаёт значение в redirect. Маршрут требует активной роли и CSRF, но
подставленный внешний URL способен увести Диспетчера/Администратора на phishing
страницу после успешного действия.

Минимальный контур: единый same-host validator на
`url_has_allowed_host_and_scheme`, внутренний fallback и `urlencode` для query.
Тесты: внешний URL, protocol-relative/backslash/CRLF, внешний Referer,
разрешённый относительный/current-host URL и специальные символы параметров;
затем dispatcher mutation, PostgreSQL smoke/chaos и полный gate. Rollback —
revert одного code-only commit, без БД и миграций.
