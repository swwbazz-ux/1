# P28-I1-R1 — точная граница сходимости

## Сходится

При одинаковом полном наборе валидных бизнес-событий и одинаковом lifecycle сходится результат `Projection.business_dict()`:

- статус и причина выбора;
- выбранные event ID и point ID;
- причинные максимумы и отсутствующие предки;
- устойчивые диагностические основания;
- каноническая история бизнес-содержания без receipt time;
- идентичность исходной погрузки;
- operational allowed/reason;
- notification key выбранного события.

Причина сходимости прежняя: граф строится по ID наблюдённых предков, максимумы являются свойством графа, P28-В3 применяется только к ролям ровно двух независимых максимумов. Часы и порядок доставки не являются tiebreaker.

## Не обязано сходиться

Фактический аудит доставки отражает разные процессы и потому не объявляется одинаковым:

- порядок `ReceiptObservation.observation_index`;
- переданное адаптером `reported_received_at`;
- disposition каждого предъявления;
- `duplicate_count`;
- первое сохранённое receipt-поле полного `Projection.to_dict()`;
- порядок несовместимых предъявлений одного ID.

Эти значения сохраняются отдельно и не участвуют в route choice. Имя `reported_received_at` не утверждает, что адаптер доказал первое серверное получение.

## Конфликтующие ID

Все уникальные несовместимые конверты сохраняются полностью. Первое содержание остаётся применяемым только как сохранённый оригинал; наличие конфликта переводит каждый затронутый рейс в `integrity_conflict`. Конфликтующий конверт не применяется и не исчезает. Повтор идентичного конфликтующего конверта добавляет только receipt-наблюдение.

## Неполная история

`history_complete=False` — прямое доказательство неполноты, независимо от числа известных событий. Поэтому ни 0, ни 1, ни N записей не дают окончательного победителя. После изменения только контекста на `history_complete=True` проекция пересчитывается из того же ledger.

## Ограничение доказательства

Исходные 22 теста и восемь тестов R1 проверяют заданную матрицу. Все 24 перестановки относятся к одному четырёхсобытийному графу. Это не доказательство всех DAG, транспорта, конкурентной БД или installed-app поведения.
