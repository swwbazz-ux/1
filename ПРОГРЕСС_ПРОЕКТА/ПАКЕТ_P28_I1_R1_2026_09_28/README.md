# P28-I1-R1 — сохранность конфликтов и честная неполная история

Основа задания: `docs/mechanics-passport` `8d8948647d22ecefc69b0ef214a665344637cd9b`. Зафиксированная release-основа только для контекста: `f2248cb79c737e98b580e784abea394335a2700b`.

Это отдельный pure-Python пакет. Исходный `ПАКЕТ_P28_I1_2026_09_28`, его manifest и raw не изменяются. R1 не подключён к Django, БД, handlers, очереди, экрану или native audio.

## Исправления C1/C2

### C1 — несовместимый ID

- первое содержание ID остаётся единственным применяемым событием;
- каждый новый несовместимый конверт сохраняется полностью: рейс, автор, роль, точка, времена, предки, loading ID и fingerprint;
- конфликт диагностируется во всех рейсах, затронутых оригиналом или несовместимым конвертом;
- третий рейс не меняется;
- повтор того же конфликтующего конверта не создаёт второе свидетельство и не имеет бизнес-эффекта;
- snapshot → JSON → restore сохраняет оригинал, конфликты и receipt-аудит.

### C2 — явно неполная история

`history_complete=False` всегда возвращает `causality_incomplete`, включая 0, 1 и несколько известных событий. Победитель и notification key отсутствуют. После подтверждения полноты тот же ledger пересчитывается без нового действия сотрудника.

## Граница C3

`Projection.business_dict()` — обещанная сходящаяся бизнес-проекция. В неё входят решение, точка/событие, причинные максимумы, устойчивые причины/диагностика, loading identity, lifecycle и допустимость notification key. Из неё исключено `received_at`.

`Projection.to_dict()` — полный исторический вид; он может различаться по первому сохранённому receipt-полю. `RouteLedger.audit_snapshot()` отдельно хранит все предъявления с `observation_index`, честным именем `reported_received_at` и disposition. Этот порядок не участвует в выборе направления. `duplicate_count` — свойство доставки, не бизнес-решения.

## C4 — запуск и журналы

Из корня чистой ветки-потомка основы:

```powershell
& '.\ПРОГРЕСС_ПРОЕКТА\ПАКЕТ_P28_I1_R1_2026_09_28\run.ps1' -DocsRoot (Get-Location).Path
```

Gate использует `git status --porcelain=v1 --untracked-files=all`, поэтому прекращает запуск при staged, unstaged или любом untracked-файле. Журнал содержит требуемую основу, фактический HEAD, release-маркер и результат gate.

Runner перенаправляет одновременно stdout и stderr в `raw-run-r1-utf8.log`; поэтому в raw присутствуют unittest-строки и `P28_I1_TRACE`/`P28_I1_R1_TRACE`. Затем неизменный приёмочный probe Астры запускается против R1 и сохраняется в `acceptance-replay-r1-utf8.log`.

## Ожидаемые трассы до запуска

| Трасса | Ожидаемое |
|---|---|
| Полный конфликтующий конверт → snapshot/restart | Оригинал и конфликтующий конверт восстанавливаются полностью |
| Один ID между X/Y плюс независимый Z | X/Y `integrity_conflict`; Z остаётся resolved |
| Повтор конфликтующего конверта | Одно конфликтное свидетельство, отдельное receipt-наблюдение, нет бизнес-эффекта |

| Исходные 22 теста | Все проходят на R1 |
| Приёмочные C1/C2/C3 probes Астры | 3/3 contract pass, exit 0 |
