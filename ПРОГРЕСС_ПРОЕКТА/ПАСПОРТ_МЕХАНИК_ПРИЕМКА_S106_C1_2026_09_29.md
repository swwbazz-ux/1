## 3. Уточнённое описание механики для рецензии

### 3.1. Идентичность и допуск раньше выбора времени

Предложенное в проекте раннее `if own_clock_is_invalid(existing): allowed=True` неприемлемо без статуса и кода. После первого успешного восстановления raw `occurred_at` остаётся плохим; второй запрос снова попадёт в handler вместо сохранённого результата. Плохие часы также не должны превращать произвольный предметный отказ в разрешённый replay. Это ошибка **псевдокода проекта**, не утверждение о таком дефекте текущего PR.

Обязательный порядок:

1. Сначала проверить неизменность event ID и actor/access/role/device/fingerprint. Несовместимый конверт сохраняется как отдельная попытка и не подменяет оригинал.
2. Уже `ACCEPTED`, включая `no_effect`, возвращает сохранённый результат без второго handler-эффекта, независимо от исходных часов. `RETRY` остаётся отдельным существующим путём, его нельзя случайно превратить в terminal при рефакторинге.
3. Для старого `CONFLICT` определить допустимую **роль / event type / код**. `device_clock_ahead` дополнительно требует доказанного собственного сдвига. Другие статусы/коды не открываются самим фактом плохого времени.
4. Только после допуска выбрать time-policy из доказательств **самого события** и независимо выбрать dependency-policy по основанию replay. Возвращать reason и обе политики, а не один общий bool.

Минимальные проверки: повтор ACCEPTED с плохим raw-time; неподходящий код с плохим raw-time; `device_clock_ahead` без доказанного сдвига; обычный RETRY; допустимый dependency-conflict одновременно с плохими собственными часами.

### 3.2. Время и зависимости — независимые признаки

Плохие часы предка не доказывают плохие часы ребёнка. Собственный исходный timestamp ребёнка сохраняется. Восстановление по зависимости не должно автоматически ставить `clock_adjusted=True`.

Обратное тоже важно: если собственные часы ребёнка действительно плохие, выбор `first_received` не отменяет его допустимую самостоятельную обработку по своим ссылкам. Ранний clock-return с `dependency_policy='normal'` из проекта теряет второе условие. Значения `normal` и `advisory_own_refs` должны иметь явную семантику, а не означать «как получилось в выбранной ветке».

Чужой/непришедший/отказанный предок не даёт ребёнку полномочий или объектов. Handler разрешает собственные ссылки в доказанной области автора/устройства/смены/техники. Если нужного объекта ещё нет, это сохранённое ожидание предметной ссылки с существующим механизмом повторной обработки; нельзя выдать успешный учёт без факта или заимствовать чужой `trip_id`.

### 3.3. Сохраняем восстановление корня свободного ковша

Целевая механика обязана сохранить релизный путь: повтор исходного `driver.trip.loaded/free_bucket_not_available`, locked revive/self-accept своего права, предметную идемпотентность погрузки и возможность обработать её завершение.

В client startup сначала надо поднимать доступный восстанавливаемый корень, затем зависимого ребёнка. Но квитанция `accepted/no_effect` родителя сама по себе не доказывает наличие конкретного Trip. Для завершения нужна доказанная собственная ссылка на рейс; недоступный корень не заменяется фиктивной погрузкой. Самостоятельное событие с достаточными собственными ссылками не обязано ждать нерелевантного предка.

Условие «другое живое право» сохраняется как явно исследуемая граница текущего release, а не новая утверждённая причина мешать работе. S106-патч не должен молча обходить его либо объявлять все такие коллизии решёнными.

## 4. Открытое место: время факта и предметная хронология

Принимаю принцип сохранения честного времени ребёнка как следствие ГП-0. Однако опубликованный probe проверяет только отмену машиниста и намеренно получает:

```
погрузка: raw clock недостоверен, прикладной loaded_at = first_received
отмена: собственное время = first_received − 30 секунд
```

На PR `17cbb3e9` реально разные пути (`core/offline_sync.py`):

- `_process_excavator_loaded_cancelled`, около 3340: логирует `cancel_before_load` и записывает ранний `cancelled_at`;
- `_process_driver_manual_completed`, около 3596: возвращает `manual_complete_before_load`;
- `_process_driver_unloaded`, около 3690: сдвигает прикладной `unload_at` до `loaded_at`.

Поэтому 5/5 не доказывает восстановление всех цепочек без нового отказа или изменения производного времени. Время получения погрузки — запасная оценка, оно не доказывает, что честное завершение произошло раньше физической погрузки.

Нужна адресная договорённость для этих трёх путей: как сохранить собственные факты и проверенную принадлежность одному рейсу, как обозначить неопределённость производного интервала и продолжить обработку без повторного ввода работником. Не исправлять проблему подменой raw-time ребёнка или выдуманным временем погрузки. Новые правила оплаты, отмены уже выполненного рейса R-12 и весь глобальный M-TIME этой сверкой не утверждаются.
