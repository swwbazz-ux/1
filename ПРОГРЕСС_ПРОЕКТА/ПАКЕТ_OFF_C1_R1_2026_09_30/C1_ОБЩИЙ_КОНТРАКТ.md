# C1: узкий общий контракт fingerprint

Источник: release `f7302f4346f64f5e8bfe89c7a4da232f7caed648` → кандидат `6c31e8545fd5f5da727ce077774ab4eaf07fd21b`.

Это первая безопасная точка для согласования с отдельной Driver-работой. **Нельзя переносить в Driver весь OFF-C1-R1.** Переносима только следующая семантика `core.offline_sync.normalize_offline_event`:

1. `local_shift_id` извлекается до построения immutable envelope.
2. Если wire-событие release не содержало `local_shift_id`, пустой ключ не добавляется ни в `normalized`, ни в canonical JSON. Поэтому ранее сохранённый fingerprint остаётся точным повтором.
3. Непустой новый `local_shift_id` добавляется до fingerprint и защищён от подмены так же, как payload.
4. Серверный `confirmation_token` добавляется только после fingerprint: это capability повторной доставки того же immutable close, а не новая личность события.
5. Массовое изменение старых receipts не требуется и не разрешается этим кандидатом.

Минимальный смысловой diff:

```python
local_shift_id = str(
    raw_event.get('local_shift_id')
    or payload.get('local_shift_id')
    or context_snapshot.get('local_shift_id')
    or ''
).strip()[:128]

normalized = {...}
if local_shift_id:
    normalized['local_shift_id'] = local_shift_id

canonical = {...normalized, 'occurred_at': occurred_at.isoformat(), ...}
normalized['fingerprint'] = sha256(canonical)
normalized['confirmation_token'] = str(raw_event.get('confirmation_token') or '').strip()
```

Адресные регрессии:

- `test_release_fingerprint_lost_response_replays_for_both_field_roles`;
- `test_release_fingerprint_retry_receipt_stays_retryable_for_both_field_roles`;
- `test_release_fingerprint_recoverable_conflict_reprocesses_for_both_field_roles`;
- в первом тесте отдельно проверены подмена `local_shift_id` и payload → `event_id_reused`.

Результат текущего SQLite-прогона этих тестов входит в общий `core.test_offline_sync`. Перед совместной интеграцией Driver обязан повторить те же сценарии обеих ролей на точной общей реализации; это не разрешение merge.
