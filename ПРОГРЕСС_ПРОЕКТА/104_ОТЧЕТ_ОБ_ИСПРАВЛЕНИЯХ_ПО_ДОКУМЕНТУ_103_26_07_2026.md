## 2. QA-CHAOS-P1-P09-012

### 2.1. Воспроизведение

До исправления красная матрица показала:

- отсутствовал единый version-contract HTML ↔ JavaScript ↔ service worker ↔
  серверный poll;
- статические файлы нескольких PWA обслуживались стратегией
  `cache-first` с `ignoreSearch: true`;
- новый HTML мог получить старый JavaScript;
- несовместимая оболочка не блокировала изменяющие действия;
- ролевые service worker не публиковали единый набор
  `appContractVersion/shellVersion/roleCode`.

Исходный результат:

```text
users.test_chaos_p09_contract:
3 tests, 46 subtest failures

static/js/tests/pwa-contract-runtime.test.js:
1 PASS, 1 expected FAIL, 4 SKIP
```

### 2.2. Подтверждённая причина

Версия PWA существовала только как локальный cache-name отдельных оболочек.
HTML, загруженный JavaScript, service worker и серверный ответ не подтверждали
взаимную совместимость. `ignoreSearch: true` дополнительно разрешал вернуть
старый статический файл для нового URL с cache-buster.

### 2.3. Исправление

Добавлен единый контракт `pwa-contract-v1`:

- manifest каждой из 11 ролей публикует contract, shell и role;
- HTML публикует те же значения в `data-app-*`;
- service worker отвечает теми же значениями на `GET_VERSION`;
- operational-state poll публикует серверный contract;
- `realtime-client.js` регистрирует версию исполняемого JavaScript;
- inline-guard в `base.html` разрешает изменения только при согласованном
  контракте;
- при несовпадении guard блокирует изменяющие действия, показывает сообщение,
  вызывает `registration.update()` и отправляет `SKIP_WAITING`;
- один contract допускает не более одного контролируемого reload;
- guard не изменяет и не удаляет открытый рейс и не отправляет mutation-запрос;
- согласованная старая оболочка остаётся доступной offline;
- при появлении нового серверного contract старая оболочка блокируется;
- для legacy-path используется тот же metadata-contract, но сохраняется
  ограниченный legacy scope;
- все стратегии статики переведены на `network-first` + `cache: "no-store"`
  с точным cache-key, без `ignoreSearch: true`;
- очистка cache остаётся ограниченной prefix конкретной роли.

## 3. Расширение QA-CHAOS-P1-P06-015-P08-006 по P11-012

### 3.1. Воспроизведение

Красная регрессия подтвердила:

- HTML-путь создавал рейс как `ACTIVE` и сразу сохранял факты `40/80`;
- JSON-путь создавал `LOADED_WAITING_UNLOAD` с `NULL`;
- один путь был виден в сменной аналитике иначе, чем второй;
- после изменения справочников на `60 м3` и плотность `3` HTML-рейс сохранял
  старые `40/80`, а JSON-рейс фиксировал `60/180`;
- завершённый legacy-рейс с `NULL` менял результат после изменения справочника;
- transport показывал `Смена не определена`;
- management dynamics теряла ночной legacy-рейс в
  `hour/day/shift/month`.

Исходный результат:

```text
trips.test_chaos_p06_p08_p11_legacy:
11 tests, 10 failures
```

### 3.2. Подтверждённая причина

HTML и JSON использовали разные конструкторы рейса. Кроме того, read-only
отчёты пытались восстановить факты завершённого legacy-рейса по актуальным
справочникам. Дата и смена legacy-рейса определялись разными полями в разных
отчётах.

### 3.3. Исправление

Создан единый серверный конструктор
`create_loaded_waiting_unload_trip()`:

- HTML и JSON создают одинаковый `LOADED_WAITING_UNLOAD`;
- до разгрузки `volume_m3=NULL`, `tonnage=NULL`;
- при разгрузке оба маршрута фиксируют актуальные на этот момент параметры
  справочников;
- после разгрузки сохранённый snapshot больше не меняется;
- idempotency, блокировки и одноразовое закрытие простоя сохранены;
- legacy `ACTIVE` остаётся разгружаемым;
- завершённый legacy `NULL` больше не пересчитывается по справочнику:
  стабильный read-only результат равен `0/0`;
- дата и смена такого legacy-рейса определяются один раз по `completed_at`;
- тот же fallback используется в mining, transport, daily, shift analytics,
  management и соответствующих Excel;
- чтение отчётов не записывает данные в БД;
- migration/backfill не создавался.

### 3.4. Регрессии

Проверены:

- HTML/JSON parity;
- видимость обоих рейсов у Водителя и в аналитике;
- справочник `40/2 → 60/3`, результат разгрузки `60/180`;
- стабильность snapshot после следующего изменения справочника;
- повтор одного client action без дубля;
- legacy `ACTIVE`;
- одноразовое закрытие простоя;
- legacy completed `NULL` до/после изменения справочника;
- экран и Excel transport/daily/analytics/management;
- `Все = День + Ночь`;
- матрица `day/night × hour/day/shift/month`;
- повторное чтение без изменения БД.

Результат:

```text

reports: 20/20 OK
```

## 4. QA-CHAOS-P2-P09-010

### 4.1. Воспроизведение и причина

Первый `401` operational-state poll возвращал `null`, но клиент продолжал
interval/focus/pageshow polling. Уже открытые confirm/hold и mobile queue не
получали терминального сигнала завершения аутентификации.

Исходная JavaScript-регрессия:

```text
3 tests: 2 PASS, 1 expected FAIL
401: read-only transition отсутствовал
```

### 4.2. Исправление

Первый `401` теперь атомарно:

- устанавливает `authEnded=true`;
- останавливает оба interval;
- отменяет текущий poll;
- запрещает следующие poll/focus/pageshow/online wake;
- очищает pending operational update и mobile mutation queue;
- один раз переводит экран в read-only;
- одним событием сбрасывает confirm/hold;
- показывает сообщение о завершении сессии;
- один раз переводит на `/`, без reload-loop.

`500` и offline остаются восстанавливаемыми сетевыми состояниями.

Результат:


## 5. QA-CHAOS-P2-P09-011

### 5.1. Воспроизведение и причина

Если администратор менял роль внутри того же `EmployeeAccess`, старый session
содержал тот же access id и не видел смену роли.

### 5.2. Исправление

В session сохраняются:

- `active_role_code`;
- timestamp/revision входа.

Poll возвращает session snapshot и active snapshot. Если роль того же доступа
изменилась:

- старый poll получает `role_active=false` или `401`;
- старый экран становится read-only;
- старый POST получает `409 inactive_role`;
- права новой роли появляются только после нового входа;
- открытая старая сессия не создаёт смену и не получает новые полномочия.

Результат:

```text

```
