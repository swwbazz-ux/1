# P28-I1 — исполняемое ядро выбора направления рейса

**Это единственное новое поручение Кодексу.** Реализовать и проверить изолированное ядро правил маршрута как первый ограниченный этап кандидата. Оно пока не подключается к рабочему приложению; текущие handlers, БД, очереди, экран и native остаются прежними. Не проводить новый общий аудит и не повторять P28-C1/R1 вместо реализации этого ядра.

## 1. Утверждённая область

- Независимые указания водителя D→P2 и машиниста O→P3 по тому же продолжающемуся рейсу: текущим направлением становится P2 водителя. Оба события сохраняются. Порядок доставки и сравнение часов победителя не меняют.
- Если машинист создал P3 после наблюдения D→P2, его причинно последующее P3 действует по ранее утверждённому P28-В2. Новое решение не является постоянным превосходством водителя над машинистом.
- Сменщик того же экскаватора вправе дать маршрутное распоряжение по P28-В1, с отдельным авторством и неизменной исходной погрузкой.
- Исходная точка погрузки/отчёт 188, маршрут в пути, подтверждённая разгрузка и административная коррекция — разные значения.

Вопросы независимых команд одной роли/двух устройств, R-04/R-12/R-13, новые архивные полномочия и выбор между противоречивыми физическими погрузками этим заданием не решаются.

## 2. Результат реализации

Подготовить небольшой модуль на Python без Django/БД/сети и его запускаемые тесты. Разместить вместе с README и журналом в отдельном пакете `ПРОГРЕСС_ПРОЕКТА/ПАКЕТ_P28_I1_2026_09_28/` документационной ветки. Пакет — исполняемый прототип ядра, не новая бизнес-логика в production. Отдельная локальная рабочая копия, свежие refs перед началом и перед публикацией; сохранить параллельные изменения документов.

Вход — нормализованные неизменяемые события конкретного рейса с ID, отпечатком содержания, типом, автором/ролью, целевой точкой и наблюдёнными предками; отдельно исходный контекст и подтверждённые свидетельства жизненного цикла. Граница доверия явная: ядро не доказывает подпись/полномочие/фактический показ UI. Оно получает уже проверенный контекст; ответственность будущего адаптера описывается, не подменяется проверкой произвольной клиентской строки.

Выход: сохранённая история/идентичности, выбранная точка и основание выбора, идентичность действующего маршрутного события либо честное состояние неразрешённости; отдельно допустимость оперативного показа/уведомления этого рейса. Исходные записи не удаляются при смене результата. Никаких реальных звуков, уведомлений или изменений рейса ядро не выполняет.

## 3. Обязательные свойства алгоритма

1. **Сначала причинность, затем правило независимых событий.** Построить проверяемое отношение предшествования; рассматривать актуальные причинно максимальные события, а не сортировать все события нестабильным попарным правилом «позже по причинности, иначе водитель». Такой компаратор может дать цикл. Обосновать выбранный алгоритм на коротких цепочках.
2. Для полной истории с единственным актуальным D и независимым O выбрать D по P28-В3. Если O наблюдал D и причинно следует ему — O по P28-В2. Предки не возвращаются как текущие из-за повторной доставки.
3. Отсутствующий предок, цикл, несовместимый повтор ID или неполная legacy-история не превращаются в доказанную независимость. События сохраняются; результат явно показывает, чего не хватает. При поступлении доказательства пересчитывается без повторного действия сотрудника. Реальный фоновый исполнитель в этом пакете не создаётся.
4. Независимые актуальные события одной роли не получают победителя по времени, ID, поступлению или должности. Для неутверждённых сочетаний вернуть отдельный результат `policy_unresolved` с причиной; это внутренний результат прототипа, не проект блокирующего экрана сотрудника. Нельзя объявить весь такой набор «решённым» только потому, что одна пара D/O имеет утверждённое правило.
5. Для известной отмены, подтверждённой разгрузки или доказанного замещения X более поздним Y история X сохраняется, но X не становится оперативным поверх Y и не получает голосовую команду ехать обратно. UNCONTROLLED по таймеру сам по себе не означает разгрузку. Пустой superseded_by не доказывает отсутствие Y. Старое actual без происхождения не создаёт событие водителя.
6. Время действия/приёма хранится раздельно и не меняет доказанную причинную связь. Идентичный набор событий и доказательств даёт одинаковую конечную проекцию при всех порядках доставки; промежуточная доступность данных может различаться и показывается отдельно.
7. Повтор одного ID/содержания не создаёт второй маршрутной записи. Другой payload под тем же ID не заменяет сохранённый оригинал; конфликт явно диагностируется. Ключ для будущей озвучки связан с выбранным маршрутным событием, не с произвольной общей версией снимка. Физическое воспроизведение «ровно один раз» не заявляется.

## 4. Минимальные проверки

Тесты должны проверять утверждённые исходы и инварианты, а не пересказывать строки реализации. Входы и ожидаемый результат каждой трассы описать перед результатом запуска.

| Трасса | Ожидаемое |
|---|---|
| Независимые D:P2 и O:P3, оба порядка | P2; оба автора и события сохранены |
| D:P2 → O:P3 с наблюдением D, доставка O раньше D | После полной доставки P3; до D причинность не объявлена независимой |
| O:P1 → D:P2 | Последующее D действует; исходная погрузка P1 не переписана |
| D:P2 → O:P3 при часах машиниста −3 минуты | P3; времена сохранены, причинность не заменена сортировкой по часам |
| Независимые D и O1; O2 видит O1, но не D | Видимость собственного предка не делает O2 последующим относительно D; после полной доказанной истории правило В3 сохраняется |
| Разветвлённая история из 3–4 событий | Перебор всех перестановок доставки; одинаковый итог либо одинаковое явно открытое сочетание, без скрытого попарного цикла |
| Независимые цепочки D1→O1 и D2→O2 | Актуальный причинный набор O1/O2: неутверждённая коллизия одной роли. Попарный цикл O1 > D1 > O2 > D2 > O1 не используется для выбора |
| Повтор, потеря квитанции, пересоздание процесса из тех же записей | Та же история и результат; сериализация/десериализация не заявляется проверкой реального телефона |
| Несовместимый повтор ID; цикл; отсутствующий предок | Сохранность и явная диагностика; нет выдуманного победителя |
| Ссылка предка на другой рейс | Не создаёт причинную связь между маршрутами разных рейсов и не меняет соседний рейс |
| Два независимых водителя/машиниста одной роли | `policy_unresolved`, не произвольный победитель |
| Сменщик того же экскаватора | Автор погрузки и автор новой команды различимы; роли не сливаются |
| X после технического таймера, затем маршрутная правка | Нет выдуманной разгрузки; адресная история сохраняется |
| X CANCELLED / X разгружен / X заменён Y без старой FK | История X сохранена, нет рабочего показа/уведомления X поверх завершения/Y |
| Legacy actual=P3 после коррекции или неизвестного источника | Нет выдуманного события водителя и новой маршрутной озвучки |

Смешанные сложные сочетания не упрощать удалением неудобных событий. Если появляется конкретная недостающая норма, сохранить минимальный контрпример и пометить границу, не выбирать политику самостоятельно. Подготовленное ядро и все остальные проверки всё равно завершить.
