# Паспорт механик — протокол работы и роли

Редакция 2 от 27.09.2026 — по прямому указанию Василия (передано Астрой). Заменяет редакцию 1, в которой работой руководил Claude «Паспорт механик». Обязателен для всех участников. Цель — чтобы чаты не рассинхронизировались и владелец не был «почтальоном» без понимания, что куда.

## Участники и полномочия

| Участник | Кто | Что делает | Что НЕ делает |
|---|---|---|---|

| **Астра** | ChatGPT Астра 6 | **Руководит проектом**: определяет очерёдность работы, готовит решения, ставит задачи Кодексу, проверяет результаты, собирает и выносит вопросы Василию. | Не утверждает правила вместо владельца. |
| **Рецензент** | Claude, чат «Паспорт механик» | **Независимый технический рецензент**: проверяет решения Астры и результаты Кодекса, ищет ошибки и противоречия, предлагает альтернативы — прямо и по существу, согласие ради согласия не требуется. ## Разногласия
Замечания рецензента Астра и рецензент разбирают вместе. Если договориться не удалось, Астра передаёт Василию обе позиции, последствия вариантов и свою рекомендацию. Молчание или недоступность не считаются согласием.

## Недоступность рецензента
Проект не зависит от постоянного присутствия рецензента. Если рецензент недоступен, Астра продолжает работу с дополнительной проверкой и явно отмечает, какие решения не получили его рецензии. Требование утверждения владельцем сохраняется.

## Единственный источник правды
Файл паспорта в репозитории `swwbazz-ux/1`, ветка `docs/mechanics-passport`, `ПРОГРЕСС_ПРОЕКТА/ПАСПОРТ_МЕХАНИК.md`. Все ссылаются на механики по ID (например `M-DOWN-1`). Что не записано в файле — не решено. Правила сервера — `191_ЕДИНЫЙ_КОНТРАКТ_РОЛЕВЫХ_ПРИЛОЖЕНИЙ.md` v1.0 (`CR-*`); паспорт на них ссылается.

## Жизненный цикл каждой механики
`ЧЕРНОВИК` (автор черновика) → `КРИТИКА` (рецензия Claude) → `СОГЛАСОВАНО` (Астра + рецензент; без рецензии — Астра с пометкой «без рецензии Claude») → `УТВЕРЖДЕНО` (Василий) → `В РАБОТЕ` (Кодекс, номер PR) → `ВЫЛОЖЕНО` (Координатор, SHA) → `ПРИНЯТО` (проверено Василием на реальном телефоне).
Статус меняет только тот, кто указан в скобках.

## Кто кому пишет
- Астра → Кодекс — задания; Кодекс → Астра — ответы и отчёты (копия рецензенту, если результат нужен для рецензии).
- Астра ⇄ Рецензент — решения на рецензию, замечания, альтернативы.
- Астра → Василий — пакет «Решения владельца» (вопросы пронумерованы, у каждого варианты, последствия и рекомендация; при разногласии — обе позиции).
- Кодекс ⇄ Координатор — только очередь выкладки (слить/выложить/проверить).
- Если рецензенту нужен факт из кода, он формулирует вопрос Астре, и та включает его в своё задание Кодексу.
- Никто не пишет в обход этой схемы.

## Формат каждого пересылаемого сообщения
Первая строка всегда:
`ОТ: <кто> → КОМУ: <кто> | ТИП: вопрос / предложение / возражение / решение / задание / отчёт / рецензия | МЕХАНИКИ: <ID через запятую>`
Одно сообщение — один получатель. Владелец пересылает блок целиком, ничего не дописывая.

## Правила содержания
- Правила владельца от 26.09 (см. бриф) выше любых документов. Предложение, которое им противоречит, помечается «ПРОТИВОРЕЧИТ ПРАВИЛУ N» и выносится владельцу, а не принимается молча.
- Каждое правило паспорта должно иметь приёмочную проверку: стенд на PostgreSQL + реальный телефон в фокусе + фоновая нагрузка других машин.
- Для каждого места, где сервер может отказать работнику, паспорт даёт правило без отказа (кроме битых данных).
- Вопросы владельцу — только те, на которые нет ответа в правилах и журнале решений.
