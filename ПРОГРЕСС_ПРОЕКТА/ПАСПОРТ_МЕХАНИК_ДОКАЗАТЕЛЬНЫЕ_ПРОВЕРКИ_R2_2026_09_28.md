## 3. Спорный старт простоя

Проверен ровно сценарий: причина «Ожидание разгрузки» требует гружёного рейса, но на сервере нет открытого рейса; событие пришло через offline sync с `occurred_at` на две минуты раньше receipt, без `sent_live` и `clock_unreliable`.

На обоих SHA:

- первый ответ — `accepted`, `code=''`, `retryable=false`;
- warning содержит `loaded_trip_required`;
- `OfflineFieldEvent.status=accepted`, `error_code=''` и `downtime_event_id` указывает на конкретный созданный `DowntimeEvent`;
- `receipt.occurred_at == DowntimeEvent.started_at ==` времени действия телефона;
- повтор того же `event_id` — `deduplicated`, второй простой не создан;
- operational version вырос на первой записи и не изменился на повторе.

Кодовый путь PR: `core/offline_sync.py::_process_downtime`, строки 3863–3943; несовпадение гружёности записывается через `_log_discrepancy`, а не превращается в отказ.

Граница доказательства: проверена только ветка корректного прошлого device-time без clock hints. Не проверены `sent_live`, `clock_unreliable`, future-skew, исправление часов и установленное приложение. PostgreSQL-атомарность этого сценария не доказана.

## 4. Manager и контрольные роли

Fixture создаёт разных сотрудников: Диспетчер, Manager, Администратор и Горный мастер. Единственная открытая диспетчерская смена принадлежит чужому сотруднику-Диспетчеру. Для ролей отправляются одинаковые assign/release payload.

Фактическая матрица на обоих SHA:

| Роль и условие | Assign | Release | Данные |
|---|---:|---:|---|
| Manager, чужая диспетчерская смена открыта | 200 | 200 | создан отдельный `HaulAssignment(status=pending)` соответствующего action; `assigned_by=manager`; создан `ShiftClientAction` с actor Manager и чужой dispatcher shift |
| Dispatcher, смена открыта | 200 | 200 | то же изменение по тому же payload, actor Dispatcher |
| Admin, чужая диспетчерская смена открыта | 200 | 200 | то же изменение по тому же payload, actor Admin |
| Manager, диспетчерская смена закрыта | 409 | 409 | число/состояние assignments, version и receipt count не изменились |
| Горный мастер, диспетчерская смена открыта | 403 | 403 | assignments, version и receipt count не изменились |

Это доказывает фактический доступ, но не утверждает его нормативную допустимость.

## 5. Stale assign и placement

Проверены два ранее не покрытых варианта stale assign с заведомо неверным `expected_state_id`:

1. у целевого экскаватора placement существует, но `zone=inactive`;
2. placement отсутствует.

В обоих вариантах и на обоих SHA ответ — HTTP 409, `code=state_conflict`; assignment не меняется и `ShiftClientAction` не создаётся. Однако до отказа сервер соответственно переводит placement в `active` либо создаёт новый `active` placement и поднимает operational version (в варианте создания — на два шага).

Кодовый путь PR: `trips/dispatcher_topology_commands.py::execute_dispatcher_assign_truck`, placement создаётся/активируется в строках 321–325, а stale-проверка возвращает `state_conflict` позже, около строки 336. Это зафиксированный бизнес-дефект R2; исправление не выполнялось.

## 6. Очередь Горного мастера

Node-probe не ищет текст regex. Он извлекает из фактического `templates/trips/dispatcher_control.html` и исполняет функции `read/write/enqueue/schedule`, `dispatcherPostQueued`, `flushDispatcherSyncQueue` и `showDispatcherDnDError` (PR: строки 898, 996, 1604 и связанные функции).

Фактическое поведение на обоих SHA:

- повторные команды одного самосвала схлопываются в одну; остаётся последний payload;
- HTTP 409: команда удаляется, повтор не планируется, вызываются notice, stale marker, два mobile refresh и один desktop refresh;
- HTTP 503: команда также удаляется как terminal, повтор не планируется, вызываются notice и один mobile refresh, desktop refresh не вызывается;
- сетевой `TypeError`: команда остаётся, `attempts` становится 1, планируется retry через 1200 мс, refresh/notice не вызываются.

Таким образом, временный 5xx сейчас теряет команду, тогда как сетевой сбой сохраняет её. Бизнес-исправление не делалось.

Проверены вызовы функций отображения/обновления, но не фактический DOM, внешний вид, браузер или установленное рабочее место. Отрисовка: **NOT_RUN**.
