## 2. Две обязательные правки ядра

### C1. Содержание несовместимого повтора теряется

`route_core.py:118–121, 168–172, 178–182`: Collision хранит ID и два fingerprint, но не входной конверт. Вход: `D/X/P2`, затем тот же `D/X/P9`. После snapshot → JSON → restore остаются P2 и хеш второй записи. Само P9, его автор, время, предки и остальные поля восстановить невозможно. Тест проверяет сохранность первого события, но не второго.

Дополнительная трасса: первым пришёл `D/Y/PY`, затем `D/X/PX`. Вторая запись потеряна, а `project(X)` возвращает `no_route_event` без диагностики — фильтр конфликтов на строках 205–208 смотрит только на события X, оставшиеся в основном словаре.

**Требование:** сохранить полное неизменяемое содержание каждой несовместимой версии как свидетельство, не заменяя уже сохранённый оригинал и не применяя конфликтующую запись. Диагностика должна охватывать все затронутые рейсы; отдельный посторонний рейс не меняется. Это исполнение сохранности из задания I1, не новая политика победителя.

### C2. Одно событие скрывает явно неполную историю

`route_core.py:251`: признак `history_complete=False` учитывается только при `len(trip_events)>1`. При единственном D:P2 или O:P3 результат — `resolved`, пустая диагностика и ненулевой `notification_key`.

Одно известное событие не доказывает отсутствие неизвестного причинно последующего события. Честный признак неполноты передан на вход, но ядро его теряет. Это противоречит §3 задания и пункту 3 CONVERGENCE.

**Требование:** при таком входе выдавать явную неполноту без окончательного победителя и без ключа нового маршрутного уведомления. Проверить ноль, одно и несколько известных событий; после поступления полной истории результат должен пересчитываться. Не превращать это внутреннее состояние в блокирующую очередь для сотрудника. Разрешение обходить неполноту по одному новому событию потребовало бы отдельного доказанного основания; количество записей таким основанием не является.

Собственный адресный probe воспроизвёл **3/3 нарушения ожиданий**: C1, C1 для другого рейса и C2; exit=1 ожидаем для проверенного I1. Это отдельная приёмка, не падение исходных 22 тестов.

## 3. Уточнение сходимости и журнала

### C3. Направление сходится; весь аудит сейчас не сходится

Два одинаковых бизнес-события D:P2 с `received_at=10:01` и `10:03` в обратных порядках дают одно направление P2, но разное `history[0].received_at`: сохраняется первое предъявленное значение. `duplicate_count` тоже зависит от числа доставок, а запись принятого оригинала при несовместимых ID — от реальной истории приёма. Эти значения нельзя незаметно включать в обещание одинаковой полной проекции.

Для R1 явно определить сравниваемую бизнес-проекцию (решение, точка/событие, причинные максимумы, устойчивые основания и допустимость текущего уведомления при одинаковом lifecycle). Историю приёма и несовместимых предъявлений хранить отдельно, без участия в выборе направления. Не переименовывать первое предъявленное `received_at` в доказанное первое получение сервером. Допустим и вариант устойчивого сохранения всех наблюдений приёма с явной идентичностью; выбирать бизнес-победителя по ним нельзя. Тест должен отдельно проверить сходимость бизнес-результата и честность аудита.

### C4. Runner подтверждает тесты, но не весь обещанный контроль

- `trace()` печатает в sys.stdout; Tee подключён только к unittest stream. Поэтому опубликованный raw содержит 22 результата, но не строки `P28_I1_TRACE`. Собственный захват stdout их содержит. Полный stdout/stderr нужно сохранять в новом журнале R1.
- `run.ps1` использует только `git diff --name-only`: staged-изменения и чужие untracked этим не проверяются. README обещает более строгую проверку. Это установлено чтением скрипта; исполнение PowerShell — NOT_RUN. Исправить gate под заявленную область и указать фактический HEAD вместе с требуемой базой, не только константу базы.
- Новый запуск должен писать в отдельный явно заданный файл и сохранять исходное доказательство I1. Обновлённый manifest считать по опубликованным байтам. Не переписывать старый raw как будто это тот же запуск.
