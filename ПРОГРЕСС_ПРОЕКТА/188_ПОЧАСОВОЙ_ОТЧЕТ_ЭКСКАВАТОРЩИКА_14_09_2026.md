# Почасовой отчёт Экскаваторщика — 14.09.2026

## Решение

Существующий круг выполнения плана на экране «Работа» стал единственной точкой
входа в почасовой отчёт. По нажатию открывается нижний мобильный лист с двумя
самостоятельными блоками: сверху текущий календарный час, снизу предыдущий.
В каждом блоке одна строка на точку и три столбца: «Куда отправлены», «БелАЗ»,
«NHL»; собственные итоги находятся в нижней строке этого же блока.

Отчёт отвечает на вопрос: «на какую точку Экскаваторщик отправил самосвал →
какой это тип → сколько отправок было в каждом из двух часов».

- время события: каноническое `Trip.loaded_at`;
- принадлежность: `Trip.excavator`, без ограничения текущей сменой машиниста;
- точка отправки: неизменяемое `Trip.assigned_dump_point`;
- последующая `actual_dump_point` Водителя группировку не меняет;
- старый рейс без `assigned_dump_point` попадает в «Точка не определена», потому
  что исходное назначение достоверно восстановить из изменяемого `dump_point` нельзя;
- тип берётся из активных серверных групп техники `belaz_trucks` и `nhl_trucks`,
  а не угадывается по модели или гаражному номеру; неизвестный или конфликтный
  тип отмечается как неполнота данных и не подменяется БелАЗ/NHL;
- отменённые рейсы исключаются, остальные состояния учитываются один раз.

Интервалы полуоткрытые: предыдущий `[начало прошлого часа; начало текущего)`,
текущий `[начало текущего часа; момент единственного серверного снимка)`. Поэтому
рейс ровно на границе часа не учитывается дважды.

## Надёжность

Отчёт использует отдельный защищённый GET без изменений данных. На клиенте есть
один выполняющийся запрос, объединение сигналов, защита поколения ответа, отмена
запроса и таймеров при закрытии. Открытое окно не уничтожается заменой рабочей
оболочки. Последний успешный ответ хранится локально; без связи он показывается с
явной отметкой времени, а несинхронизированные погрузки не выдаются за серверные.

Android Back реализован через историю WebView, поэтому новая версия APK не нужна.

## Публикация

Выпуск опубликован на `driverform.ru` как оболочка Экскаваторщика `v236`,
production marker `3907bc17b50f8d4b7331048a9ce4e672e156694d`. Сохранены уже
работавшие общий static release `v159` и оболочка Диспетчера `v105`.

В тот же выпуск вошло узкое исправление нативного указателя версии APK. После
замены operational fragment новый HTML мог прийти без версии в User-Agent и
скрыть кнопку обновления; теперь Android-мост сразу восстанавливает номер и
состояние кнопки на новом shell. Чтобы уже открытый экран загрузил новый
страничный JavaScript, приложение нужно один раз полностью закрыть и открыть;
обновление APK, очистка данных и кэша не требуются.

Перед выкладкой создана резервная копия кода и PostgreSQL, а также исполняемая
точка отката:
`/srv/accounting-mvp/backups/code/excavator-hourly-v236-before-20260914T005820Z`.
После deploy прошли `manage.py check`, no-op migration check, `collectstatic`,
restart, `nginx -t`, публичные проверки SW/CSS/JS и read-only построение schema v2
на текущих production-данных. За пять минут три клиента выполнили 20 fragment-
запросов, максимум 4 запроса одного клиента в минуту; все ответы `200`, потока нет.

## Срочный hotfix v237

центрируются без влияния глобальных стилей кнопок, крестик закрытия строится двумя
симметричными линиями, ТЕСТ-1 определяется как БелАЗ по фактическим типу и модели
техники, а пустой столбец NHL скрывается отдельно для каждого часового блока.

Hotfix `b4f39c48` опубликован поверх фактического production `ready-core-traffic-v164`
с сохранением Диспетчера `v110`; оболочка Экскаваторщика повышена до `v237`.

0 NHL и 0 рейсов с неопределённым типом. Миграций и изменений данных не было.
