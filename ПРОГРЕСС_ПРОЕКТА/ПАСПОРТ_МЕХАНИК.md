# Паспорт механик полевых приложений

Версия: **0.1 — оглавление и разметка** (27.09.2026).
Ведут: Claude «Паспорт механик» (раздел «как должно быть») и Codex «Актуализировать паспорта механики» (раздел «как есть»). Правят этот файл напрямую, ветка `docs/mechanics-passport`.
Утверждает: владелец. Пока механика не отмечена «УТВЕРЖДЕНО», это черновик.

## 0. Как устроен паспорт

**Иерархия.** Правила владельца от 26.09.2026 (OWN-1…OWN-8) → решения владельца из раздела R этого файла → правила `CR-*` из `191_ЕДИНЫЙ_КОНТРАКТ_РОЛЕВЫХ_ПРИЛОЖЕНИЙ.md` v1.0 → журнал решений → остальные документы.

**Связь с 191.** 191 — свод правил сервера (`CR-*`). Паспорт не пересказывает эти правила, а ссылается на их номера. Паспорт добавляет то, чего в 191 нет: что делает телефон сразу и без связи, что главнее на экране, что видит пульт, а также приёмочные проверки. Если паспорт и 191 расходятся, это ошибка: правится 191, в журнале редакций 191 указывается ссылка на паспорт.

**Проверки.** Номера из чек-листа 205 (`ПАСПОРТ_МЕХАНИК_ЧЕКЛИСТ_205_2026_09_27.md`): A-xx водитель, B-xx машинист, C-xx межролевые, D-xx офлайн и часы, E-xx смены, F-xx пульт. Тег приёмки: `[стенд]` — стенд на PostgreSQL, `[телефон]` — реальный телефон в фокусе с фоновой нагрузкой других машин, `[лог]` — сверка по logcat (`Capacitor/Console`, `driver-outbox`) и по базе.

### Форма одной механики

```
### M-xx · Название
Статус: ЧЕРНОВИК | НА КРИТИКЕ | УТВЕРЖДЕНО        Реализация: …
Источник правды: …
Телефон сразу (в т.ч. без связи): …
Экран — что главнее: локальная очередь / снимок сервера, когда и почему
Сервер: … (правила CR-*)
Расхождения — как решает сервер, без отказа работнику: …
Где сервер сейчас может отказать → чем заменить: …
Пульт видит: …
Приёмка: [стенд] … [телефон] … [лог] …
Как есть (Codex): …
Открытые вопросы: → R-xx
```
