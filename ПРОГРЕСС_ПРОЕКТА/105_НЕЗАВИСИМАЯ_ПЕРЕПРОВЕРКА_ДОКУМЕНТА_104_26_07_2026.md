## 3. QA-CHAOS-P1-P09-012-R1

Название: version-contract не блокирует изменяющий drag-and-drop Расстановки.

Приоритет: `P1`.

### 3.1. Фактический результат

В `templates/base.html` общий guard:

- распознает POST-формы, кнопки, отдельные input и специальные data-атрибуты;
- слушает только `submit`, `click`, `pointerdown`, `touchstart`, `keydown`;
- не слушает `dragstart`, `dragover` и `drop`;
- не предоставляет обязательный mutation-check для прямого `fetch`.

В `static/js/deputy-mining-manager-v3.js`:

- `planEditable()` проверяет только состояние плана и наличие endpoint;
- карточка сотрудника становится `draggable`;
- обработчик `drop` вызывает `saveSlot()`;
- `saveSlot()` вызывает `postJson()`;
- `postJson()` отправляет изменяющий POST;
- ни один из этих путей не проверяет `AppPwaContractGuard.getState().locked`.

Точная исполняемая статическая проба текущих локальных рабочих файлов продукта:

```text
guardEvents:
["submit", "click", "pointerdown", "touchstart", "keydown"]

hasDropGuard=false
hasDnDDrop=true
planChecksContract=false
postChecksContract=false
bypassDetected=true
PROBE_EXIT=3
```

Это означает: при несовпадении HTML/JavaScript/service worker экран показывает
`locked=true`, но назначение сотрудника перетаскиванием может дойти до сервера.
Серверный endpoint не требует заголовок текущего app-contract и поэтому не
является вторым барьером этого сценария.

### 3.2. Неточный cache-key Заместителя

В `assignments/deputy_views.py` функция `canonicalStaticRequest()` строит ключ
только из:

```text
origin + pathname
```

Query-string удаляется. При сетевой ошибке URL новой статики с новым
cache-buster может получить ответ, сохраненный под тем же pathname.

Это функционально повторяет опасное свойство `ignoreSearch` и противоречит
строкам 93–95 документа 104 о точном cache-key.

### 3.3. Требуемый результат

1. Любой изменяющий путь проверяет contract непосредственно перед mutation.
2. При `locked=true` запрещены:
   - `dragstart`;
   - `drop`;
   - `saveSlot`;
   - публикация плана;
   - очистка ячейки;
   - временный перевод;
   - любой прямой POST/fetch.
3. Заблокированный drag-and-drop:
   - не меняет локальный state;
   - не показывает ложное `Сохранено`;
   - не отправляет запрос;
   - не меняет план и его версию на сервере.
4. Cache-key сохраняет query-string либо включает эквивалентную точную версию
   ресурса; новый cache-buster не получает старый файл.
5. Безопасные live-обновления и просмотр остаются доступными.
6. Открытый рейс и незавершенные серверные факты не удаляются.
7. Один contract вызывает не более одного контролируемого reload.

### 3.4. Обязательные регрессии

- locked drag source не становится активным;
- искусственный `drop` при `locked=true` дает `fetch count = 0`;
- `saveSlot()` и общий `postJson()` повторно проверяют contract;
- unlocked drag-and-drop сохраняет назначение ровно один раз;
- старый worker/JavaScript + новый HTML;
- сетевой отказ при URL с новым cache-buster;
- два последовательных release без reload-loop;
- cache-prefix другой роли не очищается;
- экран сохраняет безопасный read-only и live-обновления.

## 6. QA-REG-P2-002

Название: мобильная форма входа смещается после autofocus.

Приоритет: `P2`.

### 6.1. Фактический Browser QA

Сервер запускался только `START_SERVER_MVP.bat` и остановлен только
`STOP_SERVER_MVP.bat`.

На desktop `1280×720` десять доступных origin прошли:

```text
10/10 contract = pwa-contract-v1
10/10 shell = ожидаемая версия
10/10 ready = true
10/10 locked = false
10/10 form внутри viewport
10/10 ошибок консоли = 0
```

`admin.localhost` не проверялся живым браузером: он запрещен политикой текущей
браузерной сессии. Этот запрет не обходился. Автоматическая contract-матрица
всех 11 ролей, включая Администратора, прошла.

На mobile `390×844` contract согласован у всех десяти доступных origin, ошибок
консоли нет и body-level horizontal overflow отсутствует. Однако после
естественного autofocus внутренний контейнер сам прокручивается по горизонтали:

| Origin | `main.scrollLeft` | `main scroll/client` | Форма |
|---|---:|---:|---|
| `excavator.localhost` | `44` | `407 / 358` | `left=-2`, обрезана |
| `deputy.localhost` | `88,8` | `710 / 358` | `left=-46,8`, обрезана |
| `oup.localhost` | `88,8` | `524 / 358` | `left=-46,8`, обрезана |
| `mechanic.localhost` | `22,4` | `386 / 358` | внутри viewport, но есть внутренний overflow |

На трех первых экранах визуально обрезаются заголовок, подписи и левая часть
полей. Проверка только `documentElement.scrollWidth` этого не замечает, потому
что переполнение скрыто внутри `main`.

### 6.2. Подтвержденная причина

- поле телефона имеет `autofocus`;
- обработчик focus включает `is-login-keyboard-active`;
- в этом режиме заголовок получает `white-space: nowrap`;
- `scrollIntoView({inline: "nearest"})` горизонтально прокручивает внутренний
  grid к полю;
- длинное название роли расширяет внутреннюю область и сдвигает всю форму.

### 6.3. Требуемый результат

1. После естественного autofocus при `390×844`:
   - `main.scrollLeft = 0`;
   - `main.scrollWidth <= main.clientWidth`;
   - заголовок и форма полностью внутри viewport.
2. Длинные названия ролей переносятся или безопасно уменьшаются.
3. Открытие клавиатуры не сдвигает карточку по горизонтали.
4. Проверить все 11 origin, включая повтор после 350 мс и после focus/blur обоих
   полей.
5. Desktop `1280×720` не регрессирует.

этапа документа 104. Без сохраненного журнала команд нельзя формально

воспроизвела еще одну пару; она точно атрибутирована текущему полному прогону и
удалена после фиксации доказательства. Более ранние файлы не удалялись.

1. Все private ImageField портала в тестах используют отдельный

3. Временный каталог удаляется через cleanup даже при падении теста.
4. Список, размеры и SHA рабочего `private_media` до/после:
   - `manage.py test portal`;
