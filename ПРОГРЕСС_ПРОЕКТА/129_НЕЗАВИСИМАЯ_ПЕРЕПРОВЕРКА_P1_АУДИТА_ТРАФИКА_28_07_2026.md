## 8. Новые и остаточные карточки

### QA-TRAFFIC-P1-002-R1 — снятый с расстановки сотрудник не получает событие

Статус: **ВОСПРОИЗВЕДЕНО / P1**.

Причина:

- закрываемые старые назначения уже известны в
  `assignments/services.py:438–455`;
- event payload в `assignments/services.py:503–515` получает только
  `target_employee_ids` нового плана и всю технику плана;
- после закрытия старого назначения
  `core/realtime.py:93–129` уже не находит технику снятого сотрудника;
- `core/realtime.py:169–178` считает событие нерелевантным;
- клиент продвигает cursor без обновления экрана.

Изолированное воспроизведение:

```text
removed_worker_relevant:   False
unchanged_worker_relevant: True
```

Это обратный ожидаемому результат.

Требуется:

1. передавать в `employee_ids` объединение сотрудников реально
   закрытых и реально созданных назначений;
2. передавать в `equipment_ids` только технику реально изменившихся
   слотов, а не всю технику опубликованного плана;
3. добавить серверную регрессию через настоящий `/realtime/state/`:
   снятый сотрудник получает событие, новый получает событие,
   неизменённый сотрудник не получает событие;
4. выполнить Browser QA без reload для снятого Водителя и Машиниста.

### QA-TRAFFIC-P1-002-R2 — релевантное событие всё ещё загружает полный HTML

Статус: **ВОСПРОИЗВЕДЕНО / ОСТАТОК ИСХОДНОЙ P1**.

Требуется:

1. для связанных изменений передавать достаточную JSON-дельту либо
   получать узкий серверный фрагмент;
2. не загружать полный рабочий HTML для обычного связанного события;
3. сохранить защиту несохранённых форм, удержаний и модальных окон;
4. подтвердить на сменном event-профиле сокращение количества и байтов
   полных HTML GET минимум на `80%`;
5. проверить Водителя, Машиниста, Диспетчера и Горного мастера.

Приёмочный сетевой критерий:

- нерелевантный экран — `0` HTML/fragment GET;
- релевантный экран — только JSON-дельта или узкий фрагмент;
- неизменённые соседние сотрудники — `0` HTML/fragment GET;
- актуальность экрана сохраняется без ручного reload.

### QA-TRAFFIC-P1-005-R1 — аварийный process-local fallback допускает overlap

Статус: **ВОСПРОИЗВЕДЕНО / P1 АВАРИЙНОГО ПУТИ**.

Причина:

- `_acquire_reconcile_process_gate()` в
  `assignments/services.py:900–908` удерживает lock только на время
  проверки таймера;
- при I/O-сбое `_acquire_reconcile_server_gate()` возвращает
  `RECONCILE_PROCESS_ONLY`;
- если первая сверка выполняется дольше интервала, второй поток проходит
  таймер и начинает сверку параллельно.

Исполняемое воспроизведение с имитацией недоступного файлового lock:

```text
max_parallel_reconciles: 2
overlap: True
```

Требуется:

1. добавить отдельный неблокирующий execution-lock или running-флаг на
   всё выполнение process-local fallback;
2. освобождать его в `finally` на успешном и аварийном пути;
3. регрессия должна запустить два потока так, чтобы интервал истёк до
   завершения первой медленной сверки;
4. ожидаемый `max_parallel_reconciles = 1`;
5. сохранить отсутствие HTTP 500 при файловом I/O-сбое.

### QA-TRAFFIC-REG-P2-001 — измеритель считает старую секундную частоту

Статус: **ВОСПРОИЗВЕДЕНО / TEST TOOLING**.

`tools/full_pwa_traffic_audit.py:574–593` умножает каждую realtime-сессию
на все секунды 12-часовой смены и не учитывает интервалы `5/15 с`.

Поэтому новый независимый запуск инструмента снова вывел:

```text
realtime_requests_per_12h_shift = 2 808 000
```

Требуется:

- извлекать фактический интервал роли из контрактного HTML/конфигурации
  или хранить его в явной структуре `RoleTarget`;
- считать Водителя, Машиниста, Диспетчера и Горного мастера по `5 с`,
  Системного администратора и Руководителя по `15 с`;
- отдельно учитывать паузу скрытого окна только как дополнительную
  экономию, не как гарантированную базу;
- ожидаемый новый расчёт активных окон — `550 080`;
- обновить поля прогнозируемых байтов тем же интервалом.

### QA-TRAFFIC-DOC-P2-002 — уточнить доказательства документа 128

Статус: **ДОКУМЕНТАЦИЯ / TEST COVERAGE**.

Требуется исправить формулировки:

- subprocess/spawn-тест подменяет доменную сверку записью PID, поэтому
  доказывает межпроцессный lock, но не фактическое выполнение всей
  доменной сверки;
- текущий reconcile-путь блокирует строки `HaulAssignment`; заявление
  об отдельных `Equipment/Employee/Trip locks` для этого пути
  завышено;
- либо добавить настоящий PostgreSQL multiprocess domain-тест, либо
  честно сузить формулировку отчёта.
