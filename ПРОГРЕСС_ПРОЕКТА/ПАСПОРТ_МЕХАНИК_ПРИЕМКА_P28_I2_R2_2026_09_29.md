## 2. Закрытый дефект

Конфликты выбираются дополнительно через `existing_event_id` из уже доказанно собранного набора receipts. Поэтому исходная запись с `trip_id=NULL`, связанная с X через `(actor, device, local_trip_id)`, переносит свой конфликт на X. Предъявленный несовместимый повтор с Y сохраняется для Y; обе стороны видят исходный и предъявленный конверты.

Фильтры автора/устройства и правило неоднозначной локальной привязки не ослаблены. Объединение по PK не дублирует одну запись конфликта, основание её включения сохраняется. В R2 не меняются другие правила адаптера; прежние тесты сохранены, добавлены две отрицательные регрессии.

Неизменный приёмочный probe Астры подтвердил через реальные HTTP handlers:

- X и Y: `integrity_conflict`, по одному сохранённому conflict source;
- исходный и предъявленный конверты доступны полностью;
- нет выбранного маршрутного победителя и ключа озвучки;
- независимый Z не изменён;
- при чтении — 0 DML.

Принятая локальная привязка в этом probe — явная DB fixture, как и в прежней приёмке; весь пользовательский поток погрузки на телефоне этим не имитируется. Отрицательные тесты с чужим автором/устройством и неоднозначной связью проходят. I2-C1/C2, включая оставшееся сочетание R1, закрыты; ранее принятый I2-C3 сохраняет свою границу.

### Оговорка запуска с кириллицей

При стандартном `core.quotePath=true` runner до тестов ошибочно сравнивает экранированные Git-пути с неэкранированными ожидаемыми именами. Сохранён первоначальный отказ. Для воспроизведения задан **только параметр вывода Git `core.quotePath=false` в окружении процесса**; исходный runner, кандидат и ожидания не менялись. После этого полный прогон и clean/dirty gate прошли.

Это документированное условие запуска проверочного инструмента; оно не скрывает изменения списка файлов или содержимого. [Точная команда и журналы](ДОКАЗАТЕЛЬСТВА_ПРИЕМКИ_P28_I2_R2_2026_09_29/README.md) позволяют повторить результат без ручной правки probes. Новая доработка адаптера из-за этой настройки не назначается.

## 4. Что означает приёмка

Принят **читающий адаптер реальных legacy-свидетельств с явной неполнотой**, отдельно от приложения. `history_complete=False`, причины `dedicated_route_event_journal_absent` и `ui_observation_not_recorded` остаются правильными. Старые данные не достраиваются до выдуманной полной истории; отсутствие доказательства не назначает победителя.

Это не разрешение рабочего подключения, merge или deploy и не объявление жалобы о перенаправлении после пяти минут исправленной. PostgreSQL, конкурентная запись, DOM, телефон, native audio и production — **NOT_RUN**. Кандидат и результаты SQLite не заменяют будущую проверку записи нового журнала и интеграции интерфейса.
