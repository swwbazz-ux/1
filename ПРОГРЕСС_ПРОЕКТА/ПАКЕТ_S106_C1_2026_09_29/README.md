# Исполняемый пакет S106-C1

Пакет фиксирует различия повторной обработки между:

- release `8c215ae2a45196e3e74e566c54f2ab5cb321be02`;
- PR №106 `17cbb3e913dfdc98aaa9585ba4090d0f4cf17ee0`;
- общей базой `d208b84db920aa98ec80612645dac3996c61f76c`.

Release сдвинулся с проверявшегося в постановке `5721c045…` на `8c215ae2…`
коммитом диспетчерского экрана №132. Blobs семи проверяемых offline/queue файлов
не изменились; весь runner всё равно повторно исполнен на новом полном SHA.

Это тестовый и документационный пакет. Он не меняет рабочие обработчики, модели,
миграции, версии оболочек или общие ветки. Временные worktree создаются под
`%TEMP%` и удаляются в `finally`.

## Запуск

Из корня репозитория:

```powershell
$python = (Resolve-Path '.\СИСТЕМА_MVP\.venv\Scripts\python.exe').Path
& '.\ПРОГРЕСС_ПРОЕКТА\ПАКЕТ_S106_C1_2026_09_29\run_s106_c1.ps1' `
  -RepoRoot (Get-Location).Path `
  -PythonExe $python
```

Требуются локальные git-объекты обоих полных SHA. Runner сам проверяет их,
проверяет merge-base, создаёт изолированные SQLite test DB и сохраняет UTF-8
stdout/stderr и коды завершения в `results/`.

## Ожидаемые результаты

`run_s106_c1.ps1` завершается кодом `0`, но внутри намеренно сохраняет четыре
ненулевых результата:

- `merge-probe`: `1`, потому что фактическое пробное слияние имеет три
  текстовых конфликта;
- `release-target-contract-known-gap`: `1`, три из пяти целевых проверок
  воспроизводят пробелы release;
- `pr106-unchanged-release-django-tests-known-incompatible`: `1`, два
  неизменённых release-теста не могут импортировать отсутствующий в PR helper;
- `pr106-unchanged-release-js-test-known-gap`: `1`, PR отправляет только
  зависимое завершение, но не отклонённую корневую погрузку.

Все четыре кода явно перечислены как ожидаемые в runner. Они не превращаются в
ложный PASS.

## Состав

- `contract_cases.json` — общий машинно-читаемый проект контракта, статус
  `PROPOSED_NOT_APPROVED`;
- `verify_contract_cases.py` — полнота девяти групп и 32 ролевых пар PR;
- `probe_client_recovery.cjs` — настоящий Driver/Excavator runtime с MOCK
  transport;
- `test_s106_c1_probe.py` — пять одинаковых Django-проверок для обоих SHA;
- `prepare_pr106_test_overlay.py` — перенос трёх release-регрессий только во
  временный тестовый overlay PR;
- `run_s106_c1.ps1` — полный воспроизводимый прогон;
- `results/` — сырые журналы последнего прогона;
- `SHA256SUMS.txt` — manifest опубликованных байтов пакета.

## Границы доказательства

SQLite подтверждает последовательную доменную обработку, но не PostgreSQL-
конкурентность. JS probes исполняют реальный код очередей, однако transport в
них MOCK: настоящая HTTP-доставка, DOM/WebView, установленное приложение,
телефон и production — `NOT_RUN`. Пробное слияние не создаёт merge-коммит.
