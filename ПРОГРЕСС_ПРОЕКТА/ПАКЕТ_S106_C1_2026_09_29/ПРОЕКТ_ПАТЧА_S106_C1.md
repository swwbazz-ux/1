## 1. Одна серверная точка решения

В `core/offline_sync.py` предлагается заменить две несогласованные булевы
ветви одной чистой функцией, которая не смешивает допуск повторной обработки с
выбором времени:

```python
@dataclass(frozen=True)
class StoredReplayDecision:
    allowed: bool
    reason: str
    time_policy: Literal['raw_device', 'first_received']
    dependency_policy: Literal['normal', 'advisory_own_refs']


def decide_stored_event_replay(existing, normalized, access):
    # same actor/access/role/device/fingerprint проверены до вызова
    if own_clock_is_invalid(existing):
        return StoredReplayDecision(
            True, 'own_clock_repair', 'first_received', 'normal'
        )
    if exact_pair(existing, 'driver.trip.loaded', 'free_bucket_not_available'):
        return StoredReplayDecision(
            True, 'cancelled_free_bucket_factual_load', 'raw_device', 'normal'
        )
    if existing.error_code in LEGACY_DEPENDENCY_CODES:
        return StoredReplayDecision(
            True, 'legacy_dependency_reevaluation',
            'raw_device', 'advisory_own_refs',
        )
    if exact_worker_truth_pair(existing):
        return StoredReplayDecision(
            True, 'worker_truth_reevaluation', 'raw_device', 'normal'
        )
    return StoredReplayDecision(False, 'stored_terminal', 'raw_device', 'normal')
```

Минимальное применение в `process_one_offline_event`:

```diff
- recoverable_clock_conflict = ...
- recoverable_worker_truth_conflict = ...
- clock_adjusted = recoverable_conflict
+ decision = decide_stored_event_replay(existing, normalized, access)
+ if existing.status != RETRY and not decision.allowed:
+     return _stored_result(existing, deduplicated=True)
+ normalized['device_occurred_at'] = existing.occurred_at
+ normalized['received_at'] = existing.received_at
+ normalized['clock_adjusted'] = decision.time_policy == 'first_received'
+ normalized['occurred_at'] = (
+     existing.received_at
+     if decision.time_policy == 'first_received'
+     else existing.occurred_at
+ )
+ normalized['dependency_policy'] = decision.dependency_policy
```

`first_received` применяется только к событию, чьи **собственные** часы
доказанно недостоверны. Невалидное время родителя не переписывает честное время
ребёнка.

## 2. Зависимость не даёт полномочий и ID

При `advisory_own_refs` `_dependency_state` журналирует отсутствующего,
отказанного, чужого либо пришедшего не по sequence предка, но не берёт из него
`trip_id`, `acceptance_id` или полномочия. Обработчик ребёнка обязан:

1. разрешить собственные `trip_id/local_trip_id/downtime/free-bucket` ссылки;
2. применить обычные проверки роли, объекта, хронологии и идемпотентности;
3. вернуть `retry` своего предметного типа (`trip_reference_pending` и т.п.),
   если собственных доказательств пока не хватает;
4. не превращать `dependency_*` в автоматический `accepted/no_effect`.

Это сохраняет независимость достоверного ребёнка и одновременно не позволяет
чужому предку передать ему объект или полномочие.

## 3. Полный путь свободного ковша обязателен

Одного replay-helper недостаточно. При интеграции PR №106 надо сохранить
релизные функции:

- `_revive_cancelled_free_bucket_by_driver_load`;
- `_accept_free_bucket_by_driver_action`;
- блокировку/проверку другого живого `REQUESTED/ACCEPTED/USED` права;
- фактическую погрузку, её идемпотентный action и дальнейший зависимый complete.

То есть корневое `driver.trip.loaded/free_bucket_not_available` сначала
повторяется тем же конвертом, под блокировкой восстанавливает или самостоятельно
принимает именно своё право и проходит обычный handler. Только после устойчивого
`accepted/no_effect` корня может быть повторён зависимый complete. Отправить один
complete, оставив погрузку terminal, недостаточно.

## 4. Клиентский планировщик

Клиент не решает доменный исход. Он лишь повторяет неизменяемый конверт и
использует четыре транспортных состояния зависимости:

1. родитель есть и сам recoverable — отправить его, затем ребёнка;
2. родитель подтверждён `accepted/no_effect` и удалён — разрешить ребёнку один
   probe;
3. родитель отсутствует — разрешить один server probe ребёнка;
4. родитель terminal и несовместим — self-contained ребёнок может быть
   отправлен, но его handler использует только собственные ссылки; ребёнок без
   своих ссылок остаётся серверным `retry`, а не бесконечной клиентской петлёй.

Матрица event/code должна генерироваться или проверяться по
`contract_cases.json` для обеих ролей. Это не означает механического равенства
списков: сервер повторно проверяет данные, клиент только планирует доставку.
