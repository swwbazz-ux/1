# Production deploy каталога готовых PWA

Дата: 23.08.2026 (Владивосток).

## Итог

Публичный каталог восьми готовых рабочих PWA опубликован на боевом сервере и
доступен по адресу `https://driverform.ru/apps/`.

Кодовый commit:
`b79c23d794bc5407c7c8f1924ab3349a7b79d4bb` (`feat(pwa): add public app catalog`).
Ветка: `codex/pwa-app-catalog-2026-08-23`. Локальный и удалённый SHA перед
deploy совпадали.

Архив собран непосредственно из commit. SHA-256 архива:
`2668CE5C710680F5512CCFF8113DD19B072E3F3D7A6D17DB324B28EBA1C8BCB2`.
Сервер до распаковки подтвердил SHA и строгий allowlist из десяти обычных
файлов без ссылок и небезопасных путей.

Модели, миграции, `.env`, nginx-конфигурация, systemd unit, рабочие данные и
справочники не менялись. `migrate` не выполнялся: до и после выпуска план
содержал `No planned migration operations`.

## Резервная копия и откат

До замены создан комплект:

`/srv/accounting-mvp/backups/deploy-20260822T225958Z-pwa-catalog-before-b79c23d`

В нём находятся:

- исходные четыре существовавших production-файла с SHA-256;
- перечень десяти отсутствовавших до выпуска source/staticfiles-целей;
- текстовый план отката;
- исполняемый `rollback.sh`.

Откат восстанавливает четыре прежних файла, удаляет только новые файлы
каталога и их собранные static-копии, повторно запускает `check` и
`collectstatic`, перезапускает `accounting-mvp` и проверяет nginx. Откат базы
не требуется, потому что схема и данные не изменялись.

## Серверные проверки

- `manage.py check`: без ошибок;
- миграционный план: пуст;
- `collectstatic --noinput`: скопированы ровно четыре новых static-файла,
  остальные 265 не изменены;
- SHA source и собранных static-файлов совпали;
- `accounting-mvp`: `active/running`, `NRestarts=0`, `ExecMainStatus=0`;
- `nginx -t`: успешно;
- за десять минут после выпуска в журнале приложения нет `Traceback`,
  `Critical`, `Internal Server Error` или `Exception`.

## Публичная проверка

- `https://driverform.ru/apps/`: HTTP 200, ровно восемь карточек;
- восемь разрешённых QR endpoint: HTTP 200, `image/svg+xml`;
- QR для Делопроизводителя, Механика, Табельщика и Начальника участка: HTTP
  404;
- `/apps/` на каждом из восьми ролевых поддоменов: HTTP 302 на общий каталог;
- корень и manifest каждого из восьми приложений: HTTP 200;
- четыре новых публичных CSS/JS-файла: HTTP 200;
- ролевой вход Диспетчера содержит кнопку установки, правильный manifest и
  ссылку назад в каталог.

Production Browser QA `1280×720` подтвердил сетку `4 × 2`, восемь одинаковых
карточек `283 × 239`, отсутствие горизонтального overflow и manifest у самого
каталога. Центральное окно Диспетчера открылось с правильной прямой ссылкой и
полностью загруженным SVG QR `256 × 256`. Ошибок консоли нет. Локальная
предрелизная Browser QA того же commit дополнительно пройдена на `768×1024` и
`390×844`; опубликованный runtime взят из этого точного commit.

## Следующий шаг

В офисе открыть `https://driverform.ru/apps/` на компьютере и телефоне, затем
последовательно установить и запустить восемь PWA. После этого провести
сквозной smoke Диспетчера вместе с Машинистом экскаватора, Водителем самосвала
и Горным мастером до начала карьерного пилота.
