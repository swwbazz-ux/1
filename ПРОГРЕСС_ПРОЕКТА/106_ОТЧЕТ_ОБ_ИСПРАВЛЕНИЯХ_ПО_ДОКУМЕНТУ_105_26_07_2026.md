## 2. QA-CHAOS-P1-P09-012-R1

### 2.1. Воспроизведение

До исправления новый исполняемый JavaScript-набор подтвердил три нарушения:

- карточка сотрудника при `locked=true` оставалась доступной для drag;
- прямые пути `saveSlot()` и `postJson()` могли дойти до `fetch`;
- новый URL статики с другим query-string при сетевом отказе получал старую
  запись path-only cache.

Результат красного прогона:

```text
3 FAIL
1 PASS
```

### 2.2. Причина

`static/js/deputy-mining-manager-v3.js` определял редактируемость только по
состоянию плана и endpoint. Обработчики `dragstart`, `drop`, `saveSlot()`,
публикации, очистки и временного перевода не перепроверяли
`AppPwaContractGuard.getState().locked` непосредственно перед mutation.

В service worker Заместителя `canonicalStaticRequest()` удалял query-string,
поэтому разные cache-buster URL имели один ключ.

### 2.3. Исправление

В рабочем JavaScript Расстановки:

- добавлен единый `mutationAllowed()`;
- contract и неактивная роль проверяются перед `dragstart`, `drop`,
  `saveSlot()`, `postJson()`, публикацией, очисткой ячейки и временным
  переводом;
- `postJson()` повторно проверяет contract непосредственно перед `fetch`;
- при блокировке DnD завершается, локальный план не меняется, ложное
  `Сохранено` не появляется;
- событие contract/active-role закрывает изменяющие диалоги и перерисовывает
  экран в безопасном read-only, не блокируя поиск и live-просмотр;
- после снятия lock разрешенный drop выполняет ровно один POST.

В service worker Заместителя:

- cache-key теперь содержит `pathname + search`;
- fallback выполняет точное `cache.match(request)`;
- новый query-string не получает старый файл;
- shell согласованно поднят:

```text
deputy-mining-manager-desktop-shell-v13
→ deputy-mining-manager-desktop-shell-v14
```

Версия `v14` согласована в `assignments/deputy_views.py`,
`users/role_apps.py`, ответах manifest/service worker/HTML и тестах.
Версии остальных ролей не менялись.

### 2.4. Регрессии

Новый `static/js/tests/deputy-contract-runtime.test.js` исполняет настоящий
production-обработчик Расстановки и подтверждает:

1. locked drag source имеет `draggable=false`;
2. искусственный locked `drop` дает `fetch count = 0`;
3. locked `drop` не меняет DOM/state и текст autosave;
4. `saveSlot()` и `postJson()` независимо перепроверяют contract;
5. unlocked drag-and-drop выполняет ровно один POST;
6. безопасный поиск и переход из read-only в editable сохраняются;
7. сетевой отказ для нового cache-buster не возвращает старый ресурс.

Существующий `pwa-contract-runtime.test.js` повторно подтвердил:

- старый JavaScript/service worker с новым HTML блокирует mutation;
- согласованный старый offline-shell остается читаемым;
- открытый рейс не удаляется из DOM;
- два последовательных release не создают reload-loop;
- cache-prefix другой роли не очищается.

## 3. QA-REG-P2-002

### 3.1. Воспроизведение

До исправления исполняемые проверки воспроизвели:

- после естественного autofocus `main.scrollLeft=88`;
- после focus телефона `main.scrollLeft=44`;
- длинный заголовок расширял grid и создавал внутренний overflow.

Результат красного прогона:

```text
3/3 FAIL
```

### 3.2. Причина

В режиме клавиатуры заголовок получал `white-space: nowrap`, а
`input.scrollIntoView({inline: "nearest"})` горизонтально прокручивал внутренний
контейнер. Grid-дети формы не имели полного ограничения `min-width: 0`.

### 3.3. Исправление

В мобильном login-контуре:

- dialog, form и все непосредственные grid-дети ограничены
  `min-width: 0; max-width: 100%`;
- длинный заголовок переносится через `white-space: normal` и
  `overflow-wrap: anywhere`;
- удален всенаправленный `input.scrollIntoView`;
- сохранена только необходимая вертикальная коррекция через
  `window.scrollTo({left: 0})`;
- горизонтальная позиция dialog/document сбрасывается сразу и повторно через
  350 мс;
- обработан autofocus, который браузер успел применить до
  `DOMContentLoaded`;
- focus и blur обоих полей используют один безопасный путь.

Новый исполняемый набор проверяет autofocus, focus/blur телефона и пинкода,
повтор через 350 мс и desktop:

```text
4/4 PASS
```

Новый Django-контракт подтвердил общий login-шаблон для всех 11 role-origin.
