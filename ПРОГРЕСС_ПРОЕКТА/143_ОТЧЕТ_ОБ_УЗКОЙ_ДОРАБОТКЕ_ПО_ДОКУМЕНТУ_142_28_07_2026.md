## 4. Выполненные исправления

### 4.1. QA-TRAFFIC-P2-002-R2-R1

`templates/includes/achievement_prize.html` теперь слушает фактическое событие
приложения `operational-state-connection`.

Контракт обработчика:

- восстановление запускается только при `event.detail.connected === true`;
- reconnect объединяется с уже существующим pending/in-flight/backoff;
- burst reconnect-событий не создаёт параллельные запросы;
- `connected=false` не запускает GET;
- периодический таймер достижений не добавлен.

После исчерпанных error/backoff следующий фактический reconnect выполняет ровно
один recovery GET.

Статус карточки:

```text
ГОТОВО К ПЕРЕПРОВЕРКЕ
```

### 4.2. QA-TRAFFIC-P2-002-R3

Exact-match события достижения Машиниста теперь использует только
`data-eo-current-excavator-id`, то есть технику реально открытой смены.
`data-eo-shift-excavator-id`, который может содержать лишь предварительное
назначение, больше не считается открытой сменой.

Проверено отдельно:

- exact-событие для назначенного экскаватора без открытой смены: `0 GET`;
- truncated-событие для назначенного экскаватора без открытой смены: `0 GET`;
- действующий путь открытой смены сохранён.

Статус карточки:

```text
ГОТОВО К ПЕРЕПРОВЕРКЕ
```

### 4.3. QA-TRAFFIC-P2-003-R2-R1

В `templates/base.html` введено отдельное переходное состояние
`controllerVersionPending`.

При `controllerchange` общий PWA contract guard теперь:

1. немедленно инвалидирует версию прежнего service worker;
2. переводит contract в `ready=false`, `locked=true`;
3. ждёт проверки версии именно текущего controller;
4. не снимает pending reload до получения результата;
5. при совпавшей версии возвращает `ready` без reload;
6. при несовпадении допускает не более одного безопасного reload;
7. не выполняет reload при незавершённом действии и восстанавливает путь после
   его завершения;
8. при отсутствии ответа не наследует старое `ready`.

Статус карточки:

```text
ГОТОВО К ПЕРЕПРОВЕРКЕ
```

### 4.4. QA-TRAFFIC-P2-003-R3-R1

В runtime Машиниста и Горного мастера добавлена синхронизация stale update UI.
Если показанный worker:

- больше не равен `registration.waiting`;
- уже стал `controller`;
- либо перешёл в `activated`,

то inspection generation инвалидируется, ссылка на worker очищается, modal
закрывается, badge и сохранённое состояние обновления очищаются или
пересчитываются.

Повторный `SKIP_WAITING` не отправляется.

Статус карточки:

```text
ГОТОВО К ПЕРЕПРОВЕРКЕ
```

## 15. Остаточные риски и ограничения

1. Асинхронный ответ конкретного service worker и точный момент активации другой
   вкладкой невозможно надёжно воспроизводить ручным Browser QA. Эти гонки
   доказаны исполняемыми runtime-тестами production-обработчиков.
2. PostgreSQL проверялся на изолированном переносимом PostgreSQL 16.14.
   Production не использовался.
3. Работа ограничена пятью остатками документа 142. HTTP/2, P3 и соседние
   продуктовые изменения сознательно не начинались.
