# Новая проверка простоев после восстановления workspace

Исходный код получен заново из `swwbazz-ux/1` по точному commit `ecb61af55b699a7a2417abba6df4dd490f3464a9`. Manifest содержит пути репозитория, Git blob SHA и SHA256 шести файлов. Байты проверены, лишний перевод строки транспортного копирования удалён только после доказательства совпадения исходного Git blob SHA.

Повтор: `python probe.py` из этой папки либо `python <путь>/probe.py` из любой папки. Используется стандартная библиотека Python. Скрипт сначала проверяет Git blob всех шести источников, затем извлекает неизменённый AST одной `_process_downtime` и выполняет два случая с явно заданными двойниками ORM, сменной блокировки и публикации состояния.

Получено `REPRODUCED_FUNCTION_COUNTEREXAMPLE`: исходный `ended_at=12:00` после обычного стопа 18:00 превращается в 18:00; обратное сочетание также переписывается. При этом сохранён лог `downtime_already_closed`. Функция не различает происхождение существующего окончания.

Квалификация контрпримера: старый конец достоверен и относится к тому же рабочему интервалу; входящий стоп обычный, не явно разрешённое исправление истории. Это не утверждает универсальное правило выбора минимального времени для любых коррекций.

Результат не доказывает full request, Django-транзакцию, PostgreSQL-блокировки, весь outbox, UI либо реальный телефон. Эти уровни имеют статус `NOT_RUN`. Exit 0 означает успешное воспроизведение диагностического наблюдения, не product PASS. Прежние утраченные raw-прогоны не восстановлены и в доказательства не включены.
