## 6. QA-PG-P2-003 — некорректная секция в тестовой фикстуре

Приоритет: `P2`.

Классификация: только тестовая фикстура, production-модель корректна.

Файл:

```text
СИСТЕМА_MVP/backend/trips/test_chaos_p01_shift_downtime.py
```

Причина:

- `create_driver(..., 'CHAOS-DRIVER-OLD')` формирует имя
  `Секция CHAOS-DRIVER-OLD`;
- длина имени — 23 символа;
- `DormitorySection.name` имеет утверждённый `max_length=16`;
- PostgreSQL корректно отклоняет INSERT;
- SQLite ограничение `VARCHAR(16)` не применяет.

Все 14 тестов класса падают в `setUp`, до своих бизнес-проверок.

Требуемое исправление:

- передавать в `create_driver()` отдельные короткие имена секций, например
  `QA-OLD` и `QA-NEW`;
- не строить имя секции из `access_code`;
- не увеличивать `max_length`;
- не менять модель и миграции.

Критерии приёмки:

- класс на PostgreSQL: `14/14 OK`;
- класс на SQLite: `14/14 OK`;
- полный PostgreSQL-набор не содержит этих `DataError`;
- миграционных изменений нет.

## 7. QA-PG-P2-004 — повторное закрытие streaming response

Приоритет: `P2`.

Классификация: тестовая инфраструктура; production-обработчик
`achievement_views.py` менять не требуется.

Файл:

```text
СИСТЕМА_MVP/backend/trips/tests_achievements.py
```

Причина:

- тест полностью читает `image_response.streaming_content`;
- Django TestClient после чтения уже закрывает streaming response штатным
  wrapper;
- повторный ручной `image_response.close()` снова посылает
  `request_finished`;
- при `CONN_MAX_AGE=0` PostgreSQL-соединение закрывается внутри atomic
  `TestCase`;
- следующий запрос падает с `OperationalError: the connection is closed`;
- ещё два теста получают каскад того же повреждённого class-level
  соединения.

Требуемое исправление:

- удалить прямые `image_response.close()` и `download_response.close()`;
- оба ответа полностью читать через
  `b''.join(response.streaming_content)`;
- проверить фактическое содержимое `b'prize-image'`;
- сохранить последующие `achievement_shown`, `refresh_from_db()` и повторный
  `achievement_current`.

Критерии приёмки:

- `AchievementPrizeApiTests`: `4/4 OK` на PostgreSQL;
- тот же класс: `4/4 OK` на SQLite;
- полный PostgreSQL-набор не содержит трёх `OperationalError`;
- production views, модели и миграции не меняются.

Документ 116 как исторический отчёт не переписывается. Для последующих
проверок использовать только:

```powershell
$pgRoot = 'C:\Users\swwba\AppData\Local\Temp\codex-pg16-qa-20260727-01'
& "$pgRoot\bin-dist\pgsql\bin\pg_ctl.exe" start `
  -D "$pgRoot\data" `
  -l "$pgRoot\postgres.log" `
  -o '-p 55432 -h 127.0.0.1' `
  -w
```

После запуска обязательно проверить:

```powershell
& "$pgRoot\bin-dist\pgsql\bin\pg_isready.exe" `
  -h 127.0.0.1 -p 55432 -d postgres -U qa_cluster_admin
```

Ожидается:

```text

```
