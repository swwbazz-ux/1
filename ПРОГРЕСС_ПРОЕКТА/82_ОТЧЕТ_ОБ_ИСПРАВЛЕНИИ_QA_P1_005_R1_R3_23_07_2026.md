## 5. Инструкция независимой перепроверки

### R1 — суточная сводка простоев

1. Создать простой с `started_at = 24.07.2026 01:30 Asia/Vladivostok`.
2. Открыть `/reports/downtimes/?date_from=2026-07-23&date_to=2026-07-23`.
3. Проверить один объект и дату суточной сводки `23.07.2026`.
4. Экспортировать тот же фильтр через `/reports/downtimes/export/`.
5. В блоке «Сводка по датам» проверить `23.07.2026`.
6. Убедиться, что строки `24.07.2026` в сводке нет.

### R2 — plan fallback и пустой snapshot

1. Создать ночную смену с `opened_at = 24.07.2026 01:30 Asia/Vladivostok`.
2. Оставить `plan_status` пустым и вызвать `calculate_open_shift_progress`.
3. Ожидать `date = 23.07.2026`.
4. Передать эту смену как reference shift в `calculate_truck_shift_progress`, когда у самосвала нет активной смены.
5. Ожидать `date = 23.07.2026`.
6. Вызвать `dispatcher_empty_snapshot_progress`.
7. Ожидать `date = 23.07.2026`.
8. Отдельно проверить смену с уже назначенным snapshot: его plan value и status не должны пересчитываться.

### R3 — динамика руководства

1. На одной производственной дате создать:
   - дневной рейс в 10:00, объём 11;
   - ночной рейс в 20:00, объём 22.
2. Для каждой гранулярности `hour`, `day`, `shift`, `month` выбрать `day`.
3. Ожидать: 1 рейс, объём 11, одна учтённая точка/корзина.
4. Повторить четыре гранулярности для `night`.
5. Ожидать: 1 рейс, объём 22, одна учтённая точка/корзина.
6. Проверить итоговые KPI, таблицу, точки и series графика.
7. Убедиться, что рейс противоположной смены нигде не суммируется.
