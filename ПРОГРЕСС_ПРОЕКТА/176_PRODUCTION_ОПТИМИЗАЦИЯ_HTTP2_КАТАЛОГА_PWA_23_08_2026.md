# Production-оптимизация HTTP/2 каталога PWA 23.08.2026

## 1. Основание и границы

Владелец разрешил выполнить всё необходимое для ускорения публичного каталога
`https://driverform.ru/apps/`, поскольку на реальном телефоне руководителя
страница загружалась неприемлемо долго.

Выпуск ограничен production-конфигурацией nginx. Код Django, static-файлы,
база данных, миграции, `.env`, сертификаты и рабочие данные не изменялись.

## 2. Исходное состояние

До изменения подтверждено:

- nginx `1.24.0` собран с `--with-http_v2_module`, но TLS-блок содержал только
  `listen 443 ssl` и `listen [::]:443 ssl`;
- Chrome отдавал HTML, CSS, JavaScript и изображения по `http/1.1`;
- первая загрузка содержала до 12 запросов, `65 668` байт сетевой передачи и
  `84 617` байт после распаковки;
- контрольная холодная серия имела медиану полной загрузки около `1 005 мс`,
  а повторная принудительная серия при нестабильном маршруте доходила до
  медианы `3 509 мс` и p95 `4 026 мс`;
- повторное открытие имело медиану около `381 мс`;
- сам production-сервер отвечал быстро: loopback p50 `5,0 мс`, p95 `6,4 мс`.

Причина задержки находилась не в Django и не в весе страницы, а в сетевой
очереди нескольких мелких HTTPS-запросов по HTTP/1.1.

Проверка `sha256sum -c` прошла для всех шести файлов. Исходный SHA-256
активного server block:

`3cac5d7cf96661ff21c7938623753c832466e5fb9583d2bd1aa49b0843549a97`.

## 4. Изменение

Изменены только две строки TLS-блока:

```nginx
listen 443 ssl http2;
listen [::]:443 ssl http2;
```

Итоговый SHA-256 активного файла:

`33f49d36a0addca8900a907862138bf1f06c96167864a97a4b79e95af5c21d91`.

Перед reload выполнен успешный `nginx -t`. Применён штатный
`systemctl reload nginx`, без restart приложения и без прерывания сервиса.

- TTFB p50: `112 мс`, p95: `174 мс`;
- DOMContentLoaded p50: `276 мс`, p95: `417 мс`;
- полная загрузка p50: `534 мс`, p95: `702 мс`;

- сетевой объём не изменился: `61 489–65 668` байт.

Пять повторных открытий с кешем:

Имитация мобильного канала `1,6 Мбит/с` с задержкой `150 мс`:

- три холодных открытия: `548–592 мс`;
- медиана: `579 мс`;
- протокол: `h2`.

Относительно обычной исходной холодной медианы полная загрузка ускорилась
примерно на `46,9%`. Хвост нестабильной принудительной серии сократился с p95
около `4 026 мс` до `702 мс`.

## 7. Итоговое решение

`QA-TRAFFIC-P2-004` закрыта. Каталог готов к офисному тестированию и повторной
проверке на телефоне руководителя.

WebP, Brotli, объединение файлов, service worker каталога и дополнительное
кеширование HTML сейчас не внедряются: после HTTP/2 страница стабильно
загружается быстрее одной секунды, а дальнейшая экономия не оправдывает риск и
сложность. Хешированные URL и `immutable` остаются возможной общей будущей
задачей статики, но не являются блокером каталога.

Commit и push по этой инфраструктурной операции не выполнялись. Production
изменён только в двух строках nginx; код, база, миграции, `.env`, сертификаты
и рабочие данные сохранены без изменений.
