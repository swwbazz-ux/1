## Основания для размеров

[Android Developers](https://developer.android.com/guide/topics/ui/accessibility/apps) рекомендует зоны касания от 48×48 dp; [WCAG о контрасте](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) — 4,5:1 для обычного текста и 3:1 для крупного. Это ориентиры проверки, а не заявление о соответствии текущего приложения. Нормативный веб-минимум [24×24 CSS px](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) недостаточен как проектная цель для полевой работы.

CSS px, физические пиксели снимка и Android dp не приравниваются автоматически. В макетах номера 24/30 CSS px и плитки высотой 52/64 CSS px выбраны как сравниваемые предложения. Итоговые размеры и контраст измеряются в фактически отображённом интерфейсе, а пригодность в перчатках проверяется пользователем на устройстве.

## Будущая приёмка после реализации

- Все машины и комплексы достижимы, поиск находит также скрытые/нижние элементы и не меняет назначения.
- Номера, длинные обозначения, особые состояния и реальные зоны касания проверены на планшете; нет перекрытий при клавиатуре и открытых карточках.
- Нормальный тап открывает карточку; режим перестановки показывает источник и цель, сохраняет штатные подтверждения и серверную защиту от дубля/устаревшего состояния. Бизнес-проверки выполняются согласованно, не случайными операциями в рабочей смене.
- Закрытая смена и недостаток прав объясняются; упрощение UI не обходит запреты.
- Актуальность, потеря сети и восстановление обозначены честно. Успешное локальное нажатие не приравнивается к серверному подтверждению.
- Realtime не срывает ввод, открытые формы и выбор. Не возвращается цикл повторных неизменённых DOM-записей, блокировавший запуск до 0.1.1.
- Сохраняются личный PIN, аппаратное обслуживание, подпись/package, автостарт и альбомная ориентация. Отдельную кнопку Wi-Fi не добавлять.
- Отдельная физическая проба при привычном хвате, свете и используемых перчатках; автономная перезагрузка без USB. Результат макета/браузера не объявляется полевой приёмкой.

Для Ш-01 повторно проверены `dispatcher_header.html` и `dispatcher_active_badge.html`. При открытой смене показываются фото либо инициалы, имя активного диспетчера, подпись роли и время открытия. При закрытой — заглушка аватара, «смена не открыта» и подпись роли. Активный диспетчер не обязательно совпадает с текущим пользователем планшета.

| Элемент левого блока | Предварительная важность | Предложение для обсуждения |
|---|---|---|
| Состояние смены | Высокая: объясняет доступность управления | Постоянно видимое короткое обозначение |
| ФИО ответственного диспетчера | Значимо для ответственности, частота обращения уточняется | Компактные ФИО постоянно либо подробности по нажатию «Смена» |
| Фото / инициалы в крупной плашке | Низкая для оперативной расстановки | Убрать из постоянной шапки, если пользователь согласует |
| Подпись «горный диспетчер» | Низкая как повтор роли | Убрать из постоянной шапки, если пользователь согласует |
| Время открытия смены | Полезно эпизодически | В подробности смены, если пользователь согласует |

Исходное предложение Джарвиса: компактное «Смена открыта · Фамилия И.О.» / «Смена не открыта». Пользователь уточнил его ниже; исходное предложение убрать аватар **отклонено**. Рабочий APK и макеты на этом шаге не менялись.

## Принятые решения по шапке и текущий вопрос Ш-02

Прямые указания пользователя от 31.10.2026:

| Элемент | Решение / статус |
|---|---|
| Аватар | **Оставить.** Компактный размер подобрать при раскладке, аватар не удалять |
| ФИО | **Фамилия полностью, имя и отчество инициалами:** «Иванов И.И.» |
| Подпись «Горный диспетчер» | **Убрать** из планшетной шапки |
| Кнопка дневного/ночного режима | **Убрать** из шапки. Само правило выбора оформления этим не определено; не вводить новую автоматику как уже согласованную |
| Вращающиеся часы | **Заменить компактными часами с датой**, без вращения |
| «Назад» / «Выйти» | Удаление из шапки **условно**: сначала нужен простой и понятный механизм, кто входит и начинает смену |
| Аналитика / Журнал / Отчёты | Пользователь предложил отдельный экран, например «Подробности смены», с понятными читаемыми показателями в разных разрезах. Название, состав показателей и размещение журнала/выгрузок ещё обсуждаются |
| Общий принцип | Максимально удобная работа, минимум лишних действий и повторного ввода |

Формат ФИО должен корректно работать и при отсутствии отчества. Действующий заимствованный компонент показывает ответственного общей диспетчерской смены, а не обязательно человека на планшете. ### Предложение для простого входа — ещё не согласовано

«Начать смену» → выбрать своё фото/ФИО → ввести личный код сотрудника → одна кнопка начала работы. Это требование к будущему сценарию, не существующая уже готовая функция.

Личный код сотрудника и служебный PIN планшета — разные назначения. Служебный PIN и вход по громкости «+» не меняются. Общий PIN планшета не используется для определения автора рабочих действий. Техническая возможность идентификации только по PIN без выбора сотрудника не предполагается без проверки; более однозначный вариант — фото/ФИО плюс личный код.

## Установка на планшет разрешена — требования Ш-06

Прямое указание пользователя: **«давай на планшет выкатывай, буду тестировать, только правило такое, одновременно 2 панели не может быть вытащено и если с ней не взаимодействуют некоторое время, то она обратно скрывается, заезжает»**.

- Одновременно открыта только одна панель, в том числе при переключении и анимации: предыдущая скрывается до показа следующей.
- Базовый интервал бездействия выбран Джарвисом: **10 секунд**. Пользователь точное число не задавал. Это параметр реализации, который можно изменить по полевой пробе.
- Касания, прокрутка и ввод в открытой панели обновляют таймер. Автоскрытие приостанавливается во время активного жеста, фокуса редактируемого поля, открытого диалога и работы экранной клавиатуры. После завершения взаимодействия снова отсчитывается полный интервал.
- Поиск в нижней панели не переключает гаражи на каждом введённом символе. Запрос/подсветка сохраняются; Enter может завершить ввод и явно открыть найденный гараж. Исходная техника и её обработчики остаются в своей `.dispatcher-board`.
- Действуют исправления 0.1.1: никакого цикла повторных одинаковых class/disabled/hidden/style mutations. Native readiness не ослабляется. Повторный init, смена фрагмента и неизвестная версия серверного DOM проверяются отдельно.
- Только локальное обновление планшета подписанным APK с сохранением данных. GitHub, Actions, SSH и публикация на production-сервер для этой задачи не требуются и не разрешаются как автоматическое следствие USB-установки.

Исполнители: `tablet_ui` — рабочие CSS/JS и целевые тесты в своей ветке; `qa_recon` — независимый браузерный прогон и readiness; `android_kiosk` — проверка устройства, сборка/подпись и USB-установка после команды интегратора; Джарвис — интеграция, версия, документация и итоговая проверка. До записи результата установки наличие собранного APK не считать публикацией на устройстве.

## Замечания владельца после установки — Ш-07

Пользователь сообщил: «боковые панели должны быть крупнее и чтоб квадраты техники должны быть такого же размера как и на рабочем поле», панели должны быть «во всю высоту экрана», выезжать поверх рабочего поля без его пересчёта. Также сообщил, что перестало работать расформирование комплекса и стряхивание самосвалов из комплекса.

Обновлённые критерии:

- Слева и справа — панели на полную высоту, без прежних отступов под шапку и нижнюю строку. Более широкая область гаража; плитки техники имеют фактические размеры плиток основного поля. Содержимое и серверные функции сохраняются.
- Открытие и закрытие меняет только положение и видимость панели. Размеры и позиции комплексов/плиток, прокрутка основного поля не меняются. Исключение — настоящее изменение данных или размера экрана, которое проверяется отдельно и не должно маскироваться под движение панели.
- Даже полностью пустой гараж открывается как полноценная область возврата техники. Существующее подтверждение расформирования и освобождения самосвалов обязательно сохраняется.
- Прежние правила одной панели, 10 секунд, паузы при вводе/жесте/диалоге остаются действующими.

Найдены конфликты, подлежащие проверке и исправлению: штатный CSS скрывает пустые гаражи через `display:none`, а 0.1.3 меняет только visibility/transform. Размер такого гаража измерялся как нулевой. В планшетной последовательности tap-select → цель настоящий dragstart происходит лишь после выбора цели, поэтому штатное временное раскрытие пустого гаража не помогает. Независимый агент проверяет обе цели и маршруты подтверждения в изолированной fixture.

Для пересчёта найдены две зависимости: штатный `dispatcher-canvas-v1.js` пишет общие размеры холста на resize; при замене фрагмента adapter временно возвращает старую сетку для замера, что запускает настоящий ResizeObserver самосвальных стоек. Статичный снимок с отключёнными серверными script-блоками этого взаимодействия не проверял. В следующем прогоне обязательны реальные canvas, board-layout и complex-truck-racks runtime, пустые гаражи, неизменность геометрии по кадрам и исходные подтверждённые команды.

0.1.3 подтверждён как установленный release: пульт открылся без ошибки readiness, Activity/ландшафт и режим обслуживания NONE сохранены. Полный набор проверок устройства прерван по поступившим замечаниям; автоскрытие, все направления и новый холодный запуск для этого выпуска завершёнными не считаются.
