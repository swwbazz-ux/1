## 3. Новый дефект QA-CHAOS-P1-008-R1

### 3.1. Название

`QA-CHAOS-P1-008-R1 — Механик может закрыть простой Самосвала вопреки правилу «только Водитель»`.

Приоритет: `P1`.

### 3.2. Утвержденное правило

Документ 97 устанавливает:

- простой Самосвала открывает и закрывает только Водитель;
- у Механика не должно быть кнопки, API-пути или другого права управления простоем Самосвала;
- исходный конфликт Механик × Водитель снят именно потому, что такой доступ Механику не требуется.

### 3.3. Фактическое поведение

Текущий контур Механика:

1. выбирает все открытые `DowntimeEvent` без ограничения по виду техники;
2. выводит кнопку закрытия у каждого выбранного события;
3. принимает в `mechanic_close_downtime_view` любой `DowntimeEvent`;
4. не проверяет, что событие относится к Самосвалу.

Адреса причины:

- `СИСТЕМА_MVP/backend/downtimes/views.py`, `mechanic_dashboard_view`;
- `СИСТЕМА_MVP/backend/templates/downtimes/mechanic_dashboard.html`, форма закрытия;
- `СИСТЕМА_MVP/backend/downtimes/views.py`, `mechanic_close_downtime_view`.

### 3.4. Независимое воспроизведение

На временной in-memory test DB созданы:

- тип техники и Самосвал;
- причина простоя, доступная Водителю;
- активный Механик с полностью активированной ролевой сессией;
- открытый простой Самосвала.

Затем активный Механик отправил настоящий POST на штатный маршрут `mechanic_close_downtime`.

Фактический результат:

```text
HTTP = 302
ended_at до POST = NULL
ended_at после POST = timestamp
ожидание теста = ended_at остается NULL
результат = FAIL
```

Тестовая база уничтожена. Рабочая `db.sqlite3` не использовалась и не изменилась.

### 3.5. Риск

Механик может ошибочно завершить водительский простой Самосвала. После этого техника способна выглядеть доступной раньше фактического окончания простоя, а история будет противоречить утвержденному распределению ответственности.

## 7. PostgreSQL

На компьютере нет локальной PostgreSQL-службы и `psql`; Django использует локальную SQLite. Настоящие конкурентные тесты не запускались и не объявлены пройденными.

Обязательный внешний приемочный набор:

1. два Механика открывают простой одной разрешенной техники;
2. разгрузка Водителя конкурирует с отменой рейса Диспетчером;
3. разгрузка Водителя конкурирует со служебным завершением;
4. два клиента одновременно отправляют одинаковый `client_action_id`;
5. переключение активной роли конкурирует с уже начатым изменяющим действием;
6. погрузка конкурирует с закрытием простоя разрешенной техники.

Использовать только отдельную разрешенную тестовую PostgreSQL, не production и не рабочую базу.
