## Решение

**Принимаю функциональную цепочку повторной погрузки Y в границах Q1–Q3. Полный сквозной E2 остаётся PARTIAL: настоящая разгрузка водителя X ещё не проверена.** Отдельного повторного испытания ради PNG до повтора Q3 не назначаю.

Проверены опубликованные raw, диагностический профиль, инструменты и отчёт. Адресную сверку Q2/Q3 параллельно выполнил отдельный агент. Собственного Django/БД/телефонного прогона Астра не выполняла; числовые выводы ниже получены из опубликованных свидетельств.

Подсчёт Trip в qa1_db_probe.py идёт по trip_id из TripClientAction с данным event_id. Это адресное подтверждение 1/1/1, не полный аудит всех строк БД.

PNG до retry Q3 остаётся NOT_CAPTURED. Для сохранности и дедупликации достаточны опубликованные pending-конверт, DOM, proxy и DB. Полная визуальная приёмка этим не объявляется. Дополнительные Q1-V/Q2-V — отдельные циклы, их нельзя выдавать за кадры первоначальных Q1/Q2.

Профиль имеет отдельный package, выключенный updater и отдельный HTTPS origin. Build-time patch разрешает нестандартный порт только для названного диагностического профиля/хоста; по опубликованному patch проверки HTTPS/hostname не отключены. Установленный APK отдельно не извлечён и не хеширован: это ограничение отчёта сохранено.

## Исправление вывода о manifest

Заявление «40/40 опубликованных файлов совпали» независимо не подтверждено. Из 34 прочитанных текстовых Git blobs:
- все 34 точно совпали с SHA-1 объекта Git и его размером;
- 19 совпали с исходным SHA256SUMS;
- 15 имеют в исходном manifest хеш CRLF-варианта, тогда как в Git лежит LF;
- шесть PNG в этой сверке самостоятельно не прочитаны/не хешированы.

Для всех 15 несовпадений CRLF-вариант точно воспроизводит старое значение, поэтому причина установлена; это не свидетельство потери данных событий. [Отдельный аудит опубликованных байтов](ПРИЕМКА_E2_QA1_2026_10_02/git-text-manifest-audit.json) содержит исходные и фактические SHA-256, Git blob и размер для всех 34 текстов. Исходный пакет, raw и старый manifest сохранены без изменений. Новый аудит не выдаётся за исходный manifest и не объявляет проверенными PNG.

Проверка воспроизводится на любом checkout репозитория: читать каждый путь через `git cat-file blob 0c8fcdef:<путь>`, затем считать SHA-256 этих байтов, не текста checkout Windows. Для контрольного Git SHA-1 хешировать `blob <длина>\0<байты>`. Новых производственных испытаний из-за переводов строк не требуется.
