## 1. Разрешённая граница

В production опубликованы только серверные средства наблюдения за закрытыми
сменами Водителей:

- временная линия смены по существующим рейсам, простоям и назначениям;
- защищённый диагностический JSON-срез по диапазону дат;
- защищённый JSON-срез по структурному `WatchPeriod`;
- проверка качества и полноты исходных серверных событий.

Не опубликованы и не рассчитываются:

- баллы;
- места;
- официальная первая пятёрка;
- премии;
- утверждённая формула KPI;
- пользовательский экран рейтинга;
- запись результатов рейтинга в рабочую базу.

Все ответы сохраняют
`official_rating_eligible=false`.

## 7. Закрытый доступ и read-only режим

Без авторизации оба маршрута возвращают `401 JSON`, не выполняют redirect и
не раскрывают данные:

- `/reports/rating/driver-shadow-data/`;
- `/reports/rating/driver-watch-data/`.

Оба ответа имеют:

```text
Cache-Control: max-age=0, no-cache, no-store, must-revalidate, private
```

Авторизованная проверка выполнена через существующий активный доступ
Администратора без создания login-сессии. Вся транзакция принудительно
переведена командой:

```sql
SET TRANSACTION READ ONLY
```

Сервер подтвердил `transaction_read_only=on`. Изменяющие действия не
выполнялись. Кадровый персональный номер в JSON отсутствует.

## 10. Где и как проверять

Контур опубликован в production на `driverform.ru`, но отдельного
пользовательского экрана рейтинга пока нет.

Проверка выполняется только действующей активной сессией одной из ролей:

- Диспетчер;
- Администратор;
- Руководитель.

Маршруты:

```text
GET /reports/rating/driver-shadow-data/?date_from=2026-07-06&date_to=2026-07-12
GET /reports/rating/driver-watch-data/
```

До появления `WatchPeriod` второй маршрут честно возвращает пустой
структурный вахтовый срез.

## 11. Следующий предметный этап

Deploy закрытого теневого контура завершён.

Уточнение владельца процесса: составы вахт уже утверждены, поэтому новый
реестр утверждения и новая согласующая роль не нужны. Действующие
обязанности остаются без изменений:

- ОУП вводит сотрудников в систему;
- Делопроизводитель контролирует расселение сотрудников;
- Заместитель начальника участка распределяет сотрудников по технике и
  дневной/ночной смене.

Следующий этап — только технически использовать утвержденный состав вахты и
существующую расстановку для связи `WatchPeriod` с закрытыми
`EmployeeShift`. Теневой рейтинг не участвует в утверждении состава и не
передает эту функцию Табельщику или Руководителю.

После накопления хотя бы одной полноценной структурно связанной вахты можно
калибровать нормализацию, формулу и веса KPI.
