# «Завершить смену другой роли и начать эту» — одинаково во всех ролях

Дата: 10.09.2026. Ветка `codex/cross-role-shift-handover-2026-09-10` (worktree `C:\mm-handover`),
от боевого коммита `360e8f31`; коммиты `deb3732e` (фикс 500 мастера + логирование 500,
перенос из ветки аудита), `cf433d13` (механизм для всех ролей), `f5078551` (версии).
Решение пользователя: вариант Б — один человек с несколькими ролями при старте смены в
новой роли получает вопрос и одним действием завершает старую смену и открывает новую.

## Что было

Правило базы «одна открытая смена на сотрудника» (`unique_open_shift_per_employee`)
встречало многоролевого сотрудника по-разному: водитель и экскаваторщик — отказ «смена
уже открыта», диспетчер — «у вас уже открыта смена…», ОУП — «сначала завершите…»,
мастер — необработанный `IntegrityError` и белый экран 500 (инцидент 10.09, отчёт 182).
Плашка «Продолжить здесь» тут ни при чём: она переключает сеанс, а не смену.

## Что сделано

Общий слой в `shifts/services.py`:

- `find_other_role_open_shift(employee, workplace_code)` — открытая смена в другой роли
  (пустой `workplace_code` старых записей другой ролью не считается);
- `other_role_shift_prompt(shift, target)` — текст вопроса «У вас открыта смена «Горный
  диспетчер» с 09:44. Завершить её и начать смену Горного мастера?», кнопка «Завершить и
  начать», имя поля `close_other_role_shift`;
- `resolve_other_role_shift(...)` — без подтверждения `OtherRoleShiftOpen` (сообщение
  «…Подтвердите её завершение, чтобы начать смену …»), с подтверждением —
  `handover_other_role_shift`: служебное закрытие (`is_service_closed=True`,
  `closed_by` = сам сотрудник, незавершённые рейсы в перенос, паспорт смены водителя в
  очередь, событие `shift_handover_closed`) и открытие новой смены в той же транзакции.
  Конечные показания техники при таком закрытии не вводятся — их негде ввести на экране
  другой роли; в отчётах смена помечена служебным закрытием, как при закрытии диспетчером.

Экраны (все: экран заранее знает про чужую смену, вопрос задаётся после обычного жеста):

| Роль | Жест | Где вопрос | Ответ «да» |
|---|---|---|---|
| Водитель | удержание 1 с | стандартное окно `openAppConfirmDialog` | hidden `close_other_role_shift=1`, повтор submit |
| Экскаваторщик | удержание 1 с | то же; плюс вопрос от сервера (409 `other_role_shift_open`), если экран устарел | JSON `close_other_role_shift: true` |
| Диспетчер | кнопка + окно (10 с) | текст окна = вопрос | hidden-поле в форме |
| Горный мастер | кнопка + окно (10 с) | текст окна = вопрос | hidden-поле в форме |
| ОУП | кнопка | окно `data-confirm` на форме | hidden-поле в форме |

## Бой не равен git — важно для публикации

Живые файлы сервера **не совпадают ни с одним коммитом** в репозитории: сегодня на бой
клали правки напрямую (`tmp/claude-search-v75…v79`, `tmp/claude-canvas-v77`; диспетчер
v79, экскаваторщик v222 с подтверждением показаний, статика v132). `DEPLOYED_COMMIT`
говорит `360e8f31`, но `shifts/services.py`, `trips/views.py`, `dispatcher_control.html`,
`excavator_work.html`, `role_apps.py` на бою новее.

Поэтому набор для публикации собран как **боевой файл + мои правки** (3-way merge, база
`360e8f31`): конфликты только в строках версий и в двух местах, где обе стороны добавили
строки; серверные новшества (подтверждение показаний экскаваторщика, холст диспетчера)
сохранены. Зеркало бой+правки (`C:\live-mirror`) прогнано тестами и проверено в браузере
(экскаваторщик и мастер). Набор: 21 файл в `scratchpad/deploy` (16 кода/шаблонов + 5 тестов).

План публикации: резервная копия `backups/deploy-<UTC>-shift-handover-before`
(все заменяемые файлы + DEPLOYED_COMMIT) → сверка, что боевые файлы не менялись с
момента снятия копии → копирование с контрольными суммами → `collectstatic` →
`systemctl restart accounting-mvp` → проверка версий SW всех ролей и кодов ответов.
Миграций нет. Откат — копирование из резервной копии и перезапуск.

## Дополнение 11.09.2026: адаптив входа в узких окнах

Замечание «адаптивной вёрстки нет совсем» (облачный браузер ~1024×700): причина — общее
правило `app.css` `@media (orientation: landscape) and (max-width: 1180px) { .dispatcher-shell
{ width:1400px; height:800px; transform: scale(.5) } }` — тело входа несёт класс
`dispatcher-shell` и ужималось вчетверо. Для `body.login-unified-v2` масштабирование
снято. Вторая правка: в узких/квадратных окнах (1024×700, 1280×800) левая колонка почти
вертикальная — `<source media>` подставляет вертикальный кадр (`object-position: center
12%`), горизонталь — при `(min-width:1024px) and (min-aspect-ratio: 7/4)` и на
горизонтальном телефоне `(min-width:761px) and (max-height:520px)`; `min-height` колонки
= 100dvh. Проверено на 1024×700, 1280×800, 1366×768, 1920×1000, 844×390, 375×812.
Коммит `d5b5bc8d`, выложено 11.09 (2 файла, CSS v=5, копия
`backups/deploy-<UTC>-login-adaptive-before`). Урок: стенд с `--noreload` не подхватывает
