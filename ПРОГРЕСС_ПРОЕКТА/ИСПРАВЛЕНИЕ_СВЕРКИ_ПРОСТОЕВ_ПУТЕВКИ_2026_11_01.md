# Исправление сверки простоев путёвки Водителя — 01.11.2026

## Причина и исправление

Локальный журнал путёвки склеивал разные начала одной причины, если погрузка Экскаваторщиком уже закрыла простой на сервере, но на телефоне не было отдельного события окончания. При слиянии синтетические локальные границы подменяли канонические серверные.

Исправление в `driver-manifest-local-v1.js`:

- идентичность простоя определяется устойчивыми локальными/серверными ID;
- закрытый серверный интервал использует серверные границы;
- локальное окончание сохраняется до подтверждения, пока серверная строка открыта;
- входящая действующая погрузка ограничивает ожидание своим временем;
- отклонённые действия остаются видны в журнале и не меняют подтверждённую длительность;
- устаревший снимок не открывает известный закрытый интервал;
- сохранённые журналы v1 пересобираются автоматически, без очистки данных телефона.

Серверный payload содержит собственную версию состояния и семантику причин. Версия фиксируется до чтения исходных событий. Веб-оболочка Водителя и каталог приложений согласованно переведены на v380. Native APK менять для этого исправления не требуется.

## Проверки

Добавлены синтетические регрессионные сценарии: повторные ожидания, погрузка с другого устройства, устойчивые ID, автономные окончания, перезапуск, старые снимки, закрытие смены и отклонённые действия. Регрессия воспроизводит завышение исходным алгоритмом, исправленный алгоритм даёт каноническую сумму.

Локальные проверки: JavaScript — 1014 успешных, 1 штатный пропуск; мобильная оболочка — 44/44; Django users — 611 проверок, 3 штатных пропуска; контракт пакета публикации — 70 проверок, 1 платформенный пропуск. Независимое ревью исправления: APPROVE. Добавлена проверка собственной версии серверного payload при параллельном изменении состояния.

Настоящий Chrome, локальный Django через `START_SERVER_MVP.bat`, изолированная синтетическая SQLite: `/driver/?tab=manifest` — HTTP 200 при ширине 390 и 1280 px, правильная каноническая сумма, 15 тестовых рейсов, без переполнения и наложения подписей. Запись локального простоя без сети и последующая перезагрузка сохраняют журнал и сумму; неподтверждённый итог помечен предварительным. Единственная сетевая ошибка консоли создана явной offline-фазой; ошибок JavaScript не обнаружено.

Реальные production-выгрузки, локальные ключи диагностики и данные сотрудников в репозиторий не включаются. Подробный протокол инцидента хранится локально у владельца.

## Публикация и откат

Поставка ограничена тремя файлами: `static/js/driver-manifest-local-v1.js`, `users/views.py`, `users/role_apps.py`. Схема и данные БД не изменяются.

Путь публикации: итоговая release-ветка на подтверждённом последнем application release, защищённый PR в каноническую ветку, `VERIFY` и `DEPLOY` одного полного SHA через GitHub Actions. Receiver перед заменой сохраняет прежние файлы и автоматически восстанавливает их при ошибке проверки/запуска. Ручной откат — режим `rollback` того же workflow с точным каталогом `github-…-deploy-before`, выданным успешным запуском.

После поставки проверить публичные manifest/service worker v380 и контрольную сумму нового JS. Факт загрузки v380 на конкретном рабочем телефоне проверяется отдельно; локальный браузерный прогон не подменяет полевую приёмку.

Статус до защищённой публикации: локальное исправление и проверка; production-успех подтверждается только фактическим `RELEASE_OK mode=deploy`.
