## Исправлено

- Driver сохраняет полный исходный конверт и ACK в том же долговечном
  хранилище. `confirmed` исключается из доставки, но остаётся в `journal()`.
  После перезапуска путёвка получает `journalEvents`, включая подтверждённые
  факты, независимо от выполнения прежнего UI callback или нового снимка.
- Старый terminal-отказ убирается только из индикатора доставки; его исходник
  больше не удаляется через 24 часа. Локально отменённая неподанная пара
  сохраняет оба исходника; связь пары записывается перед вторым шагом, поэтому
  прерывание записи второй половины не отправляет оставшуюся отмену отдельно.
- Путёвка не удаляет смены с исходными событиями по возрасту или при quota.
  При ошибке её вторичной localStorage-проекции источник остаётся в outbox,
  текущая проекция — в памяти. Сбой записи явно возвращает `false`; повторный
  запуск восстанавливает проекцию из долговечного источника. Повреждённый JSON
  сначала сохраняется побайтно в отдельный резерв; предыдущий резерв не
  перезаписывается. После этого проекция строится только из доступных событий
  outbox. При quota резерва исходный ключ не меняется, текущая проекция остаётся
  в памяти, запись можно повторить после освобождения хранилища. Несуществующий
  серверный снимок при восстановлении не создаётся.
- Excavator localStorage-журнал больше не обрезает подтверждения до 200.
  Явно отменённая неподанная погрузка архивируется как `cancelled_locally` и
  не воспроизводится как серверно подтверждённая погрузка. Новый `journal()`
  возвращает исходники очереди и архива без дубля по ID.
- Восстановление Excavator IndexedDB дополняет имеющуюся очередь из fallback
  по неизменяемой идентичности и переносит подтверждения. Оно не заменяет
  существующую IndexedDB всем старым массивом. Повреждённые legacy-данные
  сохраняются побайтно, исправная IndexedDB продолжает работать; ошибка видна
  во внутреннем состоянии хранения.
- Восстановление Driver IndexedDB переносит собственные события fallback,
  архивированные ACK, tombstone идентичности, серверные карты и метаданные
  последовательности. Имеющаяся IndexedDB дополняется по неизменяемому ID,
  конфликтующий конверт не перезаписывается. Пустая очередь доставки с высоким
  sequence в архиве не сбрасывает порядок новых действий. При quota/повреждении
  сохраняется raw fallback и остаётся рабочей primary-очередь; ошибка видна как
  `migration_error`, перенос повторяется при следующей инициализации. Очистка
  удаляет только точные перенесённые записи, сохраняя появившиеся во время
  асинхронного импорта события или новые состояния ACK. Сохранённый primary
  `null` остаётся снятием проекции завершённого рейса: старый fallback не
  заменяет его прежней квитанцией погрузки.
- Оба outbox ограничивают весь `send` до уже разобранного ответа, по умолчанию
  12 с. AbortSignal передаётся настоящим sender-функциям. Deadline работает
  и без AbortController; поздний результат истёкшего запроса не применяется.
- Зависший Promise UI callback Excavator не удерживает дальнейшую доставку.
  Quota при записи ACK оставляет исходник доступным для повтора с тем же ID.
  Driver повторяет такую ошибку через 5–8 с, а не через секундный цикл;
  счётчик принятых событий меняется после долговечного архивирования.

## Оставшиеся границы

1. Автономное opening, полноценный местный отчёт и почасовая группировка
   Excavator, весь OFF-C1 и серверное доказательство покрытия событий снимком
   остаются отдельной F7.
2. Без доказанного покрытия нет безопасной автоматической очистки источника.
   Архив сейчас растёт; `journalEvents` Driver читает и передаёт весь журнал
   данного доступа. Нужны объёмные измерения, индексы/порционная загрузка и
   ограниченная очистка только доказанно архивированной полной смены.
   При заполнении доступного хранилища новое действие не объявляется успешно
   сохранённым. Число 12 с — настройка deadline, не измеренный SLA.
3. Ранее удалённые исходники и подтверждения сверх прежних 200 восстановить
   этим изменением нельзя. Rebuild использует имеющийся долговечный журнал,
   а не объявляет его ретроспективно полным для версий до данного исправления.
   Raw повреждённой путёвки сохраняется отдельно для дальнейшего разбора.
4. Межвкладочная запись fallback localStorage и полная длительная смена на
   физических устройствах остаются NOT_RUN. Производственный выбор при
   неизвестной зависимости не менялся.
