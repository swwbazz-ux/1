делает штатное закрытие машиниста. Подпись водителя остаётся SHA-256 в прежнем
поле. Схема БД не меняется. Проверяется точный повтор, запрет иных показаний с тем
же ID, исходная история служебного закрытия и единственность действия. В обязательную
PostgreSQL-группу добавлен `HistoricalBoundariesTests`, чтобы этот сценарий больше
не ожидал полного ночного прогона.

## Автономная смена машиниста: серверное открытие и локальная связь

База — `e0655719cb5b19ac8ba088ca1ee6744e2ca703b6`. Из OFF-C1-R1
`6c31e854` адресно адаптирован только обработчик открытия; старые runtime-файлы
целиком не перенесены. Актуальные F3, R-21 и deadline отчёта сохранены.

Сервер принимает `excavator.shift.opened`, сохраняет исходное операционное время
через существующий сервис открытия и возвращает серверный ID смены. Для связи
используется `local_shift_id`, равный ID открытия. Последующие события могут
сослаться на него до появления серверного ID. До открытия они остаются RETRY;
после принятия открытия F3 автоматически продолжает сохранённые события без
повторного нажатия/отправки телефона. Исходный конверт при привязке не меняется.

Связь ограничена исходными сотрудником, доступом, ролью и устройством. Проверяются
порядок sequence и согласованность явного server ID с local ID. Необязательное
поле не добавляется к старым событиям без local ID; прежние fingerprints обеих
ролей сверяются с golden-значениями опубликованного нормализатора.

Сохраняются текущие проверки расстановки и показаний. Занятая смена не закрывается
автоматически. Предыдущие показания берутся только из смены, завершённой к моменту
нового открытия. Новых моделей/миграций нет; версии телефонных оболочек не менялись.

## F7: защита локального журнала от двух окон

База опубликованного этапа — `9d83b5c2abda213080bd75bb49c63fba8b3675ac`.
Все изменения журнала (событие, импорт, квитанция) теперь выполняются под
общей Web Lock для того же ключа доступа/роли/устройства, что используется
хранилищем. После получения блокировки журнал повторно читается и проверяется;
старый снимок окна не заменяет более новые события другого окна.

Блокировка удерживается до завершения записи, включая ошибку. Захват использует
`ifAvailable`: занятое другим окном хранилище возвращает `local_shift_busy`
без бесконечной очереди ожидания. Неуспешное действие не отправляется в outbox.
При отсутствии Web Locks запись отклоняется с `local_shift_lock_unavailable`;
сохранённые данные остаются доступны для чтения. Небезопасной имитации блокировки
через localStorage нет. Добавлен `refresh()` для явного обновления проекции
второго окна без записи новой ревизии. UI должен вызвать его при возврате окна
в фокус; привязка этого вызова относится к следующему этапу интеграции.

Новый набор проверяет два независимых JS-контекста с общей моделью browser lock:
сохранение событий двух окон, устаревшее действие после закрытия, запоздалая
квитанция, занятую блокировку и повтор, освобождение после ошибки, отсутствие
Web Locks, обновление проекции и повторную проверку владельца журнала.

## Ограничение ожидания и защита копий журнала, оболочка v269

База — опубликованный `04fff279f76b16a25216677062cf0c5f77094c81`.
Устранён риск отката к старой копии: после частичного успеха записи новая
ревизия могла существовать только в IndexedDB либо localStorage, а последующий
отказ этой копии раньше позволял загрузить старую и продолжить её перезапись.

Открытие IndexedDB и каждая операция имеют общий предел 2500 мс. При истечении
предела транзакция прерывается до освобождения блокировки записи, соединение
закрывается. Позднее завершение открытия закрывает соединение и не начинает
операцию. Новая попытка использует новое соединение; ошибка ready больше не
закрепляется навсегда за экземпляром журнала.

Если IndexedDB предоставлен браузером, но недоступен, либо не читается другая
копия, журнал возвращает ошибку вместо выбора потенциально старой истории.
Равные ревизии с разным содержимым также останавливают запись. Обе копии при
этом сохраняются без изменений. Если обе читаются, выбирается большая ревизия,
независимо от часов устройства. Успех записи хотя бы в одну копию остаётся
достаточным для подтверждения сохранения; последующая проверка не позволяет
незаметно потерять эту ревизию.

Это намеренное ограничение доступности: при невозможности сравнить копии
нельзя продолжать новые местные записи, пока чтение не восстановится.
Работа только с localStorage поддерживается, когда API IndexedDB отсутствует;
наличие API с ошибкой не считается доказательством отсутствия данных.
Синхронное зависание самого браузера/localStorage этим таймером не лечится.

сохранённой страницей. XHR никогда не получает сохранённый HTML вместо свежих
данных. Статика проверяется по исходному URL/версии и типу; HTML входа не
записывается вместо скрипта. Миграция старой оболочки сохраняет очередь.

При подготовке подключения кнопки обнаружено, что сервер не поддерживал
`excavator.work_context.changed`. Участок разделён на серверный приём и
последующее подключение экрана; в этом коммите завершён серверный приём.

Новое событие проходит существующий устойчивый приём F3: сохраняется исходный
конверт, проверяются автор, роль, устройство и собственная смена. Если местное
открытие ещё не принято, настройки ожидают его и автоматически продолжаются.
Повтор возвращает прежнюю квитанцию без повторного изменения данных.

Порода проверяется по тому же ограниченному справочнику, что в обычной форме.
Если хотя бы одна выбранная точка недоступна, весь выбор отклоняется;
частичного применения нет. Плечи перевозки берутся из серверной расстановки,
переданные телефоном значения не заменяют диспетчерские.

Исходные настройки всегда остаются в принятом событии. Актуальная проекция
обновляется только когда не найден более новый контекст или следующая смена.
Время проекции — время соответствующего факта, не время доставки. При равном
времени порядок признаётся только для большей sequence того же автора,
доступа и устройства. Если специализированная дата контекста отсутствует,
changed_at служит консервативной границей: событие может остаться историческим
без замены актуального забоя. История не переписывается по догадке.

Настройки, квитанция и транзакционные уведомления работают внутри общей
транзакции F3; исключение при смене версии откатывает проекцию.

## Автономные настройки забоя: кнопка, восстановление и погрузки

База — опубликованный `6057b1154668555957f9269bbfec23a1c9a66bb0`.
Оболочка Экскаваторщика — `excavator-mobile-shell-v272`.

Для смены, открытой через местный журнал, «Применить настройки» сохраняет
`excavator.work_context.changed` до сообщения об успехе. Отправка на сервер
идёт отдельно; зависший HTTP не удерживает кнопку. До выбора местного или
прежнего серверного пути кнопка дожидается чтения журнала. Ошибка чтения или
записи не подменяется серверным POST и не показывается как успешное сохранение.
Для существующей серверной смены без местного открытия сохранён прежний POST.

Порода, горизонт, блок и выбранные точки восстанавливаются из исходного события
после перезапуска и замены серверного фрагмента. Повторная квитанция не стирает
черновик формы. При изменении настроек в другом окне обновляются применённые
точки, но незавершённый ввод остаётся. Закрытая старая местная смена не подменяет
более новую серверную; следующая местная смена не получает событие настроек
предыдущей как своё.

Разрешённые, но не выбранные точки заранее входят в подготовленную разметку
скрытыми и отключёнными. После местного применения нужные карточки доступны
сразу, без запроса фрагмента. Скрытая карточка не принимает погрузку. Общий
шаблон сохраняет прежнюю ветку ручного рабочего места Водителя.

Настройки ссылаются на открытие и предыдущие настройки. Обычная погрузка и
погрузка «Свободный ковш» ссылаются на последнее сохранённое событие настроек.
Внутри блокировки журнала они получают именно его породу, горизонт и блок,
а не незавершённый ввод формы. Попытка устаревшего окна отправить самосвал на
уже снятую точку отклоняется без записи погрузки. Исходные события не меняются.
R19 сохранён: применение настроек само по себе не начинает Перегон или простой.

Добавлены 12 адресных JS-сценариев и серверная проверка подготовленных точек.
Они покрывают реальный обработчик кнопки, восстановление, зависшую отправку,
квоту и повтор, раннее нажатие/ошибку чтения, черновик после ACK, два окна,
смену контекста, обе разновидности погрузки, readonly и прежний POST.
