поле. Схема БД не меняется. Проверяется точный повтор, запрет иных показаний с тем
же ID, исходная история служебного закрытия и единственность действия. В обязательную
PostgreSQL-группу добавлен `HistoricalBoundariesTests`, чтобы этот сценарий больше
не ожидал полного ночного прогона.

## Автономная смена машиниста: серверное открытие и локальная связь

База — `e0655719cb5b19ac8ba088ca1ee6744e2ca703b6`. Из OFF-C1-R1
`6c31e854` адресно адаптирован только обработчик открытия; старые runtime-файлы
целиком не перенесены. Актуальные F3, R-21 и deadline отчёта сохранены.

Сервер принимает `excavator.shift.opened`, сохраняет исходное операционное время
через существующий сервис открытия и возвращает серверный ID смены. Для связи
используется `local_shift_id`, равный ID открытия. Последующие события могут
сослаться на него до появления серверного ID. До открытия они остаются RETRY;
после принятия открытия F3 автоматически продолжает сохранённые события без
повторного нажатия/отправки телефона. Исходный конверт при привязке не меняется.

Связь ограничена исходными сотрудником, доступом, ролью и устройством. Проверяются
порядок sequence и согласованность явного server ID с local ID. Необязательное
поле не добавляется к старым событиям без local ID; прежние fingerprints обеих
ролей сверяются с golden-значениями опубликованного нормализатора.

Сохраняются текущие проверки расстановки и показаний. Занятая смена не закрывается
автоматически. Предыдущие показания берутся только из смены, завершённой к моменту
нового открытия. Новых моделей/миграций нет; версии телефонных оболочек не менялись.

## F7: защита локального журнала от двух окон

База опубликованного этапа — `9d83b5c2abda213080bd75bb49c63fba8b3675ac`.
Все изменения журнала (событие, импорт, квитанция) теперь выполняются под
общей Web Lock для того же ключа доступа/роли/устройства, что используется
хранилищем. После получения блокировки журнал повторно читается и проверяется;
старый снимок окна не заменяет более новые события другого окна.

Блокировка удерживается до завершения записи, включая ошибку. Захват использует
`ifAvailable`: занятое другим окном хранилище возвращает `local_shift_busy`
без бесконечной очереди ожидания. Неуспешное действие не отправляется в outbox.
При отсутствии Web Locks запись отклоняется с `local_shift_lock_unavailable`;
сохранённые данные остаются доступны для чтения. Небезопасной имитации блокировки
через localStorage нет. Добавлен `refresh()` для явного обновления проекции
второго окна без записи новой ревизии. UI должен вызвать его при возврате окна
в фокус; привязка этого вызова относится к следующему этапу интеграции.

Новый набор проверяет два независимых JS-контекста с общей моделью browser lock:
сохранение событий двух окон, устаревшее действие после закрытия, запоздалая
квитанция, занятую блокировку и повтор, освобождение после ошибки, отсутствие
Web Locks, обновление проекции и повторную проверку владельца журнала.

## F7: подключение локального открытия к экрану машиниста (v267)

Для локально открытой смены существующие вызовы очереди проходят через адаптер:

## Ограничение ожидания и защита копий журнала, оболочка v269

База — опубликованный `04fff279f76b16a25216677062cf0c5f77094c81`.
Устранён риск отката к старой копии: после частичного успеха записи новая
ревизия могла существовать только в IndexedDB либо localStorage, а последующий
отказ этой копии раньше позволял загрузить старую и продолжить её перезапись.

Открытие IndexedDB и каждая операция имеют общий предел 2500 мс. При истечении
предела транзакция прерывается до освобождения блокировки записи, соединение
закрывается. Позднее завершение открытия закрывает соединение и не начинает
операцию. Новая попытка использует новое соединение; ошибка ready больше не
закрепляется навсегда за экземпляром журнала.

Если IndexedDB предоставлен браузером, но недоступен, либо не читается другая
копия, журнал возвращает ошибку вместо выбора потенциально старой истории.
Равные ревизии с разным содержимым также останавливают запись. Обе копии при
этом сохраняются без изменений. Если обе читаются, выбирается большая ревизия,
независимо от часов устройства. Успех записи хотя бы в одну копию остаётся
достаточным для подтверждения сохранения; последующая проверка не позволяет
незаметно потерять эту ревизию.

Это намеренное ограничение доступности: при невозможности сравнить копии
нельзя продолжать новые местные записи, пока чтение не восстановится.
Работа только с localStorage поддерживается, когда API IndexedDB отсутствует;
наличие API с ошибкой не считается доказательством отсутствия данных.
Синхронное зависание самого браузера/localStorage этим таймером не лечится.

не кэшируются. Архив не ограничен двумя часами либо последними 200 событиями.

Страницы содержат до 100 полных исходных событий, квитанции, отпечатки,
контекст закрытой смены и полную загрузочную проекцию. Снимок связан токеном,
зависящим от состава исходников, их контрольных сумм, квитанций, границ смены
и фактов погрузки. Изменение между страницами требует новой сверки. Повреждённый
или старый конверт без проверяемого исходника, неоконченная обработка и
отсутствующая предметная погрузка не дают доказательства покрытия.

Проекция явно перечисляет исходные погрузки и серверные рейсы, отмены,
исходное время погрузки, тип самосвала, назначенную при погрузке точку,
объём и отсутствие известного объёма. Несколько подтверждённых action ID
одного Trip дают один рейс в итогах. Квитанция погрузки может ссылаться полем
`equipment` на самосвал; экскаватор проверяется по исходной смене.

Телефон сравнивает все исходники с журналом, включая подтверждённые и
технические группы длинной смены. Допускается только добавленный транспортом
верхнеуровневый `sent_live`; поля факта, времени, автора, смены и payload
должны совпасть. Проверяются полнота страниц и набора ID, принадлежность,
контекст, квитанции, состав погрузок, отмены, количество рейсов и объём в
сотых м³ без накопления ошибки float. Запись покрытия и восстановление
потерянных ACK происходят атомарно под блокировкой с повторным чтением журнала.
Снимок прежней смены сохраняет новую смену/действия другого окна; устаревшая
версия доказательства не заменяет более свежую.

Сверка запущена в фоне при старте, получении квитанций, возврате окна и сети.
Открытие, новые действия и отчёт её не ожидают. Дедлайн 12 секунд охватывает
весь сетевой проход, заголовки и тело; поздний ответ не может записать покрытие.
Временный отказ повторяется автоматически с паузой 5–60 секунд. Неисправный
старый архив не мешает сверке следующих смен. При отключённой сети/смене
активного пользователя запросы прекращаются до подходящего сигнала.

Ограничение текущей выдачи — до 10 000 событий одной смены. При превышении,
истечении дедлайна или недостоверном ответе покрытие не выставляется, все
исходники сохраняются. Этот этап формирует и сохраняет доказательство и
серверный снимок; удаления или уплотнения местных исходников ещё нет.
ACK сам по себе по-прежнему не считается покрытием проекции.

## Безопасное сокращение местного архива Экскаваторщика (v276)

База — опубликованный `5bd7a7be18f9f5f82e58728150016efb81c19c6a`.
Оболочка — `excavator-mobile-shell-v276`.

Закрыт ограниченный пункт F7 «безопасная очистка уже проверенной истории
Экскаваторщика». Текущая смена и две последние закрытые собственные смены
остаются целиком. Возраст определяется порядком создания в журнале, а не
часами устройства. Фоновый проход обрабатывает одну смену; перед сокращением
он заново получает полное серверное покрытие. Обычная работа экрана сети
и этого прохода не ожидает.

У более старой закрытой смены с полным покрытием сохраняются исходные
открытие/закрытие, все ID действий, квитанции и отпечатки, серверный снимок,
местные факты погрузок с отменами и последний контекст забоя. Оригиналы всех
действий остаются на сервере и доступны прежнему архивному endpoint.
Местные классификация, названия, объёмы и применённое серверное время
сохраняются без подмены серверной классификацией. Двухчасовой и полный
сменный отчёты, сводка и контекст после сокращения/перезапуска совпадают.
Сокращение выполняется только при реальном уменьшении UTF-8 размера;
пустая смена не раздувается и не запускает бесконечную повторную сверку.
Сводные факты и перечень исходных ID остаются: это уменьшение архива,
а не абсолютный лимит всей истории телефона.

При подтверждении покрытия SHA-256 связывает полный местный исходник,
квитанции, данные проекции и доказательство. Перед удалением избыточных
конвертов под общей Web Lock повторно читается последняя версия хранилища
и проверяется тот же отпечаток. Старое покрытие v275 без отпечатка требует
новой сверки. Изменение исходника/квитанции/проекции или хотя бы одно
неподтверждённое действие не разрешает сокращение. Подсчёт отпечатка имеет
дедлайн 1,5 с; поздний результат не записывается. Отказ записи сохраняет
исходную историю и в памяти, и на диске; счётчик последовательности не
сбрасывается. Более новая запись в одной из копий не заменяется старой.

записью из уже открытого окна. Новая версия читает оба формата и проверяет
структуру сокращённого архива. Удалённый из локального списка конверт не
восстанавливается выдуманным событием: его ID остаётся занятым в архивном
перечне. Повторное использование ID, удаление через discard и поздние ACK
не могут воскресить событие либо изменить сохранённый отчёт.

## Серверное покрытие журнала Водителя и фоновая сверка (v380)

База — опубликованный `abfe6ddc9ae28ce9516dacb5f6d83b5fc595d231`.
Оболочка Водителя — `driver-mobile-shell-v380`; Экскаваторщик остаётся v276.

Добавлен read-only endpoint `/offline-events/driver-shift-archive/` для
активного доступа Водителя. Архив ограничен его исходным автором, доступом,
ролью, устройством и принятой командой закрытия. Поддержаны как собственное
местное открытие, так и серверная смена без местной команды открытия,
включая прежние смены с пустым workplace_code. Принадлежность и закрытие
подтверждаются серверными связями, а не данными из query.

Смена связывается по местному ID и серверному номеру одновременно: после
ACK открытия телефон начинает записывать числовой shift_id. В проверку
входят и неразобранные исходники без прикладного FK — по сохранённому
normalized.shift_id либо payload.local_shift_id. Ожидающий/отклонённый
исходник, чужой контекст или недостоверная квитанция не разрешают покрытие.
Все исходные envelopes проверяются до выдачи первой страницы, поэтому
повреждение последней страницы не скрывается за корректной первой.

Страницы по 100 записей содержат исходные события, квитанции, отпечатки,
границы и показания смены. Снимок связан SHA-256 с исходниками и предметными
фактами; изменение между страницами требует новой сверки. Предел одной
выдачи — 10 000 событий; срезов транспорта в 200 событий или два часа нет.
Ответы не кэшируются, серверные факты этим endpoint не изменяются.

Для каждого исходника рейса возвращается состояние самого Trip: погрузка,
завершение/отмена, самосвал и экскаватор, точка, объём и источник времени.
Несколько действий одного Trip не удваивают итог. Исходное участие,
разгрузившая смена и начисление разделены; D1 → D2 определяется прежним
проверяемым правилом паспорта `_carryover_loading_driver_shift`, а не просто
наличием driver_control_shift. Его файл `reports/driver_shift_timeline.py`
добавлен в release manifest как обязательная зависимость нового endpoint. Для простоев сохранены начало/конец, причина
и пересечение с границами смены; start/end одного простоя дают один интервал.
Проекция относится к фактам из собственных исходников этого устройства.
Она не выдаётся за полный производственный отчёт всех устройств и ролей.

Новый `driver-shift-archive-v1.js` сверяет все страницы с полным outbox.journal,
включая подтверждённые записи, местные/числовые алиасы и потерянный ACK
открытия. Проверяются исходные поля и последовательность, принадлежность,
квитанции, состав фактов, отмены, начисление, объём в сотых м³ и секунды
простоя. Различаться могут только известные метаданные доставки. Свежий
журнал повторно читается перед сохранением; новая запись другой смены не
теряется и не мешает покрытию старой.

Доказательство сохраняется отдельно в localStorage: серверный снимок,
предметные факты, manifest всех исходных ID/квитанций, SHA-256 исходников и
самого доказательства. Повреждённое доказательство восстанавливается новой
сверкой. Изменение исходников отменяет его повторное использование. Это
не разрешение очистки: исходный журнал, ACK-состояния, путёвка и незавершённые
действия не переписываются и не удаляются. Локально взаимно отменённая пара
без серверных квитанций не объявляется покрытой; её исходники сохраняются.

Сверка работает после старта, изменения журнала, возврата сети/окна.
Общий дедлайн 12 с включает чтение журнала, заголовки/тело, все страницы и
отпечатки. Поздний результат и ответ после смены пользователя не сохраняются.
Временные ошибки повторяются с паузой 5–60 с; после покрытия запросы к архиву
прекращаются до появления нового состава исходников. Ошибка сети/квоты не
мешает обычной работе Водителя. Очистка чужого состояния смены остаётся до
подключения нового фонового обработчика; звук и голосовые вызовы сохранены.

## Сжатие проверенного архива Водителя без потери исходников, Driver v381

База этапа — опубликованный `e5668fcab3018bce89a6e7b262716dfe89e7a24c`.
После подтверждения покрытия журнал Водителя всё ещё хранил каждый исходник
и полную повторную запись его идентичности отдельно. Добавлен
`driver-journal-storage-v1.js`, подключённый перед outbox, в предкэш оболочки,
составные readers экрана и production manifest. Изменения относятся к F1/F2/F7;
статус пакетов остаётся: F3 реализован в кандидате, остальные семь частично.

### Что завершено

- Сжимается одна собственная закрытая смена за фоновый проход, когда все её
  исходники подтверждены и существуют две более новые закрытые смены того же
  устройства. Порядок определяется последовательностью журнала, а не часами
  телефона. Текущая смена, две последние закрытые, чужие устройства, pending,
  conflict, auth_required, invalid и отменённые только на телефоне события
  остаются в исходном виде.
- Ранее сохранённая проверка сама по себе не разрешает сжатие: worker заново
  получает все страницы серверного снимка и проверяет точное покрытие, рейсы,
  простои и исходные конверты. Непосредственно перед заменой перечитывается
  весь набор строк в одной транзакции записи. Новое действие, другой ACK или
  изменение другой вкладкой отменяют попытку.
- Пакет содержит словарь значений и строки, восстанавливающие все поля каждого
  события, включая неизвестные дополнительные поля и состояние доставки.
  Сохраняются полный проверенный манифест ID/квитанций/отпечатков и предметные
  факты. SHA-256 защищает пакет. Это сжатие без потерь, а не удаление истории
  после создания краткого отчёта.
- Пакет, указатели исходных ID и удаление лишних копий идентичности записываются
  атомарно. `journal()`, `get()`, проверка повторного ID и локальная путёвка
  получают восстановленные исходники. Поздняя запись retry/ACK не перезаписывает
  упакованный источник. Счётчик sequence и серверные карты не сбрасываются.
- При недостатке места, повреждении пакета/указателей, смене текущей роли либо
  истечении срока нет частичного удаления. Открытие и транзакции IndexedDB,
  проверка и подготовка сжатия ограничены 2500 мс; общий проход серверной сверки
  сохраняет предел 12000 мс. Отложенное завершение отменённой операции не может
  записать пакет. Это параметры ограничений, не измеренный SLA телефона.
- Сжатие пропускается, если не уменьшает число байтов или исходники превышают
  8 МиБ. Отметка пропуска привязана к содержимому источников, чтобы фон не

Теперь запись команды хранит actor/access/настоящую роль доступа/смену,
ID запроса и исходное время. HTTP передаёт этот сохранённый контекст в

Предметный JSON и его прежний fingerprint не изменены. Источник новых команд
находится в обновляемом корне доски или мобильного фрагмента, поэтому свежая
смена после realtime не подменяется устаревшими атрибутами внешней оболочки.

Новый серверный модуль `assignments/command_context.py` защищает ровно четыре
endpoint: move_excavator и assign_truck у Диспетчера и Горного мастера.
Внутри атомарной операции он блокирует сотрудника/доступ, повторно проверяет
активную авторизацию и сравнивает её с исходным контекстом. Затем проверяет
исходную смену до предметного эффекта. Обновление сессии того же сотрудника
не запрещается; чужая cookie, подменённая роль/автор, закрытая либо другая
смена не исполняют старую команду под новыми данными.

Подмена времени/ID/смены уже принятого действия отклоняется. Повтор принятой
команды после потери ответа возвращает её прежнюю квитанцию даже после
закрытия исходной смены; новый эффект и новая запись в следующей смене не
создаются. Служебные поля квитанции не выходят в публичный ответ. Если
внутренний обработчик неожиданно выбрал другую смену, вся операция откатывается.

## Последовательные распоряжения одному самосвалу, Master v170 / Dispatcher v171

могла сохранять несколько распоряжений с одним старым числовым номером
назначения. После приёма первого второе получало конфликт со своим же
предшественником; непосредственный post мог также обогнать первый запрос.

При создании новой команды транспорт находит незавершённого предшественника
того же самосвала, endpoint, автора, доступа, роли и смены. До первой записи
вместо устаревшего числового expected_assignment_state_id сохраняется ссылка
`command:<client_action_id>`. Следующий элемент ссылается на конец цепочки,
без зависимости от порядка одинаковых временных меток. Две неоднозначные
ветви не сворачиваются в одну: третья команда не подтверждается как сохранённая.
После записи исходник, ссылка, автор и время не пересчитываются при отправке.

Мобильный Мастер после успешного enqueue сохраняет ссылку на собственную
команду в локальной карточке при наполнении, снятии и перестановке. Копирование
карточек сохраняет токен. Поэтому следующая операция может сослаться на первую
и после её ACK, пока серверный фрагмент ещё не заменил локальную карточку.
Прежний запрет повторного жеста для плитки is-transfer-pending не снят: этот
участок не меняет разрешённые пользователю действия и бизнес-правила ожидания.

Отправитель ждёт надёжно записанный ACK предшественника. Другие самосвалы
продолжают отправляться. Потеря ответа или ошибка записи ACK приводит к повтору
того же предшественника, а не к преждевременной отправке потомка. Held/rejected
или отсутствующая местная запись предшественника не означают успех; исходник
потомка остаётся в журнале. Подтверждение held через существующий read-only API
квитанций разблокирует потомка без повторного исполнения предшественника.

Сервер разрешает ссылку только для связанной с автором команды: квитанция
должна принадлежать тому же действию, сотруднику, доступу, роли и смене,
содержать подтверждённый номер назначения именно этого самосвала и исходный
контекст; время потомка не может предшествовать времени родителя. Для этого
новые ответы отдельных ASSIGN/RELEASE включают совместимое поле truck_id.
Чужая/неполная/ещё отсутствующая квитанция не заменяется текущим состоянием.
Полученный номер проходит прежний CAS доменного сервиса: вмешательство другого
сотрудника по-прежнему даёт state_conflict. Активация экскаватора Диспетчера
при таком конфликте откатывается вместе с эффектом.

Fingerprint считается по сохранённому payload со ссылкой. Тело запроса не
переписывается полученным серверным ID. Дубль после закрытия смены возвращает
первоначальную квитанцию, а подмена ссылки при том же client_action_id отклоняется.
Исходный срок ASSIGN из предыдущего участка сохраняется; RELEASE не получает
нового правила срока. Числовой протокол прежних клиентов сохранён. Клиент без
X-Command-Context и прежний сервер не должны трактовать строковую ссылку как
числовой ID: операция отклоняется, вместо выполнения с ослабленным CAS.

## Массовые распоряжения после одиночных команд, Master v171 / Dispatcher v172

База — опубликованный `4c224b4592cf7ab926dd6f40b116b8cd3e334869`.
Участок связывает release_complex и перевод экскаватора в inactive с ранее
сохранёнными одиночными ASSIGN/RELEASE в обоих пультах. Карта состава могла
содержать ссылку command:<id>, а уходящий самосвал уже отсутствовал в ней,
хотя его распоряжение ещё не было принято сервером.

До записи массового исходника общий транспорт сохраняет assignment_dependencies
с конечными одиночными командами того же автора, доступа, роли, смены и пульта.
Видимые числовые номера заменяются ссылками только при наличии собственного
незавершённого предшественника; явные ссылки карточек не пересчитываются.
Отдельный список включает и уже ушедшие с карточки самосвалы. Выбран осторожный
порядок: ждём все ранее сохранённые одиночные команды этого автора/смены,
включая команды других комплексов, потому что старые исходники не всегда
содержат доказанный исходный комплекс. При неоднозначной ветви новый массовый
исходник не подтверждается. Ссылки, список и первоначальный payload после
надёжной записи не изменяются.

Для непосредственного structural autoRetry:false-вызова отправитель ожидает
надёжные ACK предшественников до 12 секунд, будит обычную очередь и проверяет
условие раз в 500 мс. Затем HTTP массового действия имеет прежний отдельный
deadline 12 секунд, включая тело ответа. Это два ограниченных ожидания,
а не бесконечный promise. Повторный send во время ожидания разделяет promise.
Автор/роль перепроверяются, перед HTTP вновь читается исходная запись.
Успешная квитанция одного предшественника не заменяет подтверждение остальных.
Если во время ожидания отдельная сверка или другая вкладка уже сохранила ACK
самой массовой команды, отправитель возвращает эту квитанцию без нового HTTP.
Проверка действует и на границе тайм-аута: доказанный успех не откатывается.
При смене роли/автора квитанция не подменяет проверку действующего доступа.

При тайм-ауте/смене автора/отказе исходник остаётся held, promise завершается,
существующий обработчик восстанавливает карточки и отменяет поздние таймеры.
Поздний ACK родителя не исполняет откатившуюся массовую команду. После потери
процесса autoRetry:false по-прежнему запрещает фоновое исполнение; исходник
сохраняется для read-only проверки квитанции. Ошибка записи held также не
снимает заранее сохранённый запрет автоповтора. Счётчик ожиданий не позволяет
ACK одиночной команды обновить доску посреди массового жеста; общие ограничения
обновления во время сетевой операции/жеста сохранены.

Сервер разрешает ссылки по квитанциям отдельных команд: тот же сотрудник,
доступ, роль, смена и конкретный самосвал, исходный контекст и допустимый порядок
времени. Для расформирования родитель ищется среди assign_truck, а не среди
move_excavator. После подтверждения ВСЕХ зависимостей номера подставляются
только во внутреннюю карту проверки; подпись и квитанция сохраняют исходный
payload со ссылками. Состав и зона проходят прежние проверки конфликтов.

read-only сверку. При отказе исходные номера возвращаются вместе с карточками,
только если их не успело заменить более новое действие.

исходник содержит ссылку на массового предшественника и ждёт его надёжный ACK
с номером именно этого самосвала в результате. При создании команды по
числовому старому снимку транспорт также обнаруживает незавершённое массовое
распоряжение этого автора/доступа/роли/смены, затрагивающее самосвал. Конец
цепочки выбирается по зависимостям, а не по времени или порядку записи:
одиночная → массовая → одиночная → одиночная. При следующем массовом действии
выбор последней одиночной команды учитывает и промежуточный массовый узел:
одиночная → массовая → одиночная → массовая. Неоднозначные ветви остаются
ошибкой; исходники не сливаются и не переписываются после ACK. Прежние барьеры
массовых операций по одиночным командам сохранены.

квитанции, сверяя автора, доступ, роль, смену, порядок времени и присутствие
конкретного самосвала. Ссылка на обычную одиночную квитанцию, другой вид массовой
операции, отсутствующий самосвал или чужой контекст не подходит. Полученный ID
проходит прежний CAS: сторонняя перестановка после массового снятия даёт
state_conflict, включая откат активации Диспетчера. Fingerprint сохраняет
первоначальный payload со ссылкой; первоначальный срок нового ASSIGN не
продлевается доставкой. Дубликат после закрытия смены возвращает ту же
квитанцию. Прежний числовой протокол сохранён; без контекста новая ссылка
безопасно отклоняется старым числовым валидатором.

### Реализация

Общий транспорт распознаёт доказанный отказ по совокупности: rejected,
сохранённый структурированный ответ ok:false и HTTP 400. Прежняя классификация
409, ошибок авторизации, 5xx и потери ответа не менялась. Совпадают все четыре
поля контекста автора/доступа/роли/смены; ссылка должна указывать на единственного
подходящего родителя нужного типа и самосвала.

Неотправленные pending-потомки переходят в сохранённое состояние blocked со
ссылкой на исходный отказ и понятной причиной. Исходный request, время, подпись,
зависимости и квитанция родителя не меняются; серверная квитанция для потомка
не создаётся. Для этих команд нет ни нового POST, ни read-only запроса
несуществующей квитанции. Обход покрывает одиночные, массовые и смешанные
цепочки; если массовое действие зависит от отказа одного самосвала, блокируется
вся его операция и связанные потомки. Обход выполнен без рекурсии.

Согласование работает перед отправкой/фоновой досылкой, после сохранения отказа
и при проверке структурного ожидания. Ожидающий structural-вызов завершается
без исполнения и освобождает прежний UI-откат. После перезапуска частично
сохранённая цепочка доводится до того же состояния. Неоднозначные ссылки,
неизвестный результат, чужой контекст и уже начатые отправки не объявляются
безопасно отменёнными. Сохранённый ACK потомка не заменяется отказом.

Только после записи блокировки вызывается сверка проекции: у Мастера доска
помечается устаревшей и используется прежняя ограниченная повторная загрузка;
Диспетчер использует существующее восстановление после конфликта. Сверка
срабатывает и при прежней версии сервера — отказ мог её не изменить. Текущие
жесты, открытое сообщение и другие незавершённые команды продолжают защищать
экран от преждевременной замены. Если записи мешает квота, потомок остаётся
ожидающим и доска не считается готовой к замене; после восстановления записи
согласование продолжается.

Блокировка не является автоматическим переизданием команды. Даже поздний ACK
родителя не оживляет уже заблокированных потомков. После свежей расстановки
пользователь может создать новое распоряжение по её актуальному числовому
состоянию. Исходные команды остаются в журнале. Уведомление о необходимости
сверки выдаётся один раз за запуск, в том числе для уже сохранённой blocked-цепочки.

### Серверная квитанция отказа

Для четырёх маршрутов расстановки с полным исходным контекстом сохраняется
окончательный `state_conflict` после предметной проверки. Вызов обработчика
выполняется во вложенной транзакции: прежде чем сохранить отказ, откатываются
все его изменения, сигналы, события, версии и отложенные on_commit callbacks.
Квитанция использует существующий ShiftClientAction, исходные fingerprint,
автора, доступ, роль, смену, идентификатор и время. Модели и миграции не меняются.

Повтор того же ключа возвращает тот же отказ 409. Он не исполняет распоряжение,
даже если расстановка позднее стала подходящей или исходная смена закрылась.
Повтор без заголовка также не получает ложный HTTP 200; закрытая смена продолжает
защищаться прежним legacy-guard. Изменённый payload/контекст не заменяет квитанцию.

Read-only endpoint квитанции возвращает rejected лишь для сохранённого
специального признака отказа, точной подписи и полного совпадения исходного
контекста. В доказательстве передаётся HTTP 409 и контекст сервера; внутренние
служебные поля скрыты. Отсутствие записи, прежний unsuccessful payload без
признака, legacy-409, ошибка доступа/смены/времени и неразрешённая зависимость
не превращаются в доказанный отказ. Они остаются unresolved.

### Очередь и проекция

Получив state_conflict 409, современная команда ожидает чтения квитанции в held.
Кандидатами сверки также становятся pending-команды, для которых уже начиналась
отправка: потерянный успех или отказ можно восстановить до очередного POST.
Проверяемый идентификатор занят на время чтения, а другие команды могут идти
параллельно. Прямой send того же ID ждёт результата сверки. Для unresolved
pending сохраняется прежняя политика идемпотентной досылки; held автоматически
не переисполняется. Проверка квитанции ограничена общим deadline и backoff.

Отказ становится rejected только после проверки точного маршрута, ID, исходного
времени, автора/доступа/роли/смены и доказательства сервера, затем надёжной записи
в журнал. Согласование блокирует только неотправленных зависимых потомков,
сохраняя их исходники. ACK не заменяется поздней ошибкой. Переходный callback
восстанавливает доску Мастера/Диспетчера даже при неизменной версии сервера и
повторяется после перезапуска, если прежний запуск не успел обновить экран.
Перед поиском квитанций сначала согласуются уже доказанные отказы: для никогда
не отправленного заблокированного массового потомка не возникает лишнего HTTP.

При сбое записи отказ не объявляется сохранённым; callback и блокировка потомков
не обходят сохранность. Подмена исходника/автора во время чтения не завершает
чужую команду. Незавершённые действия и текущие жесты сохраняют прежнюю защиту
проекции от замены устаревшим снимком.

## Точные ресурсы сохранённой доски — 06.10.2026, Master v180 / Dispatcher v181

Ограниченный участок F2: подготовка JavaScript и CSS Мастера/Диспетчера
при установке SW. Прежний CORE содержал преимущественно адреса без query,
тогда как HTML подключает `?v=...`; mobile-shift-unified-v1.js Мастера
в CORE вообще отсутствовал. Cache.match не считает такие адреса одинаковыми.

Сделано:
- Install сначала полностью получает HTML нужной роли и проверяет адрес,
  HTML-тип и ролевой корень dispatcher-shell. Страница входа, чужая роль
  или пустой набор зависимостей не считаются готовой автономной установкой.

  локальные адреса с query; дубли объединяются, &amp; декодируется, fragment
  не входит в ключ. Комментарии и строки внутри inline-скриптов пропускаются.
  Внешняя или не-static зависимость отклоняет установку: такой ресурс
  не объявляется сохранённым молча.
- Точные зависимости добавляются к прежнему CORE/release. Все тела должны
  завершиться до записи кандидата; статические ответы должны иметь исходный
