## 2. Результат по карточкам

### 2.1. QA-TRAFFIC-P2-001-R1

Статус: **ГОТОВО К ПЕРЕПРОВЕРКЕ**.

У Горного мастера удалён отдельный десятисекундный forced state poll,
дублировавший общий realtime-клиент.

Сохранено:

- общее realtime-обновление с рабочим интервалом роли;
- один узкий JSON fragment для релевантного события;
- отсутствие fragment GET для нерелевантного события;
- одиночный catch-up после `focus`, возврата видимости или `online`;
- защита от poll storm.

В production-шаблоне отсутствуют:

- `runMiningMasterPassiveReconcile`;
- отдельный таймер `10000`;
- второй автономный цикл сверки состояния.

### 2.2. QA-TRAFFIC-P2-002

Статус: **ГОТОВО К ПЕРЕПРОВЕРКЕ**.

Из компонента достижений удалены:

- двадцатисекундный polling;
- запрос после любого общего fragment;
- общий visibility-запрос без подтверждённого релевантного события.

Оставлены:

- ровно одна начальная проверка;
- проверка только для завершённого рейса текущего Самосвала или текущего
  Экскаватора;
- debounce;
- single-flight;
- ноль запросов в hidden-состоянии;
- не более одного catch-up после возврата видимости;
- не более одной recovery-попытки после сетевой ошибки;
- прежний цикл unlock → показ → закрытие → `shown=true`.

Событие с `eventsTruncated=true` не превращено в широкую проверку достижений:
оно не доказывает, что завершённый рейс относится к текущей технике.

### 2.3. QA-TRAFFIC-P2-003

Статус: **ГОТОВО К ПЕРЕПРОВЕРКЕ**.

Автоматические полные GET service worker с `?version_check` удалены.

Новый контракт:

- сервер сообщает `role_shell_version` через общий PWA-contract;
- стабильная версия не вызывает `registration.update()`;
- одна новая версия вызывает ровно один controlled update;
- повторы той же версии не запускают второй update;
- повторная регистрация роли при fragment rebind не выполняется;
- `controllerchange` обрабатывается только общим guard;
- ручная проверка остаётся single-flight;
- автоматический controlled update сам не отправляет `SKIP_WAITING`;
- после явного подтверждения обновления общий guard откладывает
  `controllerchange` reload до безопасного завершения рабочего действия.

Дополнительно закрыты обнаруженные Browser QA race-сценарии:

- загруженный HTML `v111`, активный worker `v110`, waiting worker `v111`
  корректно показывает путь управляемой активации;
- waiting worker старее уже загруженного HTML не предлагается;
- отложенный ответ `GET_VERSION` не восстанавливает badge после
  `waiting → active`;
- fragment rebind не отправляет повторный `SKIP_WAITING` старому worker;
- recovery-кнопки PWA и форма входа остаются доступны при contract lock,
  но изменяющие производственные действия не разблокируются.

Согласованные версии после изменения:

| Водитель | `driver-mobile-shell-v111` |
| Машинист | `excavator-mobile-shell-v124` |

## 13. Остаточные риски

- Реальная сетевая задержка и фоновые ограничения конкретного Android
  зависят от устройства; физический Android в этом прогоне не использовался.
- Proxy-событие текущего прогона не требовало achievements GET из-за пустого

  подтверждено отдельным proxy-окном, а не полем `summary.json`.
- HTTP/2/nginx намеренно не проверялись и не изменялись: это исключённая
