## 9. Новый дефект QA-P1-006

### 9.1 Карточка дефекта

| Поле | Значение |
|---|---|
| ID | `QA-P1-006` |
| Приоритет | `P1` |
| Название | Почасовая динамика дневной смены исключает переходящий рейс после 19:00 |
| Экран | `/reports/management/dynamics/` |
| Параметры | `date_from=2026-07-24&date_to=2026-07-24&granularity=hour&shift_type=day&chart_mode=cumulative` |
| Ожидается | `3 рейса / 141 м³` |
| Получено | `2 рейса / 94 м³` |
| Потерянный рейс | № 17, `47 м³ / 127,37 т` |
| Атрибуция рейса | `loading_shift=day`, `created_at=19:02`, `unloading_shift=night` |
| Воспроизводимость | 100% на QA-копии R04 |

### 9.2 Подтверждённая причина

В `СИСТЕМА_MVP/backend/reports/shift_analytics.py`:

1. Кандидатный queryset и `trip_loading_shift_type` сначала правильно относят рейс к дневной смене по `loading_shift`.
2. В ветке `granularity == "hour"` рейс повторно фильтруется по `trip.created_at`.
3. `19:02` уже попадает в ночной временной диапазон, поэтому авторитетная связь `loading_shift=day` теряется.
4. Event-series графика дополнительно обрезается концом дневного диапазона; простое удаление одного фильтра исправит KPI, но оставит график неправильным.

Ориентиры текущего файла:

- кандидатный queryset: строки 158–173;
- `trip_loading_shift_type`: строки 95–98;
- повторный часовой фильтр: строки 621–626;
- построение event-series: строки 642–648;
- расчёт границ часа: строки 463–472.

### 9.3 Рекомендованное исправление

Исправлять только подтверждённый контракт:

1. Для рейсов с `loading_shift` считать эту связь авторитетной при `hour/day/shift/month`.
2. Часовую классификацию по `created_at` использовать только для legacy-рейсов без `loading_shift`.
3. Переходящее событие авторитетной дневной смены после `19:00` помещать в граничную корзину `19:00`.
4. Симметрично обрабатывать позднее событие ночной смены у границы `07:00`.
5. Исправить одновременно итоговые KPI, точки и cumulative-series.
6. Не менять атрибуцию разгрузки в транспортных и суточных отчётах: там действующий результат правильный.

### 9.4 Обязательная регрессия

Добавить в `СИСТЕМА_MVP/backend/reports/tests.py` сценарий:

1. Дневная смена содержит два обычных рейса и переходящий рейс `47 м³`.
2. Переходящий рейс имеет `loading_shift=day`, `created_at=19:02`, `unloading_shift=night`.
3. Для фильтра `day` каждая детализация `hour/day/shift/month` должна вернуть `3 рейса / 141 м³`.
4. Сумма часовых корзин должна быть `3 / 141 м³`.
5. Корзина границы `19:00` должна содержать `1 / 47 м³`.
6. Последняя точка cumulative-series должна быть `3 / 141 м³`.
7. Фильтр `night` не должен включать этот рейс по погрузке.
8. Legacy-рейс без `loading_shift`, созданный в `19:02`, должен сохранить ночную атрибуцию.
