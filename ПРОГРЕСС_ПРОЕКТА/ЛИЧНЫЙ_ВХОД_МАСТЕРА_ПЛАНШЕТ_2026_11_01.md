## Принятый сценарий

1. Первый вход: телефон + первоначальный PIN из карточки. Сервер проверяет действующего сотрудника и доступ `mining_master`; одного телефона или текста должности недостаточно.
2. Для неактивированного доступа показываются ФИО и два поля нового личного PIN. PIN — шесть цифр по действующим правилам системы. Телефон и первоначальный код повторно вводить не нужно.
3. После активации открывается пульт без автоматически созданной смены. «Начать смену» использует только что проверенную личность без повторного ввода в течение пяти минут; это одноразовое подтверждение.
4. Для уже активированного доступа используется существующий личный PIN. Переустановка APK или другой планшет не сбрасывают код и не требуют новой активации.
5. Каждое следующее начало смены: телефон + личный PIN → актуальная проверка прав → собственная смена и настоящее авторство действий. Другой мастер может войти на общем планшете своими данными.
6. Ошибка PIN, отзыв доступа, смена кода или изменение поколения сессии не обходятся сохранённой страницей. Подтверждение личности и открытие смены объединены одной транзакцией с блокировкой сотрудника/доступа.
7. Открытая смена другой роли у этого же сотрудника требует явного штатного подтверждения; оно привязано к сотруднику и конкретной смене серверным токеном. Чужая смена не закрывается молча.
8. PIN приложения не хранится в форме после отмены/возврата. Служебный PIN Android и аппаратный вход громкостью «+» не менялись.

## Технические границы

- Старт APK: `https://mining-master.driverform.ru/mining-master/tablet/`.
- Формы входа/активации: `/mining-master/tablet/login/`, `/mining-master/tablet/activate/`. Выход — POST с CSRF, сам по себе не закрывает смену.
- APK остаётся общим устройством. Отмеченная планшетная сессия направляется с прежних общего входа/активации/мастерского экрана в новый контур, чтобы нельзя было открыть смену через личный режим старого экрана.
- Диспетчерская компоновка и функции сохранены через ограниченный список серверных маршрутов. Действия идут с настоящим доступом и собственной сменой Горного мастера; роль Диспетчера искусственно не присваивается. Native/User-Agent не дают полномочий.
- Доступны карточки, назначения, перенос/расформирование, простои, ручные и исправляемые рейсы, сменные/управленческие отчёты и экспорт. Записывающие команды проверяют собственную открытую смену и свежий доступ.
- Чужая открытая смена не делает интерфейс этого мастера цветным/рабочим. Просмотр отчётов не выдаёт право записи.
- Новые правила планшета ограничены серверным маркером; обычные входы и экраны других ролей сохранены. На тестах проверены прежние dispatcher guards и общая авторизация.
- Изменение URL потребовало обновления native-списка доверенных страниц, встроенного адаптера, realtime-ссылки входа и исключения обычного Web Push приглашения. Сервис киоска и краевые системные настройки не менялись.
- Окно начала смены выносится из трансформированной шапки в корень документа только на время открытия. Проверены крупные поля, доступность кнопок и очистка PIN. При закрытой смене окно серое, «Начать смену» цветная.

## Где остановились и следующий шаг

Кандидат подготовлен; публикация и установка ещё впереди. Для новой серверной части требуется прямое разрешение по AGENTS.md. До публикации маршрута устанавливать0.1.23 поверх рабочего APK нельзя: новый адрес пока не проверен на production.

После разрешения:

1. Через защищённый GitHub Actions-канал сверить настоящий DEPLOYED_COMMIT и production-базу, создать release-ветку от неё, перенести только необходимую проверенную дельту. Не заменять production целиком этой feature-веткой и сохранить действующие изменения других чатов.
2. Проверить итоговый release commit; штатный VERIFY, затем DEPLOY с полным SHA, точным подтверждением и резервной копией. SSH не использовать. Проверить службу, релиз, ответы новых маршрутов и статические ресурсы.
3. Установить подписанный APK по USB поверх0.1.22 с сохранением данных и служебного PIN. Проверить реальный вход сотрудника, начало/конец собственной смены, автора команды, состояние отчёта, следующий вход и отсутствие регрессии панелей.
4. Проверить перезапуск/киоск и работу без USB. Первое назначение нового личного PIN настоящий сотрудник выполняет сам; его секрет не запрашивать в чате.
5. Только после реальной установки и проверки сменить указатель АКТУАЛЬНЫЙ_ВЫПУСК.md и состояние установленной версии в манифесте.

Откат серверной части — штатный rollback на сохранённый боевой SHA. Для APK Android не рассчитывать на downgrade code24→23: при необходимости собрать прежний проверенный код с новым большим versionCode и прежней подписью, сохранив данные/служебный PIN. Базу ради UI-отката не восстанавливать без анализа: после использования новой авторизации в ней могут быть законно активированные доступы и смены.
