## 3. Адресная проверка трёх карточек

### 3.1. `QA-TRAFFIC-P2-002-R2-R2`

Статус: **PASS**.

Проверен настоящий inline-runtime
`templates/includes/achievement_prize.html`, исполняемый через `vm`.

Подтверждено:

- состояние соединения начинается с `null`;
- обычное первое `connected=true` только фиксирует здоровое соединение;
- после исчерпания bounded retry последующие обычные `connected=true` не
  создают новый GET;
- `connected=false` фиксирует потерю соединения;
- только следующий переход `false → true` запускает ровно один новый
  bounded recovery;
- после второго исчерпания новые обычные `connected=true` снова не
  создают GET;
- постоянного `setInterval` в production-шаблоне нет.

Адресные сценарии: `2/2 PASS`. Полный файл достижений: `19/19 PASS`.

### 3.2. `QA-TRAFFIC-P2-003-R2-R2`

Статус: **PASS**.

Проверен настоящий общий guard, извлечённый непосредственно из
`templates/base.html`.

Подтверждено:

- после `controllerchange` экран немедленно переходит в
  `ready=false / locked=true`;
- matching-ответ waiting worker не снимает блокировку;
- только ответ точного текущего `navigator.serviceWorker.controller`
  может вернуть `ready=true / locked=false`;
- mismatch controller оставляет экран заблокированным;
- mismatch создаёт не более одного безопасного reload;
- повторная гонка не создаёт reload loop.

Адресные сценарии: `2/2 PASS`. Полный `pwa-contract-runtime`:
`30/30 PASS`.

### 3.3. `QA-TRAFFIC-P2-003-R3-R2`

Статус: **PASS**.

Проверены настоящие role-runtime из:

- `templates/trips/excavator_work.html`;
- `templates/trips/dispatcher_control.html`.

Подтверждено:

Адресные сценарии: `2/2 PASS`. Полный
