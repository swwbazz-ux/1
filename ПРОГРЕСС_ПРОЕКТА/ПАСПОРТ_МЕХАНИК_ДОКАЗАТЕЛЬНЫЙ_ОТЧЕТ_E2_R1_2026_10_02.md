# E2-R1 — доказательный отчёт

> Дополнение E2-R2 от 02.10.2026: §5 ниже доказывает сохранность очереди и досылку после устранения зависшего соединения, но не рабочий старт оболочки при продолжающем молчать listener. `Page.navigate` получил timeout; оболочка появилась после остановки listener. ## 1. Итог

Адресная доработка E2-R1 выполнена отдельным кандидатом.

- Снятие cooldown заново не реализовывалось: исходный E2-коммит перенесён без содержательной правки на свежий release как `38473e4b9a675d64ce1368032e8c66a4c31c14d9`.
- Сервер и очередь машиниста теперь восстанавливают сохранённую цепочку `dependency_rejected` после принятия точного корневого события `excavator.trip.loaded + post_unload_cooldown`.
- Восстановление сохраняет прежние `event_id`, `occurred_at`, `received_at`, `sequence`, `depends_on` и `payload`; новые события вместо старых не создаются.
- Реальный сценарий «TCP соединение принято, HTTP-ответа нет» проверен через рабочий PWA-экран, настоящий жест, закрытие/повторное открытие вкладки и последующую досылку.
- Единственный Driver-тест падает одинаково на точном base и исходном E2 в одной среде. Это исходный дефект тестового контура, а не регрессия E2; Driver UI не изменялся.
- OFF-C1-R1 и PR №145 не изменялись. Merge, VERIFY, deploy и production не выполнялись.

## 2. Что изменено

Кандидат R1 меняет только четыре файла поверх сохранённого E2:

1. `СИСТЕМА_MVP/backend/core/offline_sync.py`:
   - точное построение корней и причинной цепочки прежнего отказа;
   - root получает `conflict_recovery.reason=removed_refusal`;
   - потомок получает `dependency_recovery.reason=removed_refusal_chain`;
   - повторная обработка разрешена только для неизменного конверта того же владельца, доступа, роли, устройства и последовательности;
   - отсутствие, `retry` или посторонний конфликт в любой зависимости закрывают восстановление безопасно.
2. `СИСТЕМА_MVP/backend/static/js/excavator-field-outbox-v1.js`:
   - очередь читает журнал подтверждений вместе с текущими событиями;
   - подтверждённый root продолжает восстанавливать сохранённых детей после удаления root из очереди;
   - восстановление рекурсивно для ребёнка и внука.
3. `СИСТЕМА_MVP/backend/core/test_offline_sync.py` — серверные регрессии.
4. `СИСТЕМА_MVP/backend/static/js/tests/excavator-field-outbox.test.js` — регрессии очереди и restart.

Полный patch находится в [raw/0001-fix-recover-removed-refusal-dependency-chains.patch](ПАКЕТ_E2_R1_2026_10_02/raw/0001-fix-recover-removed-refusal-dependency-chains.patch).

## 3. Красное доказательство до исправления

На тестах, добавленных для R1, до исправления:

- Node: `29 PASS / 1 FAIL` — после удаления подтверждённого root из очереди сохранённый ребёнок не восстанавливался;
- Django после исправления тестовой фикстуры: `1 PASS / 2 FAIL` — root принимался, но ребёнок и внук оставались `conflict/dependency_rejected`.

Это соответствует дефекту из задания: клиент мог поднять полную ещё присутствующую цепочку, но серверный receipt ребёнка не имел достаточного точного основания для повторной обработки после принятия root.

## 5. Молчащий порт, очередь и restart

Проверка выполнена на `f7936b9f…` с изолированной SQLite-БД и стандартным локальным запуском проекта. Вместо ограничения скорости использован [TCP-listener](ПАКЕТ_E2_R1_2026_10_02/tools/silent_http_port.ps1), который принимает соединения на `127.0.0.1:8765` и не читает/не пишет HTTP.

Хронология:

1. Контрольный рейс X самосвала `QA-T-01`: `loaded_at=00:14:42.990054Z`, `completed_at=00:15:31.733838Z`.
2. Django остановлен; молчащий listener запущен в `00:16:47.3838323Z`.
3. Через настоящий pointer/drag обработчик страницы создано событие Y:
   - `event_id=excavator-load-333430d9-59c2-4b2a-ad90-d6a58a6469a8`;
   - `occurred_at=00:17:05.756Z`;
   - `sequence=2`;
   - CDP зафиксировал реальный `POST /offline-events/sync/`, `hasUserGesture=true`.
4. Пока порт молчал: на экране очередь `1`, карточка «Сохранено на телефоне · на телефоне», связь отсутствует; в БД receipt отсутствовал.
5. Управляемая вкладка закрыта. Новая вкладка открыта при всё ещё отсутствующем Django: service worker восстановил оболочку, очередь осталась `1`, состояние — «Ожидает отправки».
6. После остановки listener и запуска Django очередь стала `0`, карточка — «На разгрузку», связь — «Связь есть».

Сервер после восстановления содержит ровно:

- `1` receipt с исходным `event_id`, `occurred_at` и `sequence`;
- `1` `TripClientAction`;
- `1` новый рейс Y;
- `trip.loaded_at=00:17:05.756Z`, то есть время нажатия сохранено, а не заменено временем приёма `00:18:45.600Z`.

Полные поля: [silent-port-browser-qa.json](ПАКЕТ_E2_R1_2026_10_02/raw/silent-port-browser-qa.json) и [silent-port-db-after.json](ПАКЕТ_E2_R1_2026_10_02/raw/silent-port-db-after.json). Это browser/PWA-доказательство; физический APK и Xiaomi не проверялись.
