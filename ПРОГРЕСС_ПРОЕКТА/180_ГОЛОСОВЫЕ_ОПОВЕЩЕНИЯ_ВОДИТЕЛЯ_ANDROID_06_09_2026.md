# Голосовые оповещения водителя в Android APK — 06.09.2026

## Что реализовано

- В профиль Android-приложения водителя добавлено адресное фоновое оповещение по событию `trip_changed / truck_loaded`.
- Когда окно приложения свёрнуто, Android показывает heads-up уведомление `Новая точка разгрузки` с названием назначенной точки.
- Сначала звучит действующий короткий сигнал `driver_truck_assigned.wav` длительностью 900 мс, затем выдерживается пауза 200 мс и запускается утверждённая мужская запись точки разгрузки.
- На время записи приложение запрашивает кратковременное понижение громкости фильма или музыки через `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, после окончания записи управление звуком возвращается другому приложению.
- Одно серверное событие озвучивается только один раз: последняя обработанная версия сохраняется в настройках Android-приложения.
- Новая неизвестная точка без подготовленной записи имеет резервную русскую системную озвучку.

## Записи

В APK включены 8 записей: ККД, СКДР, Отвал, СВХ, Склад окисленной руды («кислуха»), Склад негабарита, Буферный склад и Подсыпка.

Текущие постоянные ID справочника `1–6` привязаны напрямую. СВХ и Буферный склад распознаются по названию, которое теперь включено в серверное событие назначения.

## Граница готовности

Версия `0.1.11` опубликована. Подключённого Android-устройства при проверке не было, поэтому сценарий «экскаваторщик назначил точку → уведомление поверх фильма → сигнал → голос» остаётся обязательной проверкой на реальном телефоне.

Фоновое получение события в этой версии использует существующий авторизованный нативный heartbeat с интервалом 20 секунд, а не Firebase Cloud Messaging. Поэтому ожидаемая задержка оповещения — до 20 секунд плюс время сетевого ответа.

## Production-hotfix экрана входа 06.09.2026

После первой установки `0.1.11` на Infinix X6833B обнаружен критический
стык двух ранее независимых изменений. Общий `<body>` получил атрибут
`data-native-app-version` для диагностики активной сессии, а встроенный
Android-updater считал любой узел с этим атрибутом подписью версии и присваивал
ему `textContent`. В результате вся страница заменялась единственной строкой
`Версия 0.1.11`.

Commit `d2788933` ограничивает Android-селектор только специальными элементами
`.native-app-version[data-native-app-version]`. Для уже установленного APK
в production немедленно разведены атрибуты: корневой диагностический атрибут
переименован в `data-native-client-version`, а heartbeat читает новое имя.
Поэтому переустановка APK и повышение версии не требуются: достаточно полностью
закрыть приложение и открыть снова.

Точечный production deploy затронул только актуальные runtime-файлы
`templates/base.html`, `static/js/application-session-heartbeat.js` и его
collected static-копию. Перед заменой сохранена резервная копия
`/srv/accounting-mvp/backups/code/version-body-hotfix-20260906T0754Z`.
`manage.py check`, `collectstatic`, restart `accounting-mvp`, `nginx -t` и
публичная проверка с точным User-Agent `CopperResourcesNative/driver/0.1.11`
пройдены. На `390×844` опубликованный экран показывает полный вход Водителя,
у `<body>` нет опасного атрибута, версия клиента `0.1.11` сохраняется для
heartbeat, горизонтального переполнения и ошибок консоли нет. База данных,
модели, миграции, APK, страница скачивания и номер версии не изменялись.
