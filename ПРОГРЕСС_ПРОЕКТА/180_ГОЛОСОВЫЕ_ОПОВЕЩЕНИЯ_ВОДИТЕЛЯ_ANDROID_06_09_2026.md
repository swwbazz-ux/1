# Голосовые оповещения водителя в Android APK — 06.09.2026

## Что реализовано

- В профиль Android-приложения водителя добавлено адресное фоновое оповещение по событию `trip_changed / truck_loaded`.
- Когда окно приложения свёрнуто, Android показывает heads-up уведомление `Новая точка разгрузки` с названием назначенной точки.
- Сначала звучит действующий короткий сигнал `driver_truck_assigned.wav` длительностью 900 мс, затем выдерживается пауза 200 мс и запускается утверждённая мужская запись точки разгрузки.
- На время записи приложение запрашивает кратковременное понижение громкости фильма или музыки через `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, после окончания записи управление звуком возвращается другому приложению.
- Одно серверное событие озвучивается только один раз: последняя обработанная версия сохраняется в настройках Android-приложения.
- Новая неизвестная точка без подготовленной записи имеет резервную русскую системную озвучку.

## Записи

В APK включены 8 записей: ККД, СКДР, Отвал, СВХ, Склад окисленной руды («кислуха»), Склад негабарита, Буферный склад и Подсыпка.

Текущие постоянные ID справочника `1–6` привязаны напрямую. СВХ и Буферный склад распознаются по названию, которое теперь включено в серверное событие назначения.

## Исправление полной тишины на реальном телефоне — выпуск 0.1.14

На Infinix X6833B с установленной `0.1.13` воспроизведён дефект: событие
погрузки рейса `419` версией `10821` для самосвала `78` от экскаватора `67`
дошло до телефона, экран обновился и показал ККД, но звук не запустился.
Production access-log подтверждает получение события и фрагмента экраном в
14:05:34, а запись события содержит корректные `trip_id`, `dump_point_id=1` и
`dump_point_name=ККД`.

от успешного показа Android-уведомления.

В `0.1.14 / versionCode 19` цепочка объединена внутри Android:

- открытое приложение одним нативным вызовом проигрывает короткий сигнал и
  через 200 мс после него мужскую запись точки;
- фоновый сервис запускает голос независимо от разрешения на push, а при
  недоступном push самостоятельно проигрывает короткий сигнал;
- реальная ошибка bridge оставляет резервный короткий сигнал, а нормальный
  общий маркер `already_announced` по-прежнему подавляет дубль.

## Повторный разбор реального телефона и выпуск 0.1.15

Реальная приёмка `0.1.14` снова не прошла: на открытом экране водителя карточка
перешла в загруженное состояние, но не прозвучали ни сигнал, ни запись. Проверка
production исключила сервер и фильтрацию: WebView Infinix X6833B получил delta
`10827..10830`, в котором для тестового водителя присутствовало событие
`trip_changed / truck_loaded` версии `10830`, после чего запросил и применил
свежий driver fragment. Нативный heartbeat того же телефона получил эту delta
через 11 секунд, но версия `0.1.14` намеренно запрещала ему обрабатывать голос,
пока `AppVisibility` считал приложение открытым. Поэтому foreground целиком
зависел от одного вызова JavaScript bridge и не имел независимого нативного
канала.

В `0.1.15 / versionCode 20` устранена эта архитектурная точка отказа:

- Android heartbeat разбирает свежий `truck_loaded` и запускает цепочку
  «короткий сигнал → голос» независимо от открытого или свёрнутого состояния;
- системное push-уведомление по-прежнему показывается только в фоне;
- foreground дополнительно запускает оповещение непосредственно по переходу
  свежего fragment из `driverHasLoadedTrip=false` в `true`, а событийный канал
  сохранён как второй источник;
- общий нативный claim версии события не допускает двойного воспроизведения;
- этапы `cue_started`, `voice_started` и ошибки ресурсов записываются нативно,
  а открытый экран отправляет диагностические метки `trigger`, `result` и
  `playback` в существующий журнал клиентских ошибок. Следующая телефонная
  проверка поэтому даст точную стадию даже при повторной тишине.

## Ускоренный контур для тестового самосвала

Исключение проверяет точный гаражный номер и не распространяется на другую
технику: для обычного самосвала задержка остаётся пять минут.

Изменение зафиксировано commit `4e45970d`, отправлено в `origin` и точечно
опубликовано на production без миграций и изменений базы. Резервная копия:

test database пройдены; `accounting-mvp` активен, `NRestarts=0`. Новая APK для

Уточнение по тестовому циклу: надпись экскаваторщика «Возвращается к
экскаватору · N мин.» относится не к задержке назначения, а к отдельному
десятиминутному `TRUCK_POST_UNLOAD_COOLDOWN`. Для `ТЕСТ-1` этот cooldown также
отключён полностью; обычные самосвалы сохраняют десятиминутный запрет повторной
загрузки. Изменение зафиксировано commit `461ccea6`, опубликовано точечно с
резервной копией
`/srv/accounting-mvp/backups/code/test1-zero-cooldown-20260906T1545Z`.

Проверка исключения на изолированной SQLite test database пройдена, production
`manage.py check` успешен, сервис активен с `NRestarts=0`. Для немедленного
пересчёта уже открытых экранов создано scoped realtime-событие версии `10961`
только по самосвалу `78`; экран экскаваторщика получил и применил fragment этой

## Синхронизация кнопки и звука — выпуск 0.1.16

После серии полевых рейсов выявлена плавающая задержка: зелёная кнопка точки
разгрузки уже появлялась, а сигнал или голос запускались заметно позже. Серверная
диагностика показала точную гонку двух нативных контуров. WebView и Android
heartbeat почти одновременно видели один `truck_loaded`; фоновый сервис успевал
записать общий `already_announced`, но его собственный экземпляр проигрывателя
мог быть уничтожен или ещё не начать воспроизведение. Открытый экран после этого
правильно подавлял «дубль», хотя фактический звук для текущего события ещё не
стартовал. В журнале это проявлялось как новый `trigger/result=already_announced`
при старом времени `voice_started` от предыдущего рейса.

В `0.1.16 / versionCode 21` введён единый процессный
`DriverDumpPointAnnouncer` для WebView и фонового heartbeat. Он сначала ставит
короткий сигнал и голос в один долговечный нативный проигрыватель, фиксирует
стадию `queued`, и только затем публикует dedupe-маркер. Отдельные проигрыватели
сервиса и bridge удалены, поэтому уничтожение одного компонента больше не может
оставить уже «занятое» событие без звука. Короткий сигнал запускается сразу,
запись точки — после штатной паузы около 1,1 секунды. Двадцатисекундный heartbeat
не ускорялся и остаётся резервом для фонового режима без лишнего расхода батареи.

логику; production APK имеет SHA-256
