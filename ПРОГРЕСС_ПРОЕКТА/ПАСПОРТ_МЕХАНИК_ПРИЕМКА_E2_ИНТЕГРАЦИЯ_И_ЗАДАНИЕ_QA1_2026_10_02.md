### Отдельное предупреждение для будущей интеграции OFF-C1

На старом `6c31e8545fd5f5da727ce077774ab4eaf07fd21b` помощника `_close_downtimes_for_load` нет, а три прежних `equipment_downtime_active` отказа ещё присутствуют. При следующей сдаче OFF-C1 надо сохранить релизный приём и закрытие простоев самосвала, **одновременно** сохранив собственную OFF-реконсиляцию с `occurred_at` и `source_event_id` после погрузки. Замена функции целиком старым вариантом потеряет одну из сторон. Текстовый merge-конфликт не воспроизводился; установлено смысловое пересечение.

Релизный помощник закрывает только начавшиеся не позже погрузки открытые простои самосвала (waiting-loading обрабатывает отдельный существующий путь), пишет `downtime_closed_by_load`. Критический простой экскаватора не закрывает, пишет `excavator_downtime_active_at_load`. Это описание кода, не общее утверждение R-01/R-17 о любых простоях любой техники.

## 3. Почему установленная приёмка ещё NOT_RUN

Присланный снимок показывает тестовое рабочее место RuStore с надписью «Нет погрузки». Он подтверждает отображение оболочки; повторную погрузку после разгрузки не проверяет.

По отчёту автора QA backend отдаёт v203 и не соответствует candidate. Сам по себе APK, собранный на нужном SHA, не гарантирует нужную веб-оболочку.

Проверено по коду candidate:
- `mobile/capacitor-shell/profiles/excavator_qa/app.properties` фиксирует serverUrl/startUrl/heartbeatUrl на qa-excavator.driverform.ru; package ru.copperresources.excavator.qa, 1.0.11-qa (12).
- README объясняет загрузку ролевого PWA с адреса профиля.
- `android/app/build.gradle` принимает для serverUrl/startUrl HTTPS origin на стандартном порту, без query, fragment и credentials; startUrl того же origin. Адрес входит в BuildConfig.

Обычный HTTP localhost через adb reverse не является уже подтверждённым способом запуска этого профиля. Нельзя молча подменять его как готовый рецепт или ослаблять проверку TLS в рабочем приложении.

### 4.1. Подготовить согласованный стенд

1. Работать в отдельном каталоге/worktree с candidate 4609f17a. Backend, шаблоны и статика — из этого SHA; test DB и тестовые учётные записи изолированы. Не использовать производственную БД или рабочие учётные данные.

Самостоятельно не заменять существующий общий/moderation RuStore QA backend, не менять production, DNS/nginx/systemd или чужие стенды.
3. Если нужен иной адрес, допустима отдельная диагностическая сборка через существующий механизм профилей: отдельный QA package, согласованные server/start/heartbeat URL, выключенный updater. Native-логика и код E2 неизменны. Профиль и сборочные изменения показать отдельно с хешами; не включать их незаметно в runtime diff PR №149. Не обходить TLS/host validation.
4. До сценариев зафиксировать backend HEAD/отсутствие runtime diff, происхождение статики и shell v264, APK package/version/SHA-256, фактический адрес WebView и service worker/cache. Номер v264 сам по себе не заменяет SHA.
5. Если безопасный канал к изолированному backend недоступен, сначала подготовить воспроизводимый локальный стенд и профиль. Сообщить один конкретный недостающий ресурс Координатору (адрес/доступ/подключённый телефон), а не повторный общий запрос «продолжать ли E2». Установленную приёмку сохранить NOT_RUN до реального прогона.

Изолированная подготовка и ранее порученная приёмка входят в подготовку кандидата; публикация на общем сервере не подменяется этим поручением.

### 4.2. Проверить обычный самосвал настоящим жестом

Использовать назначенный обычный самосвал с открытой сменой водителя, без особого режима ТЕСТ-1/manual/replace. Предыдущая разгрузка должна быть принята и видна машинисту до отключения сети: иначе проверяется иной конфликт открытого рейса, а не E2.

| Сценарий | Действие и критерий |
|---|---|
| Q1, online | Принять разгрузку X. Не дожидаясь 10 минут, погрузить тот же самосвал обычной карточкой. Карточка доступна без cooldown-затемнения/отсчёта блокировки; создаётся один Y. |
| Q2, offline → reconnect | После подтверждённой разгрузки и обновления экрана отключить связь с backend. Выполнить новую погрузку ранее 10 минут реальным жестом: действие отражается локально и сохраняется в долговечной очереди. Восстановить связь: одна квитанция/действие/рейс Y, исходный event_id и время нажатия сохранены. |
| Q3, слабая связь / потеря ответа | На уже открытом рабочем экране создать такое же действие при молчащем соединении либо потерять ответ после commit. Проверить очередь и повтор с исходным конвертом; после восстановления ровно один эффект. Указать точный способ имитации, отдельно от полного отключения сети. |

Для Q2/Q3 проверить сохранность недоставленной записи через закрытие и повторный запуск QA-приложения без очистки данных/переустановки. Зависший старт оболочки при молчащем сервере остаётся известным OFF-C1: его нельзя объявлять PASS, скрывать остановкой listener или исправлять переносом OFF-C1 в E2. Сохранность записи, запуск оболочки и дальнейшую досылку оценивать отдельно. Наличие этого известного пробела не требует повторной разработки cooldown.

Для каждого сценария: действительные условия связи; видео/кадры до и после жеста; локальный event_id и время; server receipt/action/trip ID и количество; связь X/Y; подтверждение отсутствия post_unload_cooldown. Жест через ADB/UI automation на установленном APK допустим при точном описании; прямой вызов enqueue/fetch из JS не заменяет жест.
