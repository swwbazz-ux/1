# Паспорт механики: простои

- Статус: **черновик** (не утверждён владельцем). Дата: 2026-11-11.
- База: HEAD `63dc191e`, не release. Проверка: чтение кода и документов;
  тесты не запускались.
- Смежные: `SHIFTS.md`, `TRIPS.md`, `docs/guide/02` §4, `ПРОГРЕСС_ПРОЕКТА/49`.

## 1. Назначение

Простой — интервал, в который техника не выполняет работу, с причиной из
единого справочника. Паспорт описывает справочник, ролевые списки, открытие и
закрытие интервалов, переключение причин, цвета и состояния техники и что
остаётся нерешённым.

## 2. Участники и права

| Роль | Что может | Ограничение |
|---|---|---|
| Водитель | открыть/закрыть простой самосвала | своя смена |
| Экскаваторщик | открыть/закрыть простой экскаватора | своя смена |
| Механик | открыть/закрыть простой любой техники, кроме самосвала | своя смена; самосвал → 403 |
| Диспетчер | закрыть простой | открытая смена диспетчера |
| Сменщик | изменить причину | онлайн нельзя, офлайн можно (C13) |

Доказательства: `downtimes/views.py:46-51`, `:120-199`;
`users/views.py:6211-6222`; `core/offline_sync.py:3052-3066`;
`trips/dispatcher_downtime_commands.py:20-47`.

## 3. Входы

- `DowntimeReason` (`downtimes/models.py:20`): название, короткая подпись,
  вид техники, `equipment_state`, флаги видимости
  (`show_for_truck_driver`, `show_for_excavator_operator`,
  `show_for_mechanic`), `sort_order`, активность, критичность.
- `DowntimeEvent` (`downtimes/models.py:70-107`): причина, смена, техника,
  начало/конец, автор.
- Ролевой набор — `DowntimeReason.for_workplace(...)`
  (`downtimes/models.py:41`).

## 4. Условия

1. Причина должна быть активна и видима роли; иначе кнопки нет.
2. Без открытой смены простои недоступны уже в серверной разметке
   (`PROJECT_MAP.md:190-193`).
3. Один активный простой на технику/смену — при новой причине прежний
   закрывается.
4. Закрытие смены закрывает все простои смены (требование владельца 26.09, п. 6;
   нормативной записи нет — Q-03).
5. Простой самосвала закрывает водитель, а не механик
   (`downtimes/views.py:46-51`).

## 5. Сценарий и состояния

1. **Старт.** Нажатие причины → создание `DowntimeEvent` с началом «сейчас» →
   событие версии → таймер в UI.
2. **Переключение.** Новая причина закрывает прежний интервал и открывает новый
   в одну временную точку; история не переписывается (`PROJECT_MAP.md:207-210`).
3. **Завершение.** Отдельное действие; повторное/перекрёстное нажатие не
   создаёт второй POST (`PROJECT_MAP.md:199-200`).
4. **Переходящий простой.** Целиком сохраняет принадлежность исходной смене
   (`PROJECT_MAP.md:209-210`).
5. **Закрытие смены.** Все открытые простои закрываются.
6. **Офлайн.** `*.downtime.started` / `.ended` — в очереди; применяются
   временем устройства.

## 6. Ограничения и формулы

- Таймер смены: общий простой текущей смены; на кнопке — накопленное время
  категории; повторные интервалы суммируются (`PROJECT_MAP.md:204-210`).
- Цвет и состояние: `effective_color_group` и
  `effective_equipment_state_code`; явное `equipment_state` важнее fallback
  (`49:135-146`).
- Состояния: `waiting`, `maintenance`, `repair`, `breakdown`, `downtime`
  (`49:50-58`). Неизвестная неаварийная причина → `waiting`/жёлтый
  (`49:146`).
- Автор закрытия простоя в строке не хранится; диспетчерский
  `source=dispatcher_override` пишется только в payload события
  (`state/audits/T-006/EVENTS.md:137-143`).

## 7. Ошибки и офлайн

| Ситуация | Ответ | Где |
|---|---|---|
| Нет смены | 409 (водитель/экскаваторщик) | `users/views.py:6139-6143` |
| Механик закрывает простой самосвала | 403 | `downtimes/views.py:46-51` |
| Сменщик меняет причину онлайн | 409 | `users/views.py:6211-6222` |
| То же офлайн | разрешено | `core/offline_sync.py:3052-3066` |

Офлайн: старт и завершение простоя поддерживаются очередью; при битом
хранилище очередь не отправляется (`docs/guide/06` §5, OF-03).
