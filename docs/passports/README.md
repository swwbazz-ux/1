# Паспорта механик

- Дата: 2026-11-11. Редактор: `copper-backend` (T-010). База: HEAD `63dc191e`
  (не release). Правила — только со ссылкой; статусы — три колонки.
- Назначение: описать существенные механики в одном формате, чтобы новый агент
  понимал «что это, кто участвует, при каких условиях работает, где ломается и
  что уже проверено» — без чтения всего кода и всей переписки.
- Это **не** утверждение бизнес-правил. Паспорт фиксирует требование,
  реализацию и проверку раздельно; утверждает только владелец.

## 1. Формат паспорта

Каждый файл содержит 11 разделов в этом порядке:

1. **Назначение** — что механика делает и на какие вопросы отвечает.
2. **Участники и права** — роли и их границы (со ссылкой на `guide/03`).
3. **Входы** — маршруты, форматы, обязательные поля.
4. **Условия** — что должно быть верно до применения действия.
5. **Сценарий и состояния** — шаги, статусы, переходы.
6. **Ограничения и формулы** — лимиты, TTL, расчёты с `файл:строка`.
7. **Ошибки и офлайн** — коды, терминальность, поведение без сети.
8. **Интерфейс** — что видит работник.
9. **Приёмка** — что проверено чтением, что прогоном (с версией), чего нет.
10. **Ссылки** — код, тесты, документы, аудит-коды.
11. **Открытые вопросы** — с ID и вариантами, без решения за владельца.

Заголовок каждого паспорта содержит статус: `черновик` (не утверждён
владельцем) или `действующий` (есть датированное основание). Все шесть
паспортов ниже — **черновики**: датированных решений по механике в целом нет.

## 2. Три статуса

| Статус | Значения | Чем подтверждается |
|---|---|---|
| Требование | предложено / утверждено / заменено | документ с датой, ADR, решение владельца |
| Реализация | нет / частично / есть | код, `файл:строка` |
| Проверка | нет / чтение на версии / расхождение | прогон, стенд, устройство |

`файл:строка` — реализация, а не право. «Тест существует» ≠ «тест проходит».

## 6. Приёмка паспорта

Паспорт считается готовым, когда:

1. все 11 разделов заполнены по существу, без пустых заголовков;
2. каждое правило имеет `файл:строка` или ссылку на документ с датой;
3. проверка указана честно: «чтение» не выдаётся за прогон;
4. открытые вопросы вынесены в §11 с ID, а не решены текстом;
5. reviewer подтвердил отсутствие дублей с `guide/05`–`07` и `210`/`211`.

Ни один из шести паспортов этот критерий полностью не прошёл: все они —
черновики уровня «чтение на `63dc191e`».
