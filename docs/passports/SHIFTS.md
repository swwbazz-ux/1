# Паспорт механики: смены

- Статус: **черновик** (не утверждён владельцем). Дата: 2026-11-11.
- База: HEAD `63dc191e`, не release. Проверка: чтение кода и документов; тесты
  и БД не запускались.
- Смежные: `TRIPS.md`, `DOWNTIMES.md`, `docs/guide/02`, `docs/guide/03`.

## 1. Назначение

Смена — контекст почти для всех действий: пока смена открыта, работник может
грузить, разгружать, отмечать простой, получать план и показания. Паспорт
описывает, как смена открывается и закрывается, какие ограничения держит БД,
какой план фиксируется и как считается время.

## 2. Участники и права

| Роль | Действие | Условие |
|---|---|---|
| Водитель | открыть/закрыть свою смену | онлайн — расстановка `assigned`; офлайн — без неё |
| Экскаваторщик | открыть/закрыть свою смену | только онлайн, нужна расстановка |
| Горный мастер | расстановка на смену | своя открытая смена, иначе 400 |
| Диспетчер, админ | служебно закрыть чужую смену | причина обязательна |
| Табельщик | перевахта, явка | отдельная сессия |
| Админ | принудительное закрытие | не при открытой смене у себя |

Доказательства: `users/views.py:5582-5609`, `:5841-5908`;
`trips/views.py:4935-5060`; `trips/dispatcher_shift_commands.py:245-441`.

## 3. Входы

- Модель `EmployeeShift` (`shifts/models.py:434-457`): сотрудник, техника,
  `workplace_code`, `opened_at`/`closed_at`, показания, `plan_*`, перевахта.
- Открытие — серверная форма/офлайн-событие `*.shift.opened` (только
  `driver.shift.opened`), закрытие — форма или `*.shift.closed`.
- Открытие фиксирует snapshot плана: `plan_group`, `plan_group_name`,
  `plan_calculation_mode`, `plan_value`, `plan_assigned_at`, `plan_status`
  (`shifts/models.py:430`; `64:105-113`).

## 4. Условия

1. Одна открытая смена у сотрудника — ограничение БД
   (`unique_open_shift_per_employee`, `shifts/models.py:438-443`).
2. Одна открытая смена на технику (`unique_open_shift_per_equipment`, `:444-448`).
3. Один открытый период ОУП (`unique_open_oup_period`, `:449-456`).
4. Одна открытая смена диспетчера/мастера — **только код** и глобальная
   блокировка состояния, в БД ограничения нет (`state/audits/T-006/ROLES-AND-RIGHTS.md:155-164`).
5. Онлайн-открытие на занятой технике — отказ (`shifts/services.py:681-689`);
   офлайн — прежняя смена закрывается служебно временем новой (`:811-829`).

## 5. Сценарий и состояния

**Открытие (водитель, онлайн).** Проверка роли и назначения → проверка
отсутствия своей смены → проверка занятости техники → создание смены → snapshot
плана → событие версии. Без назначения — форма с ошибкой (HTTP 200), смена не
создаётся (`users/views.py:5582-5609`).

**Открытие (водитель, офлайн).** Возможно только если самосвал уже назначен:
страница рисует подготовленный самосвал при действующем назначении
(`users/views.py:4727-4736`), а локальное открытие без него отказывает —
«Самосвал не назначен — начать смену нельзя»
(`driver-local-shift-v1.js:295-296`). Если назначение есть, событие
`driver.shift.opened` уходит в очередь, сервер применяет его временем
устройства, расхождение с расстановкой — только в техжурнал
(`core/offline_sync.py:3194-3280`). Это факт кода; нормативной записи
«телефон — источник истины» нет (Q-03).

**Открытие (экскаваторщик).** Только прямой POST, без сети невозможно:
события `excavator.shift.opened` нет (`core/offline_sync.py:49-70`;
`templates/trips/excavator_work.html:4181-4217`). Заказ владельца 30.09.2026 не
выполнен — C2, Q-04.

**Закрытие.** Своя смена: открытые рейсы становятся переходящими
(`shifts/services.py:254-300`); простои закрываются. Чужая — отказ. Служебное
закрытие диспетчером/админом требует причины
(`trips/dispatcher_shift_commands.py:245-441`). Офлайн-закрытие идёт очередью у
обеих ролей.

**Передача смены.** Онлайн причина простоя сменщику недоступна, офлайн —
доступна (`users/views.py:6211-6222` против `core/offline_sync.py:3052-3066`) —
C13. Событие `shift_handover_closed` создаётся, но никому не доставляется
(`core/realtime.py:7-40`).

## 6. Ограничения и формулы: три сетки времени

1. **Производственная:** `07:00–19:00` / `19:00–07:00`
   (`core/production_time.py:13`, `:45`, `:53`). По ней считаются производственные
   даты и плановый период.
2. **Отсечки автозакрытия:** `08:00`/`20:00`
   (`trips/views.py:6756`, `:6822-6830`). Подпись «Автоматически через 13 часов»
   (`shifts/models.py:405`) формуле не соответствует: фактически это конец
   смены → ближайшая отсечка.
3. **Календарный график 12/1:** `DAY 08:00–20:00`, `NIGHT 20:00–08:00`, перерыв
   1 час (`docs/domain/ЦЕНТРАЛИЗОВАННАЯ_ПЕРЕВАХТОВКА_2026.md:68-71`). Календарные
   времена не перезаписывают operational-время (`:220-223`).

Формулы плана: самосвал — `рейсы / plan_value × 100`, экскаватор —
`м³ / plan_value × 100` (`64:109`); расчёт —
`shifts/services.py:1444`; переснимок открытых смен при сохранении группы —
`:1312` (snapshot при открытии — `:1258-1306`).

Показания принимаются только целыми числами; проверка в браузере, форме и
доменном сервисе (`PROJECT_MAP.md:132-133`). Расхождения при передаче смены —
`ShiftReadingCorrection` (`shifts/models.py:532-565`).

## 8. Интерфейс

Вкладка «Смена» у водителя и экскаваторщика; удержание 1 с для начала и для
закрытия смены; 2 с — только у кнопки «Выйти»
(`static/js/driver-shift-v1.js:696-700`, `:716-717`;
`templates/includes/mobile_shift_screen.html:109`, `:113`). Подпись «две
секунды» осталась в старых документах; код — 1 секунда, это вопрос Q-34
(`state/BACKLOG.md` B-17). Показ плана и
процента — только из snapshot смены; «нет плана» — отдельной подписью, не `0%`
(`64:109`).
