# Паспорт механики: расселение

- Статус: **черновик** (не утверждён владельцем). Дата: 2026-11-11.
- База: HEAD `63dc191e`, не release. Проверка: чтение кода и документов;
  тесты не запускались.
- Смежные: `docs/guide/07` §8,
  `ПРОГРЕСС_ПРОЕКТА/МОДУЛЬ_РАССЕЛЕНИЯ/00-09`,
  `docs/domain/ЦЕНТРАЛИЗОВАННАЯ_ПЕРЕВАХТОВКА_2026.md`.

## 1. Назначение

Расселение — размещение сотрудников по койкам общежитий с учётом заездов,
когорт и смен. Паспорт описывает модель данных, предпросмотр и применение,
право управления (lease), официальную смену и границы: что утверждено
документами и что кодом не реализовано.

## 2. Участники и права

| Роль | Что может | Ограничение |
|---|---|---|
| Делопроизводитель (`settlement_clerk`) | предпросмотр, применение, освобождение койки | действующее право управления (lease) |
| `admin` | то же | тот же доступ |
| Второй делопроизводитель | читает карту | без lease — только просмотр |
| Табельщик, начальник участка | перевахта, явки, продления | отдельные контуры `rotations` |
| Сотрудник (портал) | личные запросы | без доступа к карте |

Доказательства: `settlement/views.py:252-276` (доступ), `:982-1001` (lease,
без бизнес-смены); `rotations/timekeeper_auth.py:8-37`.

## 3. Входы

- `SettlementSource` / `SettlementRevision` — источник и ревизия данных
  (`settlement/models.py:223`, `:573`).
- `AccommodationAnchor` — физическая койка/место (`:762`);
  `AccommodationAnchorBedAssignment` — привязки (`:963`);
  `AccommodationAnchorCalendarSlot` — слот по дате/смене (`:1258`).
- `EmployeeAccommodationBinding` — привязка жильца (`:1474`).
- `SettlementCohort` и `SettlementCohortMember` — когорта заезда (`:1787`,
  `:2018`).
- Маршруты: `/clerk/`, `/clerk/settlement/`; заезд и когорты —
  `settlement_arrival_roster*` (`:280-352`).

## 4. Условия

1. Действует только одно право управления (lease); иначе — просмотр
   (`settlement/views.py:252-276`, `:982-1001`).
2. Заезд идёт цепочкой: список заезда → когорта → предпросмотр → применение
   (`:325`, `:352`, `:1523-1645`).
3. Применение — отдельно ночное и отдельно дневное; одно не меняет другое
   (`:1637`, `:1645`).
4. Утверждённое правило ADR-029-B: одна открытая бизнес-смена; источник права —
   открытый `EmployeeShift`, а не browser lease
   (`ПРОГРЕСС_ПРОЕКТА/МОДУЛЬ_РАССЕЛЕНИЯ/05_ЖУРНАЛ_РЕШЕНИЙ_И_ОТКРЫТЫЕ_ВОПРОСЫ.md:205-207`).
   **Код проверку в `acquire` не выполняет** — сам ADR помечает это как
   невыполненный follow-up (`:209`).
5. Пересечения проживания не ограничены БД: правило уровня приложения
   (`D-01`, `ADR-008`).

## 5. Сценарий и состояния

1. **Карта.** Делопроизводитель открывает корпус, видит занятость и свободные
   койки (`settlement/views.py:482-586`).
2. **Предпросмотр.** Кнопка «Подготовить план» строит вариант без изменения
   карты; можно переместить, исключить, вернуть (`:1560`, `:1583`, `:1598`).
3. **Применение.** Отдельные кнопки «ночная»/«дневная»; создаётся фактическое
   размещение (`:1637`, `:1645`).
4. **Освобождение.** Отдельная команда с проверкой права (`:1710`).
5. **Смена/период.** Слоты по календарю и смене; календарные `08:00–20:00` не
   перезаписывают operational-время (`docs/domain:220-223`).

## 7. Ошибки и офлайн

| Ситуация | Ответ | Где |
|---|---|---|
| Нет lease | просмотр без изменения | `settlement/views.py:252-276` |
| Второй делопроизводитель | read-only | `SYNC-MATRIX.md:120` |
| Применение без предпросмотра | команда недоступна | UI карты |

Расселение не входит в полевой офлайн-контур: очередь `driver`/`excavator`
сюда не пишет. Изменения идут только онлайн-формами.
