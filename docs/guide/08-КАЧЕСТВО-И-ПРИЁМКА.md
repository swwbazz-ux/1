## 1. Три независимых статуса

| Колонка | Значения | Чем подтверждается |
|---|---|---|
| Требование | `предложено` / `утверждено` / `заменено` | датированное решение владельца, ADR, приказ; иначе «предложено» |
| Реализация | `нет` / `частично` / `есть` | `файл:строка` в HEAD |
| Проверка | `нет` / `выполнена на <версии>` / `расхождение` | прогон, стенд или устройство + версия |

Правила чтения:

1. Код не выдаётся за утверждение владельца: `файл:строка` — факт реализации,
   а не разрешение.
2. «Тест существует» ≠ «тест проходит». Имя теста без вывода и версии — это
   `проверка: нет`.
3. `выполнена на <версии>` требует либо 40-символьного SHA из отчёта CI, либо
   явной пометки «версия взята из документов, не подтверждена». HEAD
   `63dc191e` в этом комплекте — из документов.
4. «Чтение кода» закрывает только уровень L0. Оно не закрывает ни L1, ни L2.

Пример строки реестра (`docs/guide/11`):

| Правило | Требование | Реализация | Проверка |
|---|---|---|---|
| офлайн-старт смены экскаваторщика | утверждено (заказ 30.09.2026) | нет | расхождение (C2) |
| офлайн-принятие назначения | утверждено (решение 233, 02.10.2026) | есть | выполнена на `63dc191e` (чтение, прогонов нет) |

## 5. Критерии приёмки задачи

1. **Версия.** Указан точный commit (полный SHA) или версия и источник версии.
2. **Доказательства.** Каждый пункт карточки закрыт доказательством (§8) либо
   помечен «не проверено» с причиной.
3. **Границы.** Изменён только заявленный контур; `git status --short` и
   `git diff --no-ext-diff --no-textconv --` это подтверждают. Для untracked
   файлов `git diff` пуст — доказательством служит `status` плюс содержимое.
4. **Блокирующие проверки.** Если затронуты экраны водителя/экскаваторщика или
   файлы из `AGENTS.md:54-61`, проверки `AGENTS.md:63-73` выполняет CI на
   проверяемом commit (`django.yml:104-119`, `:121-161`) либо владелец. Роль
   приводит имя workflow, полный SHA и список упавших/пропущенных; нет отчёта —
   пишется «не проверено» (§7).
5. **Нет обхода прав.** Недоступная команда — блокер и запись в отчёт, а не
   «проверить на глаз».
6. **Reviewer.** `PASS` или `PASS WITH NOTES` без блокирующих замечаний.
7. **Тип задачи.** Для документационной — §6; для экранов и офлайна — §7.

## 6. Документационная задача: что проверять (только чтение и diff)

Django-прогоны не требуются (`СИСТЕМА_MVP/backend/AGENTS.md:53`). Проверка —
сверка, её может выполнить любая роль.

1. **Существование ссылок.** Каждый путь существует; выдуманный путь — дефект.
2. **Сверка `файл:строка`.** Утверждение «настроено в `…:121-161`» проверяется
   открытием файла на этих строках; номер строки без содержимого — не
   доказательство.
3. **Разделение статусов.** Требование, реализация и проверка не слиты;
   «код так делает» не выдано за «владелец утвердил».
4. **Границы diff.** `git status --short` показывает только ожидаемые `.md` и
   `state/**`; `git diff` без кода, шаблонов, статики, миграций, настроек, CI и
   `.env`. Untracked проверяются отдельно.
5. **Нет ложных прогонов.** Если тесты, сборки, БД, браузер или устройство не
   запускались — это написано. «Тесты зелёные», «CI прошёл» без SHA запрещены.
6. **Публикация.** Commit/push/deploy не выполняются; в отчёте сказано, что
   изменения локальные.

Чего недостаточно: «файл создан», «текст выглядит полным», «все разделы есть».
Разделы без проверяемых ссылок — пустой шаблон, а не документ.

## 8. Что считается доказательством

Считается:

- `файл:строка` с содержимым, подтверждающим утверждение (L0);
- вывод команды с полным SHA и числом тестов (`Ran N tests`, `skipped M`);
- отчёт CI: имя workflow, полный SHA, список упавших и пропущенных;
- HTTP-код и сетевой лог для браузерной проверки (L5);
- лог устройства или logcat для L6;
- строка `RELEASE_OK mode=... commit=... backup=...` для выпуска.

Не считается:

- имя теста без запуска и без вывода;
- «зелёный» прогон, где PostgreSQL-тесты помечены `skip`;
- SQLite-прогон как доказательство блокировок, гонок и частичных индексов;
- debug-сборка APK как доказательство поведения приложения;
- скриншот без сетевого лога и строк БД;
- успех в исходной ветке без прогона на итоговом commit;
- пересказ чужого отчёта без ссылки на файл и версию;
- «CI зелёный» без SHA.
