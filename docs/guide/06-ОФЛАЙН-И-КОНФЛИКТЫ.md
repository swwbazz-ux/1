- Дата: 2026-11-11. Основа: `state/handoffs/T-010-offline-1.md` (D6), редактор
  `copper-backend`. База: HEAD `63dc191e`, **не release**.
- Статусы: **Т** требование (`предложено`/`утверждено`/`заменено`),
  **Р** реализация (`нет`/`частично`/`есть`), **П** проверка
  (`нет`/чтение на версии/расхождение). `файл:строка` — факт кода, не решение
  владельца.
- Связанные: `guide/05` (сущности и точки обмена), `passports/OFFLINE-SYNC.md`
  (паспорт механики), `state/audits/T-006/{EVENTS,SYNC-MATRIX,COLLISIONS}.md`.

## 1. Три контура, которые нельзя смешивать

| Контур | Адрес | Направление | Чем подтверждается | Где код |
|---|---|---|---|---|
| Поле: водитель, экскаваторщик | `POST /offline-events/sync/` | устройство → сервер | квитанция на каждое событие | `core/urls.py:7`; `core/views.py:45-132`; `core/offline_sync.py:4088-4127` |
| Планшет горного мастера | `GET/POST /mining-master/tablet/field-sync/` | планшет → сервер | квитанция `applied`/`conflict`/`retry`/`auth` | `assignments/tablet_urls.py:38`; `assignments/field_sync.py:1063-1115` |
| Realtime | `GET /realtime/state/` | сервер → устройство | версия + дельта событий | `core/urls.py:8`; `core/views.py:136-260` |

Правила разделения (`EVENTS.md` §6): realtime не отправляет действия;
офлайн-очередь не доставляет состояние обратно, только квитанции; push — не
замена обмену; квитанция ≠ событие состояния; `master-field/2` ≠ формат 1
(разные ключи, лимиты и зависимости). Ни один контур не заменяет другой, и в
одну таблицу они не сводятся.

## 2. Полевой пакет: формат 1 и 20 типов событий

Пакет содержит `format_version` (или `protocol_version`) = 1, `role_code`,
`device_id` и массив `events` (`core/views.py:84-95`; `core/offline_sync.py:24`).
Версия не 1 → 400 `unsupported_format_version` (`core/views.py:87-94`). Роли —
только `driver` и `excavator_operator` (`core/offline_sync.py:4089-4090`);
иное — `auth_required`.

Типы событий — ровно 20 (`core/offline_sync.py:49-70`, обработчики `:3406-3427`):

- экскаваторщик (8): `excavator.free_bucket.accepted`, `.cancelled`, `.loaded`,
  `excavator.trip.loaded`, `excavator.trip.loaded.cancelled`,
  `excavator.downtime.started`, `.ended`, `excavator.shift.closed`;
- водитель (12): `driver.trip.unloaded`, `driver.trip.dump_point_changed`,
  `driver.trip.loaded`, `driver.trip.loaded.cancelled`,
  `driver.trip.manual_completed`, `driver.free_bucket.selected`,
  `driver.free_bucket.cancelled`, `driver.assignment.accepted`,
  `driver.downtime.started`, `.ended`, `driver.shift.closed`,
  `driver.shift.opened`.

Событие: `event_id` (≤128), `event_type`, `format_version`, `sequence`,
`depends_on`, `occurred_at` с часовым поясом, `payload`, `context_snapshot`,
`shift_id`/`equipment_id`/`trip_id`, `local_trip_id`, `local_downtime_id`
(`core/offline_sync.py:885-957`). Нет пояса в `occurred_at` → `invalid`
(`:908-911`). **Нет** `excavator.shift.opened`: офлайн-открытие смены
экскаваторщика невозможно (`:50-57`; коллизия C2).

## 3. Квитанция и шесть результатов

Одна строка `OfflineFieldEvent` на событие: `event_id` unique, `status`,
`retryable`, `error_code`, `result_payload`, ссылки на смену/рейс/технику/
простой (`core/models.py:55-129`).

| Результат | Что делает клиент | Второй эффект |
|---|---|---|
| `accepted` | убирает событие из очереди | нет |
| `deduplicated` | убирает, показывает прежнюю квитанцию | нет |
| `retry` | оставляет и повторяет с backoff | нет |
| `conflict` | терминально, в «на сверке» | нет |
| `invalid` | терминально, в «на сверке» | нет |
| `auth_required` | ждёт нового входа | нет |

Повтор с тем же `event_id`, сотрудником, допуском, устройством и fingerprint →
возвращается прежняя квитанция (`:3773-3798`, `:3892-3893`). Тот же `event_id`
с другим содержимым → `conflict event_id_reused` + запись в
`OfflineFieldEventConflict` (`:1023-1038`).

## 4. Три ключа идемпотентности

1. `event_id` unique (`core/models.py:64`).
2. `(actor, role_code, device_id, sequence)` unique (`:117-122`).
3. Advisory-lock `lock_idempotency_key` + fingerprint
   (`core/offline_sync.py:3773-3798`); fingerprint — `sha256` канонизированного
   события без `received_at` (`:958-965`).

**Р:** есть. **П:** только чтение; гонки на PostgreSQL не воспроизводились
(D-05 в `COLLISIONS.md`).

## 5. Зависимости, порядок, конфликты

- `depends_on` ≤ **32**; больше, повтор или самоссылка → `invalid
  invalid_dependencies`, событие не применяется никогда
  (`core/offline_sync.py:26`, `:902-907`).
- Пакет обрабатывается по `(sequence, event_id, index)` (`:4115-4118`), каждое
  событие — в своей транзакции (`:3775`).
- Зависимость не найдена → `retry dependency_pending`; чужая (другой сотрудник,
  допуск, роль, устройство) → `conflict dependency_owner_mismatch`; номер
  зависимости не меньше своего → `conflict dependency_order_invalid`;
  зависимость отклонена → `conflict dependency_rejected` (`:3480-3519`).
- Одно битое событие не блокирует пакет (`:4097-4127`).
- Позднее событие после закрытия смены принимается в историю своей смены с
  предупреждением (`:1127-1140`).

**OF-01 (`409 inactive_role`).** Middleware отдаёт 409 для неактивной роли, и
`/offline-events/sync/` не в списке разрешённых (`users/middleware.py:198-251`).
Клиент распознаёт только 401/403/HTML-логин
(`driver-offline-outbox-v2.js:433-446`), затем бросает `sync_rejected`
(`driver-shift-v1.js:1817`) и помечает пачку как `network`, повторяя с backoff
(`driver-offline-outbox-v2.js:1088-1093`). **Т:** предложено; **Р:** частично;
**П:** расхождение.

**OF-02 (обрезка зависимостей).** Клиент собирает «все незакрытые» зависимости
без ограничения (`driver-local-shift-v1.js:388-403`;
`excavator_work.html:4191-4198`), сервер на >32 отвечает терминально. **Р:**
есть; **П:** расхождение.

**OF-03 (битое хранилище).** Битый JSON бросает `offline_store_corrupt` и
обесценивает очередь (`driver-offline-outbox-v2.js:509-513`;
`excavator-field-outbox-v1.js:118-121`); у экскаваторщика чужой `next_retry_at`
делает `break` (`:483-495`). **Р:** есть; **П:** расхождение.

## 6. `conflict`/`invalid` у поля — терминальный тупик

Сервер не переобрабатывает терминальный конфликт, кроме узкого списка кодов
(`core/offline_sync.py:3836-3893`); у водителя и экскаваторщика нет события
разрешения конфликта (в `SUPPORTED_EVENT_ROLES` его нет, `:49-70`). В отличие
от планшета, где есть `conflict.resolve` (`assignments/field_sync.py:651-673`).
Клиент держит такие записи 24 часа и удаляет без экрана решения
(`driver-offline-outbox-v2.js:649-654`, `:743-748`). Правило владельца 26.09
требует обратного — расхождение, вопрос Q-17 (OF-05).

## 7. Планшет: `master-field/1` и `master-field/2`

- `master-field/1`: 5 типов (`shift.open`, `shift.close`, `draft.save`,
  `live.save`, `draft.apply`), билет `TICKET_AGE` — 7 суток
  (`assignments/field_sync.py:43-48`, `:216`).
- `master-field/2`: `PROTOCOL = "master-field/2"`, подпись ECDSA/SHA-256 P-256,
  сообщение ≤ 256 КиБ, тело ≤ 4× (`assignments/field_signing.py:18-20`;
  `field_sync.py:1078-1079`). Ключ регистрируется один раз: смена ключа → 409
  `device_key_changed` (`field_signing.py:75-102`).
- Порядок — строгий FIFO по `sequence`; `depends_on` ≤ **64**
  (`field_sync.py:578-586`), `conflict.resolve` FIFO обходит (`:597-598`).
- Квитанция: `id`, `actor_key`, `actor_id`, `actor_access_id`, `status`, `code`,
  `message` — **без `version`** (`:169-178`); схему `requestReconcile(version)`
  водителя к планшету применить нельзя (RT-17).
- Клиента `master-field/2` в репозитории **нет**; контракт подтверждён только
  сервером и тестами `assignments/test_field_v2.py` (25 тестов, не запускались).

## 8. Realtime: только чтение состояния

Опрос `GET /realtime/state/` с `after`, `limit` (по умолчанию 50, максимум 200),
`include_events` (`core/views.py:207-225`); скан ≤ 1000, признак
`events_truncated` (`core/realtime.py:284-307`). Неактивная роль → 200 и
`role_active: false`, опрос продолжается (`core/views.py:155-166`);
нет доступа → 401, опрос прекращается (`:137-154`). `after` больше версии
сервера → клиент версию не понижает, экран замирает (RT-07).

## 9. Лимиты и сроки

| Что | Значение | Где |
|---|---|---|
| Событий в полевом пакете | 1…100 | `core/offline_sync.py:25`, `:4092-4093` |
| `depends_on`, поле / планшет | 32 / 64 | `:26`; `assignments/field_sync.py:582` |
| Длина `event_id` / `device_id` | ≤128 / 6…128 | `core/offline_sync.py:31-32` |
| Опережение часов | 5 минут | `:27` |
| Возраст события | 7 суток объявлено, **не применяется** (`MAX_MONOTONIC_AGE_MS`) | `:30` |
| Билет планшета v1 | 7 суток | `assignments/field_sync.py:48`, `:216` |
| Окно допуска v2 | `grant_from`…`grant_until` (документ: 30 дней) | `:229-238`; `ПЛАНШЕТ…:7` |
| Сообщение планшета | 256 КиБ, тело ≤ 4× | `assignments/field_signing.py:20`; `field_sync.py:1078` |
| Ответ realtime | 50 по умолчанию, ≤200 | `core/views.py:209` |
| Терминальные записи клиента | 24 часа, затем удаление | `driver-offline-outbox-v2.js:654`, `:745` |
| Backoff поля | ≤ 8 с | `driver-offline-outbox-v2.js:605`; `excavator-field-outbox-v1.js:8-13` |

**Важно:** «7 суток» — два разных правила. Возрастной предел полевой очереди
объявлен и не используется; билет планшета — реальные 7 суток; окно допуска
`master-field/2` — 30 дней по документу. Сводить их в одно нельзя (OF-07).

## 10. `access_id` в ключе очереди

Водитель: `driver-offline-events-v2:<accessId>` (`driver-offline-outbox-v2.js:507`);
экскаваторщик: `excavator:<accessId>:<deviceId>` (`excavator_work.html:1397`).
После переоформления допуска старая очередь не отправляется и видна только по
старому ключу (OF-04, вопрос Q-18). **Т:** предложено; **Р:** есть; **П:**
расхождение.

## 11. Что не проверено и не реализовано

**Не проверено:** PostgreSQL и гонки (D-05), браузер, IndexedDB, WebView, APK,
реальные 401/409/413, трафик, поведение после переустановки приложения.

**Не реализовано:** офлайн-открытие смены экскаваторщика (C2); серверный список
квитанций (OF-06); экран сверки терминальных конфликтов (OF-05); обрезка
`depends_on` на клиенте (OF-02); распознавание 409 (OF-01); возрастной предел
очереди (OF-07).

`187` (13.09.2026) в части водителя **исторический**: он запрещает то, что код
разрешает с 02.10.2026. Для экскаваторщика он совпадает с кодом, но
противоречит заказу 30.09.2026 (C3).
