## 2. Три сетки времени — не смешивать

1. **Производственная (оперативный контур):** дневной период `07:00–19:00`,
   ночной `19:00–07:00` — так считаются план и факт самосвала без открытой
   смены (`ПРОГРЕСС_ПРОЕКТА/64…md:138-141`; `core/production_time.py:13-53`).
2. **Отсечки автозакрытия:** `08:00`/`20:00` — смена автозакрывается до
   ближайшей отсечки (`trips/views.py:6756`, `:6822-6830`). Подпись
   «Автоматически через 13 часов» (`shifts/models.py:405`) формуле не
   соответствует.
3. **Календарная (домен, приказ ОД-0267):** график 12/1 — `DAY 08:00–20:00`,
   `NIGHT 20:00–08:00`, перерыв 1 час, 11 чистых часов
   (`docs/domain/ЦЕНТРАЛИЗОВАННАЯ_ПЕРЕВАХТОВКА_2026.md:68-71`). Эти времена
   **не перезаписывают** operational-время опубликованного `CrewPlan`
   (`:220-223`).

**Т:** разделение сеток зафиксировано документом. **Р:** все три существуют в
коде. **П:** нет — сверка сетки для диспетчера и мастера (у них нет
`CrewPlanSlot`) не выполнялась; открытый вопрос Q-05
(`state/OPEN-DECISIONS.md`, T-006 C5/C11).

## 4. Простои: как считаются

- Причина — одна строка `DowntimeReason` с флагами видимости по ролям
  (`ПРОГРЕСС_ПРОЕКТА/49…md:5-16`, `:18-32`).
- Повторные интервалы одной причины **суммируются**; переключение причины
  закрывает прежний `DowntimeEvent` и открывает новый в одну точку времени, не
  переписывая историю (`PROJECT_MAP.md:207-210`).
- Верхний таймер экскаваторщика показывает общий простой смены; на кнопке —
  накопленное время именно этой категории (`PROJECT_MAP.md:204-206`).
- **Т:** правило «погрузка закрывает ожидание погрузки, разгрузка — ожидание
  разгрузки, закрытие смены — все» — требование владельца 26.09.2026, но
  нормативной записи в журнале нет (Q-03). **Р:** частично. **П:** нет;
  противоречие R-17 («закрывает ли погрузка Заправку/Ремонт») открыто
  (`state/OPEN-DECISIONS.md`).
