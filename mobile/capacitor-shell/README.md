# Мобильная оболочка Copper Resources

Универсальная Android-оболочка Capacitor 8 для существующих ролевых PWA. Серверный интерфейс не копируется и не переписывается: WebView открывает URL, заданный профилем сборки.

Первый профиль — `profiles/excavator/app.properties`:

- `applicationId` — Android package приложения;
- `appName` — отображаемое имя;
- `serverUrl` — начальный URL Capacitor;
- `heartbeatUrl` — адрес нативной фоновой проверки с cookie WebView;
- `updateManifestUrl`, `updateApkBaseUrl`, `updateCheckIntervalMinutes` — источник и период проверки обновлений;
- `syncTokenEnv` — необязательная переменная окружения с токеном, если для будущего разрешённого endpoint он понадобится;
- `alertSoundResource` и папка `res` — иконка и звук конкретного приложения.
- `splashBackgroundColor`, `splashAccentColor`, `splashIconResource` — оформление общего стартового экрана конкретного профиля.

При холодном запуске Android показывает профильный системный splash без белой
вспышки, затем поверх WebView остаётся общий анимированный экран с иконкой,
названием приложения и кольцевым индикатором в стиле серверного
`.app-sync-overlay__spinner`. Тот же слой повторно показывается при каждом
полном переходе WebView, в том числе после ввода PIN и серверных redirect.
WebView остаётся прикреплённым и продолжает отрисовываться под непрозрачным
нативным слоем, пока не закроется клавиатура,
не стабилизируются Android insets, `visualViewport`, ролевой shell, шрифты и
изображения. После этого Android дополнительно подтверждает подготовленный
кадр через `postVisualStateCallback`; лишь затем WebView становится видимым,
а слой плавно снимается. Условием показа не служит фиксированная задержка.

Нативный foreground-сервис выполняет авторизованный HTTPS polling существующего `/realtime/state/` независимо от скрытого WebView, сохраняет последний ответ и серверную версию, использует текущую cookie сессии и сообщает о релевантном изменении через звуковое уведомление, когда окно свёрнуто. При возврате окна `MainActivity` вызывает штатный `window.AppRealtime.wake(...)`, поэтому серверный PWA-контур делает собственный catch-up. Нативный код не изменяет и не дублирует доменную логику Django.

Нативный менеджер обновлений проверяет профильный JSON-манифест при возврате
приложения на экран и затем каждые 15 минут. Новая версия предлагается без
остановки текущей смены: пользователь может обновиться сразу или нажать
`Позже`. После отсрочки версия справа от заголовка `Смена` остаётся отмечена
как доступное обновление и повторно открывает диалог по нажатию. Перед передачей
APK системному установщику проверяются SHA-256, `applicationId`, `versionCode`
и совпадение сертификата с уже установленным приложением. Тихая установка без
системного подтверждения Android намеренно не используется.

Сервис объявлен как Android `specialUse`: `dataSync` при target SDK 36 ограничен шестью часами фоновой работы в сутки, что короче производственной смены. Канал поставки — прямое распространение APK с корпоративного сайта и, при необходимости, RuStore.

## Сборка

Требования текущей версии: Node.js 22+, Temurin JDK 21, Android SDK Platform 36 и platform-tools. Capacitor 8.5 компилирует Java source level 21; установленный JDK 17 можно оставить для других проектов, но `JAVA_HOME` этой сборки должен указывать на JDK 21.

```powershell
npm install
npm test
npm run android:build:excavator
```

APK появляется в `dist/excavator-debug.apk`.

## Релизная подпись

Постоянный ключ релизной подписи и файл реквизитов хранятся только вне репозитория:

- `C:\Users\swwba\CopperResourcesKeys\copper-release.jks`;
- `C:\Users\swwba\CopperResourcesKeys\keystore-credentials.txt`.

Gradle читает внешний файл автоматически. Для другого защищённого расположения нужно задать переменную `COPPER_RELEASE_KEYSTORE_PROPERTIES` с абсолютным путём к файлу реквизитов. Если файл или keystore отсутствует, release-сборка завершается с явной ошибкой и не создаёт неподписанный APK.

```powershell
npm run android:release:excavator
```

Подписанный APK появляется в `dist/excavator-release.apk`. `versionCode` в профиле приложения необходимо увеличивать перед каждым следующим обновлением.
Рядом формируется `dist/excavator-update.json`. При публикации APK нужно
переименовать в версионное имя из поля `apkUrl` (например,
`excavator-10.apk`) и только после проверки файла атомарно заменить JSON-манифест.
Именно порядок «APK, затем манифест» не позволяет приложению увидеть ещё не
доставленную сборку.

При подключённом по USB и авторизованном для отладки телефоне установка и запуск выполняются командой:

```powershell
npm run android:install:excavator
```

После первого запуска нужно разрешить уведомления и исключение из оптимизации батареи. Постоянное уведомление foreground-сервиса скрыть нельзя. Действие «Тест сигнала» в этом уведомлении создаёт отдельное звуковое heads-up оповещение через канал высокой важности. Фаза Экскаваторщика считается принятой только после проверки на реальном телефоне: вход и рабочий экран, несколько минут в свёрнутом состоянии, автоматический catch-up при возврате и звуковое всплывающее оповещение.

Геолокационные разрешения и код в проект не добавлены.
