# Планшет Горного мастера

Профиль `mining_master_tablet`, пакет `ru.copperresources.miningmaster.tablet`.
Веб-приложение: `https://dispatcher.driverform.ru/dispatcher/control/`.
По прямому уточнению владельца нужен полный набор функций и прав Горного диспетчера. Поэтому терминал с названием «Горный мастер» открывает настоящий диспетчерский модуль. Права выдаются штатным серверным входом с ролью Диспетчера; APK и User-Agent прав не предоставляют.
Подготовлено для Blackview Tab11, Android 11, экран 2000 × 1200 в альбомной ориентации.

## Что входит

- Отдельное APK с иконкой Горного мастера, альбомной ориентацией и полноэкранным режимом.
- Планшетные CSS/JS хранятся внутри APK; применяются только на точном HTTPS-хосте `dispatcher.driverform.ru` и адресах из списка ниже. Основная адаптация пульта ограничена `/dispatcher/control/`; на связанных страницах меняется только вёрстка и прокрутка. Бизнес-операции остаются серверными. Это версия адаптации под проверенный серверный DOM, а не независимый от сайта интерфейс. Остальные страницы хоста доступны с обычной серверной вёрсткой.
- HOME Activity и управляемый режим Android Device Owner / Lock task. Без Device Owner приложение **не** выдаёт обычное закрепление экрана за защищённый киоск.
- Служебное меню работает без сети и без JavaScript-моста. Вызов: удерживать аппаратную кнопку громкости `+` около трёх секунд.
- Служебный PIN 6–12 цифр задаётся ответственным при первом запуске и повторяется. Хранится только PBKDF2-хеш с индивидуальной случайной солью. Пять неудачных вводов блокируют новые попытки на одну минуту. Это отдельный PIN, не PIN учётной записи Горного мастера.
- После задания PIN требуется ещё один успешный вход в обслуживание, прежде чем можно включить защиту.
- Включение и восстановление подтверждаются фактическим `LOCK_TASK_MODE_LOCKED`: после `startLockTask()` приложение ждёт до 3 секунд, проверяя состояние каждые 100 мс по монотонным часам. `NONE` означает ожидание; `PINNED`, ошибка или таймаут запускают возврат в обслуживание. В Android 11 переход выполняется асинхронно в системном Handler, поэтому немедленная проверка после Binder-вызова недостаточна.
- До изменения политик сохраняется признак незавершённого включения. После перезапуска процесса оно проходит ту же ограниченную проверку. При паузе Activity старые callbacks отменяются, при входе в обслуживание очищается и сохранённое намерение; устаревший callback не может снова включить киоск. В logcat `TabletKiosk` записываются только этап, числовое состояние и класс ошибки, без PIN, хеша, cookie или адресов запросов.
- Обслуживание умеет приостановить защиту, открыть Wi-Fi/Android, сменить PIN и снять управление. Режим обслуживания сохраняется при перезапуске. После работ защиту нужно включить снова явно.
- USB и отладка приложением не запрещаются. В production APK WebView DevTools выключен; в debug APK включён.
- Фоновый сервис Водителя/Экскаваторщика не запускается. Встроенный загрузчик APK выключен; локальное обновление — подписанным APK поверх установленного, с сохранением данных.
- Excel/CSV/PDF-экспорт сохраняется во внутренней папке приложения с авторизованной cookie. Запрещены внешние адреса и внешние перенаправления; HTML-страница входа не принимается за отчёт. Лимит одного файла 50 МиБ. Список, удаление и передача доступны в служебном меню после PIN. Передача временно приостанавливает защиту; после неё нужно вернуть рабочий режим. Реальный экспорт требует отдельной проверки с диспетчерской сессией на планшете.
- Кнопки `window.print()` на доверенных страницах диспетчерского HTTPS-хоста открывают нативный запрос служебного PIN. Только после успешного ввода, повторной проверки той же страницы и подтверждённого выхода из Lock task открывается системная печать Android (A4, альбомная ориентация по умолчанию; можно сохранить PDF). Отмена PIN сохраняет защиту. После печати или отмены системного диалога остаётся обслуживание с явной кнопкой возврата в рабочий режим; при пересоздании Activity доступен обычный вход громкостью `+`.
- Печатный WebMessageListener разрешает только строку `requestPrint` из главного фрейма точного HTTPS-origin. В нём нет URL, HTML, имени файла, PIN или команд управления. Повторные сообщения не создают очередь; смена страницы, повторная загрузка того же адреса, ошибка загрузки и lifecycle-пауза отменяют ожидающий запрос. Неподдерживаемый `WEB_MESSAGE_LISTENER` не заменяется `addJavascriptInterface`: кнопка честно сообщает недоступность печати. Область печати шире списка планшетной вёрстки, поэтому обычные `/reports/*` также могут печататься без изменения их интерфейса.
- Во время системного диалога печатный адаптер повторно проверяет тот же документ перед построением страниц и записью результата. Обычная пауза Activity для печати допустима; навигация, перезагрузка, ошибка или уничтожение WebView отменяют поздние callbacks, чтобы не напечатать другую страницу.
- На время печати нативный фон WebView становится белым, чтобы тёмный фон заставки не попадал на поля листа. Исходный цвет сохраняется отдельным числом до изменения `ColorDrawable`; если WebView хранит фон только в своём provider и `getBackground()` не возвращает цвет, используется `SPLASH_BACKGROUND_COLOR`, установленный единственным другим нативным writer в `MainActivity`. Цвет восстанавливается при завершении/отмене адаптера, отказе запуска или уничтожении экрана. Обычная пауза Activity для асинхронной печати белый фон сохраняет.
- Отдельный экран рейтинга `/reports/rating/tv/` распознаётся заставкой только в планшетном профиле, на точном диспетчерском HTTPS-хосте и при наличии настоящего видимого `rating-tv` интерфейса с инициализированным `RatingTvScreen`. Атрибут `data-app-contract-ready` не подделывается. Общие проверки загрузки, шрифтов, изображений, стабильности вёрстки и фактического кадра сохранены; пустой рейтинг и штатное сообщение недоступности данных допустимы. Для Водителя, Экскаваторщика и остальных адресов действует прежняя проверка.

### Адреса связанных экранов

Native gate и встроенный JS разрешают только `/dispatcher/control/` и следующие 14 точных путей связанных экранов с завершающим `/`:

- `/dispatcher/reports/`, `/dispatcher/shift-log/`, `/dispatcher/management/`;
- `/dispatcher/mining-volumes/`, `/dispatcher/transport/`, `/dispatcher/downtimes/`;
- `/dispatcher/shift-reports/trucks/`, `/dispatcher/shift-reports/excavation/`;
- `/dispatcher/shift-reports/hourly/`, `/dispatcher/shift-reports/hourly-grid/`;
- `/reports/volume/`, `/reports/customer-daily/`, `/reports/templates/`, `/reports/downtimes/`.

Параметры запроса и якорь допустимы; вложенные пути, экспорт, вход и другие роли исключены из инъекции. Рейтинг `/reports/rating/tv/` использует отдельное распознавание готовности и не получает эту адаптацию вёрстки. Список native gate и его JS-обёртки берётся из одного `TabletUrlPolicy.TABLET_PATHS`. На всех связанных экранах Android Back возвращается по истории внутри доверенного хоста; запрет ухода с корневого пульта остаётся отдельной проверкой `controlPage`.

## Сборка локально

Вариант 0.1.21 со смещением ручек за системные области отклонён владельцем: он мог перекрывать технику. В 0.1.22 на проверенном Blackview включается отдельная защита краевых жестов, и закрытые ручки находятся прямо у физических краёв (0px). Их невидимая область больше не расширяется в рабочее поле. Открытые панели сохраняют прежние ручки на своей границе. При отсутствии подтверждённой native-защиты остаётся прежний расчёт системных отступов; это запасной режим, а не утверждение об отключении полос на любом Android.

Защита доступна только для API30 / `Tab11_NEU` / `Tab11_T1_251101`, при Device Owner, реальном LOCKED и Global.DEVICE_PROVISIONED=1. Используется проверенный gate прошивки `Secure.user_setup_complete`, а не общий Android Enterprise API: на время рабочего экрана значение0 останавливает вызов transient-полос. Отдельный неэкспортируемый процесс сохраняет обязанность возврата до изменения, восстанавливает1 при потере UI-клиента/истечении6-секундного срока и при новом запуске. Boot/package-replaced receiver выполняет только восстановление. Главный процесс продлевает срок раз в секунду; веб-страница не имеет API управления этим режимом. При потере службы клиент восстанавливает1 и повторяет подключение с задержкой1с, максимум3 попытки до следующего onResume; отдельное соединение ограничено3с ожидания. Поздние callbacks прежних соединений игнорируются.

В рабочем режиме на API28+ действует штатный `DISALLOW_SYSTEM_ERROR_DIALOGS`, чтобы аварийный процесс не ждал системного окна «Закрыть приложение» и восстановление могло продолжиться. При обслуживании ограничение снимается. Developer-настройка `anr_show_background` должна оставаться выключенной; на проверенном планшете она не задана. Логи ошибок не отключаются.

При подготовке доверенного планшета один раз требуется `adb shell pm grant ru.copperresources.miningmaster.tablet android.permission.WRITE_SECURE_SETTINGS`. USB не нужен для дальнейшей работы. Перед обновлением APK следует приостановить защиту либо снять это разрешение через доверенный ADB и восстановить `user_setup_complete=1`; после обновления проверить grant и возврат рабочего режима. Не выдавать разрешение другим приложениям.

Перед PIN-диалогом приложение пытается восстановить обычное состояние Android. Даже при отказе восстановления служебный вход остаётся доступен; выход из LOCKED и запуск настроек разрешаются только после подтверждённого возврата1. PIN не меняется. Одновременная принудительная остановка обоих процессов не гарантирует немедленного восстановления: оставшийся журнал обрабатывается при следующем запуске/загрузке. Сам режим отключает системные Autofill/ContentCapture; некоторые системные службы после загрузки могут ждать первого возврата1. Сетевая синхронизация пульта от этого системного backup не зависит.

Обоснование, ограничения и фактические проверки: `ПРОГРЕСС_ПРОЕКТА/КРАЕВЫЕ_ЖЕСТЫ_ПЛАНШЕТА_2026_11_01.md`. Не переносить этот механизм на другую прошивку без отдельной проверки.

Нужны Node 22+, JDK 21, Android SDK 36. Из `mobile/capacitor-shell`:

```powershell
npm ci --ignore-scripts --no-audit --no-fund
node scripts/build-android.mjs mining_master_tablet release
```

Подпись читается штатным Gradle-контуром из внешнего `CopperResourcesKeys`, секреты не переносить в репозиторий. Результат: `dist/mining_master_tablet-release.apk`. Перед устройством проверить подпись, package, versionCode, `debuggable=false`, наличие обоих `assets/tablet/mining-master-tablet.*`.

## Подготовка устройства

1. Зафиксировать модель/API/размер, аккаунты, текущий HOME, Device Owner, установленный APK, данные и план восстановления. Не удалять аккаунты и не делать сброс автоматически.
2. Установить APK; проверить вход, корректный landscape, интерфейс, отсутствие утраты данных при возврате/перезапуске.
3. Задать служебный PIN, сохранить его у ответственного, закрыть меню и физической кнопкой снова войти с этим PIN. Проверить пункт Wi-Fi. Это проверка независимого от веб-сайта восстановления.
4. Только после согласованной подготовки назначить приложение Device Owner. Для разработки на устройстве без аккаунтов Android допускает:

```text
adb -s SERIAL shell dpm set-device-owner ru.copperresources.miningmaster.tablet/ru.copperresources.mobile.MiningMasterDeviceAdminReceiver
```

Это шаблон, а не выполненная операция. При отказе из-за аккаунтов/подготовленного устройства остановиться и согласовать путь подготовки. Штатное развёртывание dedicated device обычно включает согласованный сброс и provisioning.

5. В служебном меню проверить `Device Owner`, выбрать `Действия → Включить рабочий режим` и подтвердить. Политики применяются только после проверки PIN и явного выбора.
6. Проверить `LOCK_TASK_MODE_LOCKED`, назначенный HOME, Home/Recents/шторку/поворот, холодную перезагрузку, отсутствие сети и восстановление связи. Иконка приложения или закрепление экрана сами по себе не подтверждают киоск.
7. Снова проверить вход физической кнопкой и PIN, приостановку, Wi-Fi, возврат защиты. Затем обновление поверх APK с той же подписью и повторную перезагрузку.

## Восстановление

Служебное меню доступно даже на экране сетевой ошибки: кнопка громкости `+`, затем служебный PIN. `Приостановить защиту` снимает собственные ограничения, allowlist lock task и persistent HOME. `Настроить Wi-Fi` сначала выполняет ту же приостановку.

Если PIN утрачен, не удалять данные приложения и не выполнять сброс без отдельного решения владельца. Сохранить доверенный USB-доступ для диагностики. APK не содержит универсального пароля, открытого receiver для отключения защиты или административного JavaScript API. При необходимости восстановления через обновление требуется подписанный служебный выпуск и отдельная подтверждённая операция. После снятия Device Owner его повторное назначение может потребовать подготовки Android.

## Четыре выдвижные панели 0.1.3 — 31.10.2026

На основном пульте исходные шапка, нижняя строка поиска и действий, левый и правый гаражи скрываются за соответствующими краями экрана. Содержимое, оформление и серверные функции панелей сохранены. Центральное поле занимает освободившееся место. Связанные страницы отчётов сохраняют прежнее поведение.

Потянуть краевую ручку внутрь экрана либо нажать на неё — открыть панель. Обратный свайп, повторное нажатие ручки или нажатие вне панели — скрыть. При переключении предыдущая панель сначала полностью скрывается: одновременно две панели не показываются.

Автоскрытие срабатывает через 10 секунд бездействия. Взаимодействие обновляет интервал; удержание пальца, ввод, экранная клавиатура и открытый диалог приостанавливают отсчёт. Явное закрытие или переключение остаётся доступным при поиске: поле теряет фокус, запрос сохраняется. Enter завершает поиск и показывает найденную технику, в том числе в скрытом гараже. Фоновая замена доски сохраняет открытый поиск, его текст и фокус.

Перестановка использует прежние обработчики. Выбор техники в гараже скрывает панель для выбора цели на основном поле; исходные узлы не клонируются и остаются внутри своей доски. Автоскрытие не выполняет команд с техникой и не меняет авторизацию.

Установку, подпись и фактические проверки выпуска фиксировать отдельно в журнале планшета. Само наличие этого раздела не подтверждает установку на устройство.

## История 0.1.4 — наложение панелей, заменено правилом 0.1.5

Боковые гаражи сохраняют одну вертикальную колонку. Высота — весь экран; размеры каждой плитки совпадают с плиткой самосвала на основном поле. Ширина гаража определяется одной плиткой и необходимыми отступами. Панели располагаются поверх пульта; открытие, закрытие и временная системная строка Android не меняют геометрию рабочего поля.

Пустой гараж остаётся доступной целью. При штатном перетаскивании комплекса к левому или правому краю раскрывается соответствующий гараж: слева — возврат всего комплекса, справа — освобождение его самосвалов. Исходные обработчики, проверки состояния и подтверждения сохраняются. Само раскрытие панели команд не отправляет. После включения «Перестановки» нижняя панель скрывается, чтобы следующее касание могло выбрать технику на поле.

Выпуск исправляет замечания владельца к пробному 0.1.3. Дата и результат фактической установки 0.1.4 фиксируются в журнале; этот раздел сам по себе установку не подтверждает.


## Действующее правило 0.1.5: панели в общей компоновке

При открытии любая из четырёх панелей занимает свою полосу экрана, а пульт перестраивается в оставшемся месте. При закрытии рабочая область расширяется обратно. Панели не перекрывают рабочие карточки; затемняющей или блокирующей поле подложки нет. При переключении старая панель сначала уходит, новая занимает место только после неё.

Открытие и закрытие — краевой ручкой или свайпом. Касание рабочего поля сразу выполняет его штатное действие; отдельного перехватчика для закрытия панели больше нет. Без взаимодействия панель скрывается по таймеру. После изменения доступных размеров выполняется штатный пересчёт рядов самосвалов внутри комплексов, чтобы крайняя плитка не обрезалась. При нехватке места сохраняется существующее раскрытие «+N».

Гаражи остаются вертикальными, по одной колонке на всю высоту. Их плитки совпадают с плитками рабочего поля. Прежние правила одной открытой панели, 10 секунд бездействия, сохранения поиска и пауз при вводе/жесте сохраняются. Раскрытие при переносе должно учитывать новые координаты целей после перестроения; исходные подтверждения и серверные команды не меняются.

Состав и результаты проверок/установки фиксируются в Ш-09 журнала полевого интерфейса. Этот раздел описывает требования к исправлению, а не подтверждает его установку.


## Дополнение 0.1.6: место для нижней панели при клавиатуре

При вводе номера техники поле учитывает занятую клавиатурой высоту и заканчивается перед нижней панелью. Масштаб, canvas, фокус и запрос сохраняются. Поддержаны уменьшение innerHeight и изменение только visualViewport; перекрытая высота учитывается один раз. После закрытия клавиатуры размеры возвращаются. Это доведение того же правила общей компоновки, без изменения функций пульта.
