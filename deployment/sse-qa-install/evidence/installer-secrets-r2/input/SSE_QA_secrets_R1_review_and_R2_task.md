1. Передача stdin.

Безопасная проверка с теми же параметрами настоящего `Popen` и безобидным дочерним Python-процессом дала:

```text
EXACT_RECEIVER_POPEN_STYLE CHILD_STDIN_BYTES=0 EXIT 0
WITH_STDIN_PIPE CHILD_STDIN_BYTES=24 EXIT 0
```

Отправлялась синтетическая строка длиной 24 байта. Наличие `--pipe` у будущей команды systemd-run не создаёт канал между Python receiver и его дочерним процессом. Требование `stdin=PIPE` для такой передачи описано и в [документации Python](https://docs.python.org/3/library/subprocess.html#subprocess.Popen.communicate).

Исправить создание процесса и проверить фактическую передачу байтов. Тест должен обнаруживать отсутствие PIPE; одного mock, подтверждающего вызов `communicate(input=...)`, недостаточно. Сохранить ограничение размера, обработку timeout/cancel и отсутствие секретов в argv/выводе.

2. Жизненный цикл временного nginx credential.

На временном layout воспроизведена последовательность реальных функций с подменой decrypt и внешних системных операций:

```text
materialize_nginx_auth → verify_installation: PASS
remove_nginx_auth → файл и каталог отсутствуют
verify_installation: owned file changed or missing: …/run/sse-qa-nginx/htpasswd
```

Запись создаётся в `ownership["files"]` на строках 586–588, но удаление на строках 599–608 её не убирает. При следующем enable проверка идёт раньше восстановления htpasswd. Очистка `/run` после перезагрузки создаёт ту же проблему обязательной записи.

Учесть временный credential отдельно от обязательных постоянных файлов. После подтверждённого удаления собственного файла согласованно обновлять журнал; предусмотреть восстановление после очистки `/run`. Проверки чужого/изменённого файла и постоянного ciphertext сохранить. Добавить сценарии enable → disable → enable, повторного disable и утраты временного `/run` при сохранной постоянной установке. Простое исключение всех отсутствующих файлов из проверки не подходит.

3. Права транспортного архива.

Реальный builder запущен с синтетическим JSON и umask 022:

```text
REAL_BUILDER_EXIT 0 ARCHIVE_MODE 0o644 CONTAINS_PLAINTEXT_JSON True
```

JSON действительно вложен в `payload/deploy/sse-qa/secrets.json` внутри gzip/tar. Сжатие его не шифрует. В workflow `umask 077` добавлен в `Validate manual confirmation and revision`, а создание архива выполняется в отдельном `Build deterministic release package`, где этой настройки нет. Это локально доказанный недостаток прав файла; фактическая утечка на GitHub или сервере не утверждается.

Обеспечить закрытые права до первого байта самого транспортного архива, независимо от прежних shell-шагов. Предпочтительно закрепить это в builder при создании output. Проверить новый и уже существующий output, symlink, ошибку записи и удаление временного материала после передачи/ошибки. Документация должна честно различать зашифрованное постоянное хранение и краткоживущий транспортный архив с открытым JSON. Существующие механизмы доставки приложения не переписывать вне необходимой правки.

4. Публикация без перезаписи.

В проверке с временным каталогом чужой файл был создан между последней проверкой `exists()` и реальным `os.replace()`:

```text
до публикации: FOREIGN_FILE_CREATED_DURING_PUBLISH
после успешного возврата: NEW_ENCRYPTED_BYTES
```

Для `replace_existing=False` нужна атомарная операция, отказывающая при уже существующем destination. При конфликте чужой файл должен сохраниться, собственный temporary — удалиться. Разрешённую замену принадлежащего установке файла оставить отдельным режимом с необходимыми проверками. Добавить тест именно такого порядка событий. Это дефект гарантии сохранности файлов; атака непривилегированного пользователя не доказана, родительские каталоги защищены.

5. Linux fixture.

`test_nginx_verifier_is_materialized_only_in_runtime_and_removed` падает с `FileNotFoundError` на создании `<temporary>/run/sse-qa-nginx`: `<temporary>/run` отсутствует. На Windows тест пропускался. Исправить подготовку fixture, не маскировать ошибку новым skip и не менять рабочую реализацию только ради отсутствующего тестового родителя. После исправления расширить этот тест проверками из пункта 2. Сама эта ошибка fixture не доказывает отказ создания каталога на обычном Linux-сервере, где `/run` существует.

Готовое поручение Codex:

Выполни одну локальную доработку R2 по пяти пунктам этого ревью. Сохрани выбранную схему systemd credentials и уже принятые ограничения QA. Сначала воспроизведи проблемы на синтетических данных, затем исправь их и проверь результат адресными поведенческими тестами. Передачу stdin и права архива проверь настоящими локальными дочерними процессами/файлами, без systemd и рабочего сервера. Повторное включение и очистку проверяй с временным layout и подменой внешних операций.

Выполни затронутые проверки. В отчёте раздельно укажи PASS, FAIL и платформенные SKIP; новый CodeQL и полный Linux lifecycle не объявляй выполненными без фактического запуска. Оба исходных findings пока не считать окончательно закрытыми.

Верни один проверяемый R2 ZIP с точным diff относительно этого R1, изменёнными исходниками, тестами, фактическими логами и контрольными суммами. Исторические логи заново размножать не нужно. Публикация, dispatch, обновление receiver, новый серверный preflight, установка QA и нагрузка в эту задачу не входят. Уже принятый preflight и установленный receiver остаются закрытым этапом.
